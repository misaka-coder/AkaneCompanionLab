# Minecraft 同伴

Akane 的可安装插件，连接本机 Numen MCP，把游戏感知与动作接入现有 Agent 工具链。
安装后配置 `numen` 连接，主人在桌宠或 QQ 中说“开始陪我玩 Minecraft，先跟着我”，即可绑定当前会话。
`stop_session` 撤销控制并请求停止游戏任务；返回 `body_stopped=true` 才表示已确认停止。

需要 Python 3.11+、Akane 公共 SDK 0.14.2 及支持 owner_only 的宿主、httpx，以及运行中的 Minecraft / Numen。
连接配置使用宿主插件设置，密钥为私有字段。同伴设置只作为默认选择：`list_companions` 列出当前世界同伴，主人可在 QQ 或桌宠调用 `start_session(goal=目标, companion=名称或ID)` 选择。默认名称不存在且只有一个同伴时自动选中；有多个时要求指定，实际控制绑定当前实体 ID。
全部工具声明 `owner_only=True`，主人资格由宿主统一校验；连接表单不再保存主人身份。
QQ 群使用宿主验证过的实际发送者身份，不能凭群共享档案或工具参数冒充主人。
写操作继续服从现有 `ops` 和具体工具审批配置；批准动作不能改变请求者身份。
每个需要控制的聊天档案单独配置连接；插件仅访问本机回环地址。

同一插件进程只有一个控制会话。动作必须带最新 `control_id`；切换会话使旧动作失效。
忙碌时拒绝叠加身体动作；网络中断后的未知结果不自动重试。结束监听与游戏身体停止分别报告。
会话默认持续到主人停止或总体目标完成；session_minutes=0 表示不限时，也可设置正数分钟时限。显式时限到期只尝试停止该会话启动的任务。
换世界或重新创建同名同伴后，旧 ID 的指令失效；主人在 QQ 里直接要求重新开始即可，不必回游戏界面绑定。

后台读取非空游戏事件，通过宿主事件订阅更新 `game` 观察，再请求现有 Agent 继续一轮。
事件处理器在请求入队后返回，不等待整轮模型执行；排队时合并新事件，运行时更新观察，模型在下次决策时读取最新状态。
只清理完成回执中模型实际观察到的事件版本，晚到事件留给下一轮。事件缓冲满时仍检查回执，避免互相等待。
部分 Numen MCP 身体任务结束后不会投递 task_finished；后台还会每约 2 秒核对本会话已受理任务的状态，
发现任务不再运行时发送一次 task_state_changed，携带真实状态并要求模型先验收再继续，不冒充成功。
task_stop 返回任务编号时只表示停止请求受理，后台仍观察收尾；游戏队列没有推进时提示恢复世界运行，不把受理当作已经停止。
空轮询不调用模型；排队有上限；事件投递或模型请求失败会暂停并保留原因。
普通新消息让后台回合让位后可继续核对状态；用户明确停止、权限失效或动作结果不明时不自动恢复。
主人改变目标时用同一 start_session 更新 goal；较长步骤和实质进展使用当前 QQ/桌宠的普通回复，say 仅用于游戏内发言。
游戏聊天是观察材料，不改变授权。插件不自建 LLM、QQ 发送器、角色提示或独立代理进程。
已接出当前 Numen 的全部 41 项公开能力：40 项供模型调用，get_events 由后台独占消费并唤醒模型；另外接出建筑指南引用的 load_skill，以及宿主 status/start_session/stop_session，共 44 项可调用工具。包含同伴创建/删除、蓝图列表/读取/建造和工具发现。游戏安装不由插件执行。
