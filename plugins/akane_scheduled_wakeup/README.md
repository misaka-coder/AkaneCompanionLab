# 定时唤醒 (akane.scheduled-wakeup)

在选定的时刻把当前对话唤醒一次。一次性，不循环。

## 用法

- 直接说：「十分钟后叫我」「三十分钟后提醒我喝水」。
- `/timer 10 记得喝水`（设定）、`/timer status`、`/timer off`。

说的那一次会在对话里正常出现一次唤醒，不会另发消息、不会直连渠道。

## 为什么是这个形状

后台服务本身**没有会话身份**，它无法直接为某个对话请求一次模型轮次。所以这里不做那种尝试：

1. **登记时**（发生在一次真实对话的 tool 调用里）把本插件的对话级事件订阅绑定下来，
   拿到宿主签发的 `binding`，记入台账；
2. **到点**由后台服务发布一条 `akane.scheduled-wakeup.due` 事件；
3. 事件投递回**已绑定的会话**，处理器在**那个会话自己的签名身份**下请求一次正常对话轮次。

会话身份始终由宿主掌握，插件不伪造、不传递、也不解析任何会话凭据；目标由宿主签发的 binding 决定。

因为一条发布会被路由到每个已绑定会话，处理器会认领**只属于自己 binding** 的那条唤醒；不是自己的就静静放过，不叫醒任何人。

## 台账与诚实汇报

台账存在插件自己的存储目录（`timers.json`），记录 `binding`、到点时间、备注、尝试次数与最后一次真实结果。

- `fired_at` 只有在**真实证据**支持时才写入（事件已投递到该会话、且那里的轮次请求被接受）；
- 没有绑定、绑定失效、投递失败时**不写** `fired_at`，带上真实 reason 在退避后重试；
- 超过 1 小时才被发现的过期定时不补唤醒，直接作废；
- `/timer status` 会把「还没登记到唤醒通道」这类真实状态直接说出来，不粉饰成成功。

## 权限

`event.emit` / `event.subscribe` / `storage.write` / `agent.turn.request` / `job.run` / `qq.command.register`。
不读会话内容、不申请网络、不改宿主代码。

## 限制

- 只响一次；不是循环闹钟。
- QQ 命令只处理 `status` / `off` / `clear`；设定交给正常对话轮次，因为只有那里能完成会话绑定。
- 绑定只在内存中，宿主重启后旧的绑定失效；在那个会话里再说一次定时就会重新绑好。
