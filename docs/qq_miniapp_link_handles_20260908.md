# QQ 小程序：B 站原生转发与不可变发送句柄

状态：NapCat 的 B 站生成方案经真实客户端验收失败，已从运行时能力中撤下；真实原生卡片转发已通过私聊 → 群聊 → 客户端播放验收。候选发布保持中止，线上仍运行原版本。

## 用户可见变化

用户先从 B 站客户端把原生小程序卡片分享给 Bot，再由 Bot 使用现有
`forward_group_single_msg` / `forward_friend_single_msg` 按权限原样转发真实消息 ID。
转发不拆 Ark、不重新签名、不替换预览图、短链、scene 或打开来源，因此保留原生外观与播放能力。

只给 BV 号、普通视频页或 b23.tv 链接时，`get_mini_app_ark` 的 `source` / `type="bili"`
返回 `bilibili_native_card_forward_required`，不会再生成一张“看起来成功但无法稳定播放”的卡片。

其他支持模板正常生成只返回 `stage=generated`、`card_ref`、标题、网页地址和有效期，不再把整段签名 JSON 交给模型复制。发送仍使用既有 `send_group_msg` / `send_private_msg`，传 `card_ref` 即可；不能同时传 `message`。普通文本和已有消息段发送不受影响。

微博与手工自定义生成仍保留，正常生成统一进入同一套句柄发送链；原始 Ark 模式仅供按需读取，不宣称可发送。已存在的卡片仍使用既有原消息转发能力，没有再造转发或签名实现。

## 安全及失败语义

- B 站生成路径不再抓取元数据或调用 NapCat 生成接口；缺少原生消息时结构化失败，不编造材料或自动改成普通链接。
- 卡片缓存归属于单个 Bot，并绑定操作者、会话和角色。容量 128，15 分钟或进程重启失效；不落库、不迁移历史。
- 一个句柄只尝试发送一次，含超时和结果不确定的情况。并发重复调用不会再发送；完成后的重复调用返回前次实际回执并标记 `duplicate_suppressed`。未知或已过期的句柄不会重放。
- 发送复用原有权限、消息回执、插件 Hook 和交付记录调用链。生成成功不表示已发送；发送回执也不等于客户端外观/点击通过验收。
