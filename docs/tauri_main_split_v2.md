# Tauri 主入口拆分收尾

## 范围

本轮基线为 `desktop_pet_next/src-tauri/src/main.rs` 的 6161 行，其中约 980 行为内嵌测试。完成后入口为 128 行，负责启动分支、窗口关闭回调和 80 个命令注册。运行时配置、状态、后端桥接、文件和音频、系统能力、窗口及桌面连接分别由所属模块处理；35 项原入口测试及媒体测试夹具迁至对应目录。

Tauri 命令名称、参数、异步包装、序列化字段和既有资源权限保持兼容。耗时操作与平台相关实现继续通过原来的边界执行。测试使用隔离目录和本地协议夹具，真实角色目录、系统媒体或用户窗口不作为自动测试目标。

## 已完成切片

| 目录 | 职责 |
| --- | --- |
| `runtime/` | 进程绑定、数据根/缓存目录、启动状态和时间 |
| `pet_state/` | 桌宠与角色运行时模型、归一化、持久化及角色激活 |
| `backend/` | 实例验证、管理请求权限与超时、项目桥接和插件文件选择 |
| `local_files/` | 本机打开/显示、公开网址检查、文件命名和桌面导出 |
| `workspace_files/` | 绑定检查、文件选择与上传、带实例/大小/hash 校验的下载和交付 |
| `audio_assets/` | 音频缓存准备、歌词读取、结果模型与限制 |
| `native_system/` | 桌面上下文、进程枚举/分页/终止和系统音量 |
| `native_system/media/` | 媒体命令、结果确认、时间线和 Windows/macOS 实现 |
| `pet_windows/` | 几何/位置、窗口标志、辅助窗口、激活与退出、Win32 命中回调 |
| `desktop_connection/` | 工具协议、连接握手、心跳/消息调度、调用校验、插件事件和执行记录 |
| `startup.rs` | 角色/音频资源授权、原生命中初始化、激活监听和界面服务启动 |
| `character_packs/constants.rs` | 角色模板、归档/图片限制和角色包私有目录常量 |

结构检查通过 `tests/tauri_source.py` 读取入口实际声明的生产模块；原有角色包检查的导入名仍兼容。负向断言定位到实际负责的函数，避免其他模块的合法行为造成误报。

## 基线与验证

- Rust 基线：149 项，128 项通过、21 项按原设置忽略，串行执行。
- Python 基线：11 个相关测试模块共 141 项，138 项通过、3 项失败，无错误。两项只读取旧主入口的检查分别遗漏角色导入缓存及其他模块中的工具常量，已迁移到实际模块读取；另一项是既有活动渲染断言。
- 第一片：Rust 128 项通过、21 项忽略；43 项前端/实例隔离/设备协议检查通过。生产 `cargo check` 和任务范围差异检查通过；80 个命令签名及注册顺序、25 个原入口模型保持一致。
- 第二片：Rust 137 项通过、21 项忽略，新增 9 项行为回归。并发音频准备和导出使用独占暂存文件；导出发布先独占保留目标名，遇到冲突重新选名，失败只清理本次文件。角色包导出复用该发布路径，返回实际文件名。
- 第二片同时复现并修复了已有导出文件被替换，以及短写 IPv4/映射 IPv6 等本机网址绕过的问题。公开网址使用实际 URL 解析器确认主机；普通公开网址的输入保持兼容。打开文件和网址复用一个平台启动函数。
- 文件和 HTTP 响应在读取过程中检查实际大小，防止文件在元数据检查后增长或响应超过头部声明。上传总量按实际读取字节累计；歌词仍按原来可选资源的规则处理读取失败。
- 文件桥接的 Python 检查 51 项通过、1 项因 Windows symlink 夹具条件按原设置跳过；工作区导入 Node smoke、生产 `cargo check`、接口核对及任务差异检查通过。
- 第三片：Rust 137 项通过、21 项忽略；75 项前端/设备/进程/音量协议检查通过。媒体确认、未知执行结果、平台不可用状态及分页语义保持原实现；音量读写复用一个默认端点获取函数。Windows 编译和命令/模型核对通过，其他平台保留原有 cfg 分支，未在当前机器运行。
- 第四片：Rust 139 项通过、21 项忽略；38 项前端/实例隔离检查和窗口运动 Node smoke 通过。辅助窗口复用显示、还原、聚焦的已有窗口处理；原生命中回调、关闭隐藏行为、激活监听和托管退出命令保持原调用链。
- 两项隔离几何测试复现并修复了面板忽略副屏/负坐标原点和过大面板越界的问题。位置按当前（或主）屏幕工作区夹取，普通屏幕仍优先贴在桌宠右侧；当前机器没有操作真实用户窗口来验收该位置修复。
- 第五片：Rust 140 项通过、21 项忽略；42 项桌面连接/设备/个人浏览器/插件交付检查通过。握手和会话循环独立，工具注册与调用校验复用同一份协议定义，保留十种工具的顺序和 hash、实例/租约/权限元数据校验及展示连接的空 offers 行为。
- 并发回归复现同一条浏览器调用触发 8 次打开回调的问题；浏览器执行期间保留专用互斥锁，结果入账后重复请求复用记录。该测试使用受控回调，不打开真实浏览器；共享执行记录在系统打开期间仍可供其他工具使用。
- 第六片：内嵌测试按职责迁移；无界面执行进程由 `desktop_connection/device_runtime.rs` 启动，界面初始化由 `startup.rs` 装配。业务模块直接导入所属模块，入口不再承担公共函数/常量的临时转导出。只对本轮新增模块和入口做统一格式整理。

## 最终验证

- 六个切片已分别本地提交。工作区中的其他后端、QQ、技能及迁移改动保留在原处，没有混入提交。
- Rust：161 项中 140 项通过、21 项按原设置忽略；本轮新增 12 项行为回归。串行执行避免已有设备偏好测试的毫秒级目录夹具冲突。生产 `cargo check` 通过，无编译警告。
- 命令核对：80 个命令签名及属性、80 个注册及顺序、25 个原入口模型的字段/属性保持一致。结构读取覆盖当前入口实际可达的 105 个生产源文件，排除测试和孤立文件。
- Python：13 个相关模块共 162 项，160 项通过、1 项失败、1 项按原设置跳过。失败仍为基线已有的 `PetReachGestureT5ContractTests.test_final_activity_does_not_repeat_native_media_tool_execution`，断言依赖已经移除的活动渲染结构；该前端测试维护不属于本轮原生入口拆分。跳过项为当前 Windows 条件下的 symlink 夹具。连接/设备/个人浏览器/插件交付的另一个相关测试组 42 项通过，与汇总组有重叠，不累加计数。
- 前端：`npm run build`、工作区导入/音频边界 smoke、桌宠控制器组合 smoke、窗口运动 smoke、工坊模块 smoke 及 2 项工坊状态测试通过。
- Edge 无头浏览器工坊检查通过，页面错误为 0；覆盖导入导出、立绘、慢请求/切换/写入竞争、空态、失败及重新进入的状态。浏览器测试在 Tauri 边界使用受控 I/O，未改动真实角色包。
- 任务范围内 `git diff --check` 通过。真实桌面窗口、多屏/DPI 位置、媒体操作、系统音量、进程终止及真实连接断线恢复没有通过人工操作验收；Windows Rust 编译通过，macOS/Linux 保留原有平台分支，但未在对应平台构建。

## 拆分后的验证收尾

- 设备偏好测试复用 `runtime/test_support.rs` 的独立 Sandbox，替换毫秒时间戳目录和手动清理。默认并行 `cargo test` 现为 140 项通过、21 项按原设置忽略，无须串行规避夹具冲突。
- 前端旧媒体断言改为检查实际的 `chat → bubble` 展示边界和插件工具执行入口；组合运行时 smoke 同时验证普通最终回复、历史恢复和重复展示不会执行媒体控制，以及等待原生结果时重复提交同一操作只调用一次。
- 移除 bubble/voice 两条未使用的 activity 依赖和装配参数。29 个桌宠模块的边界、状态归属、语法及未使用标识检查通过。
- `scripts/verify_akane.ps1` 的 Full/Acceptance 增加 8 个有界阶段：桌宠模块边界、组合运行时、工作区导入、窗口运动、工坊模块、工坊状态、小屋契约/类型和小屋测试。Windows CI 继续调用这一入口；Quick 范围不变。新增 Full 只读计划回归验证阶段顺序、可观察状态和超时。
- 前端契约及验证入口共 49 项 Python 检查通过；上述新增 Node 检查通过，工坊状态 2 项、小屋状态/组件 13 项通过。前端构建及 Edge 浏览器桌宠检查通过，覆盖输入、流式回复、失败、慢请求后的会话切换和重新进入，页面错误为 0。
- 后续单独统一了 33 个既有 Rust 文件的格式，展开紧凑语句并整理声明顺序。全 crate 的 `cargo fmt --check`、生产 `cargo check` 和默认并行测试通过；格式整理后的 5 个相关 Python 模块共 72 项通过（与上一组前端检查有重叠）。80 个命令签名、80 个注册顺序及 25 个原入口模型核对通过，`main.rs` 仍为 128 行。
- 本轮避开正在修改的后端业务文件；仅确认 Full 的只读执行计划和本轮相关检查，没有运行完整 Python 回归、公开导出或整条 Full/Acceptance，也没有进行真实桌面媒体及外部服务验收。

## 定位代码

遇到界面命令问题，先在 `main.rs` 的注册列表找到命令所属模块；初始化和资源读取范围看 `startup.rs`，无界面进程状态看 `desktop_connection/device_runtime.rs`。HTTP 实例验证和管理策略在 `backend/`，工作区上传与下载分别在 `workspace_files/imports.rs`、`downloads.rs`；导出发布和文件名冲突处理在 `local_files/exports.rs`。

桌面连接问题从 `desktop_connection/handshake.rs`、`session.rs` 和 `validation.rs` 进入；工具标识、版本及 hash 在 `contracts.rs`。系统媒体执行与结果确认分别在 `native_system/media/` 的平台实现和 `outcomes.rs`，面板多屏位置在 `pet_windows/placement.rs`。测试跟随所属目录；有副作用的窗口/音频/系统能力仍通过原来的命令和平台边界调用。
