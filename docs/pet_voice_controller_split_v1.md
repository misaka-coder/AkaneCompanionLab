# 桌宠语音控制器拆分记录

## 范围与基线

原 `desktop_pet_next/src/pet/voice.js` 为 1,841 行，位于主窗口控制器与实时语音客户端之间。保留 `createVoiceController` 和原有公开接口，分片拆出录音/普通识别、实时通话编排及界面反馈。输入状态和请求编号由明确的 owner 保存，跨模块通过具名端口调用，保留现有后端认证与会话归属。

本轮开始时后端提示/回复组装、QQ 等文件有其他在途改动，未纳入本轮提交；未跟踪的 `tools/` 同样不属于本轮。

基线：主窗口模块边界和真实控制器 smoke、原 8 组语音 smoke 均通过。原 56 个函数的参数、默认值和异步标记作为迁移对照。

## 第一片：录音与普通识别

- `src/pet/voice/recording.js`（352 行）拥有输入状态、请求编号、待完成的麦克风申请、录音器、音频块及 ASR 请求；普通录音和持续通话通过同一 owner 申请、核验和结束麦克风请求。
- `voice.js` 暂为 1,555 行，继续装配原有接口，待后续迁移实时编排与展示。
- 录音停止成功、停止失败和短录音的异步结果核验原请求编号与录音器身份，避免取消后迟到的旧结果清理新麦克风或提交旧输入。`dataavailable` 同样核验所属输入，防止旧音频块污染新录音。
- 格式检测使用注入的平台 `MediaRecorder`；生命周期结束后忽略迟到的采集/识别结果。
- 主窗口边界检查及旧函数消费者使用递归模块发现，继续校验子目录模块的接口、状态归属与依赖方向。

新增 9 项生产控制器行为测试；其中旧录音停止/错误/短录音结果、迟到音频块及平台格式检测共 5 项在原实现失败，迁移和修复后全部通过。麦克风重复申请/取消、ASR 迟到结果、权限失败和空录音也通过。

主窗口 30 个模块边界检查、真实控制器 smoke、语音打断/会话/采集 smoke、前端 build 与 `git diff --check` 通过。AST 对照保留原 56 个函数签名；函数体变化仅涉及上述输入守卫、平台格式检测和持续通话接入请求 owner。

## 第二片：实时语音编排

- `voice/call.js`（359 行）拥有当前通话、传输、重连和共享资源关闭；`call-input.js`（268 行）负责开轮、闲置收音、备用录音和端点提交；`call-response.js`（395 行）消费响应事件，负责超时、失败恢复和终态。
- `voice/single-turn.js`（347 行）拥有单轮实时输入及其响应生命周期。原入口降至 253 行；输入请求状态仍由 `recording.js` 统一管理（358 行）。
- 修复单轮对象未初始化分段文本 Map 的问题，第一段音频元数据现在可以正常展示文字。
- 通话失败恢复在异步录音结束后再次核验当前轮；结束通话后，回退识别也核验输入编号，避免已取消的旧轮提交旧音频或终止继任通话。
- 新一轮输入等待旧通话完成资源释放，等待期间仍显示可取消的麦克风打开状态。通话收尾核验请求编号，旧结束通知和迟到的服务错误不能覆盖新输入。
- 通话关闭逐项尝试备用录音、传输、轮次和共享采集的清理；保存首个清理失败原因并通过现有错误反馈展示，传输关闭异常仍会释放麦克风。
- 删除重复的看门狗适配包装，直接使用已有 helper 和生命周期计时器；备用录音停止复用已有 Blob helper，保留共享停止 Promise、未启动/已停止分支。通话错误收尾收敛到同一入口。
- SSR 控制器测试关闭不使用的 HMR，避免并行测试争抢默认 WebSocket 端口。

本片新增 7 项行为回归，均先复现再修复；累计 16 项控制器测试通过。34 个主窗口模块边界、真实控制器 smoke、原 8 组语音 smoke、前端 build 与任务文件 `git diff --check` 通过。底层实时客户端的 24 项回归也通过。

AST 对照保留原有 55 个非冗余函数的签名；原第 56 个私有看门狗包装已由已有 helper 直接替代。函数体变化限于上述初始化、异步所属检查、资源清理和重复代码收敛。

## 第三片：展示与兼容入口

- `voice/presentation.js` 负责麦克风按钮、回复文本分段、气泡和情绪反馈，入口只保留组装、设置桥接和输入模式选择。
- 重复设置相同的输入开关保持当前申请、录音和识别状态，避免重复开启输入把忙碌状态重置为闲置。
- 排队回复先缓存文字，开始播放后显示；相同音频头不会重复拼接文本。仍在播放的另一轮拥有气泡展示，旧完成事件不覆盖新回复。
- 通话保存最后实际展示的轮次编号，释放已结束的展示对象引用；即使新回复已经结束，迟到的旧最终文本也不能把气泡倒退到旧回复。
- 原路径的 26 个公开成员及四个只读实时 getter 保持兼容。构造控制器时不申请设备或发出后端请求。
- Python 旧源码契约递归读取桌宠子目录，并沿实时客户端的静态导入/导出读取实际实现。补查发现旧检查仍按九行兼容入口查找 PCM 实现，已修正读取方式，保留原断言。

本片新增 7 项控制器测试；重复开启三种输入状态及旧回复完成的两种时序共 5 项先失败后修复，另验证排队/重复音频头与公开接口。累计 23 项控制器行为/兼容检查通过。
