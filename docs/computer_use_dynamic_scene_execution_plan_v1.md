# PCUse 动态页面与操作恢复执行单

日期：2026-10-08；实施：2026-10-09。状态：实现完成，当前显示环境验收通过；200% DPI 与原网页模型任务复测待补。详见 [验收记录](computer_use_dynamic_scene_acceptance_20261009.md)。

本轮沿用现有窗口会话、视觉批次、权限和图片回传链路，让系统负责正确的窗口与坐标，让模型通过实际截图判断操作效果。补充 [视觉连续操作方案](computer_use_visual_batches_v1.md) 和 [前期改进执行单](computer_use_refinement_execution_plan_v2.md)，不另建 agent 主循环。

## 问题依据

1027 群本次 Gemini 网页操作约耗时 10 分钟，共 25 次工具调用，调用与结果均配对；其中 7 次在输入前被 `visual_scene_changed` 拦截。本地工具累计耗时约 8.6 秒，另有两次上游函数调用格式错误。最后成功交付截图，但没有消息发送成功的证据。

当前执行器在观察超过 15 秒后检查整窗像素：任一局部块变化超过阈值，即可阻止整段操作。加载动画、光标等可能触发该机制；由于当时未保存对照帧，不能断言那 7 次都是加载动画造成的。不能仅通过提高阈值来解决。

浏览器链路另一次任务已成功打开视频并发送截图。其观察期间页面变化导致的图片不可用，与 PCUse 的像素拦截属于不同链路，本轮不据此重写浏览器工具。

## 执行切片

### 1. 放宽完全访问模式的像素拦截

- [x] 在 `trusted_auto_allow` 下，取消整窗像素变化和点击区域像素变化作为输入的硬性否决条件。批次内预期变化不再要求与初始截图像素一致。
- [x] 保留窗口身份与位置尺寸、坐标范围、前台与实际遮挡、设备代次、停止和用户接管检查，以及现有观察有效期。引用仍绑定模型实际看过的截图。
- [x] 不自动重放输入、不把旧坐标悄悄绑定到新截图。操作完成后继续返回真实截图，由模型判断误点、页面变化和下一步。
- [x] 不新增动画识别、特殊网站白名单或逐步业务证明。`ask_each_time` 和 `disabled` 的权限语义保持原样。

入口：`desktop_pet_next/src-tauri/src/computer_use/session.rs`、`policy.rs`、`input.rs`。替换依赖整窗像素拦截的旧测试，保留实际窗口与输入边界测试。

### 2. 需要重新定位时，在同一结果里回传现场

- [x] 输入前因观察过期、窗口几何变化等需要重新定位时，若当前授权仍允许观察，直接取得并返回新截图、观察信息和新 `context_ref`，减少一次单独 `observe` 往返。
- [x] 复用检查中已经取得的可用截图，避免再次捕获同一现场；捕获失败时保留实际原因。
- [x] 新引用只来自本次真实观察，旧引用不改写。观察成功不能把原操作失败改成成功，也不能解除停止、接管或扩大授权范围。
- [x] 保留各步 `executed / not_started / unknown` 和未执行的剩余动作。输入已发生、后续取图失败时，仍明确保留已执行事实，避免模型重复发送。
- [x] 贯通设备结果、宿主字段筛选和模型图片附件链路；图片按现有机制仅用于当前观察，不把图片字节重复写入历史。

入口：Rust 的 `session.rs`、`context.rs`、`protocol.rs`；Python 的 `companion_v01/computer_use/dispatch.py`、`media.py`、`outcome.py`。尽量复用既有观察字段，不再包装一份重复结果。

### 3. 用实际输入核验坐标链路

- [ ] 在本机 200% DPI 下，用独立测试窗口记录原始截图尺寸、模型收到的尺寸、裁剪区域与缩放比例，以及实际光标落点。当前环境实际为 96 DPI，已完成整窗、裁剪放大与边缘落点实测；200% 待对应显示环境补测。
- [x] 覆盖整窗、裁剪放大和边缘坐标，验证坐标转换后落到指定控件；错误坐标不得越出授权窗口。
- [x] 只有发现实际尺寸或转换错误才改映射。当前 PNG 回传没有通用缩小处理，不预设存在丢失缩放比例的问题。本轮未发现映射错误，保持现有实现。
- [x] 如果图片说明缺少必要坐标依据，只补充当前截图的尺寸与坐标单位；不同时混用窗口像素、屏幕像素和归一化坐标。现有图片元数据已提供必要依据，指南明确图内像素坐标。

入口：Rust 的 `region.rs`、`input.rs`；Python 的 `media.py`、`companion_v01/model_image_inputs.py` 及实际模型图片组装入口。

### 4. 按需等待，并整理现有指南

- [x] 为 `observe` 增加可选 `wait_ms`，默认 0；仅在模型判断页面仍在加载时等待后观察。等待沿用执行预算，期间可被停止或接管打断，不给普通点击、输入增加固定延迟。
- [x] 同步 Python 与 Rust 的参数定义、协议版本和测试，确保按需加载后的工具可以真实调用。
- [x] 在现有 GUIDE 中替换过时说明：基于当前截图规划短段操作；批次结束看结果；等待仅按需；失败根据执行状态与返回的新现场重新规划；操作已执行不等于任务成功。
- [x] 删除与新机制冲突或重复的像素证明要求。说明仍通过能力加载提供，不每轮在动态尾部追加同一份提醒。

入口：`companion_v01/computer_use/contracts.py`、`tool_handlers/computer_use.py`，以及 Rust 的协议与执行入口。不修改通用聊天输出、MemCore 压缩或工具调度机制。

## 验收

| 场景 | 必须观察到的结果 |
| --- | --- |
| 稳定输入框旁有加载动画，观察间隔 17、30、55 秒 | 完全访问模式下不因动画阻止点击、输入与提交；最终截图能看到真实效果 |
| 光标闪烁、按钮悬停颜色变化 | 不产生无意义的像素拦截或模型往返 |
| 窗口移动、缩放、遮挡、切换前台 | 不继续使用失效坐标；能观察时同次返回新现场，不能观察时如实说明 |
| 用户停止、接管、设备代次变化 | 剩余动作停止，新截图或新引用不能绕过原边界 |
| 第二步失败，或输入后取图失败 | 已执行状态准确，后续动作未执行；没有自动重放或假成功 |
| 200% DPI、裁剪与放大 | 实际落点与截图指定位置一致，窗口边缘转换正确 |
| 默认观察、等待观察、等待中停止 | 默认无额外等待，指定等待有效，停止及时生效 |
| 询问模式与禁用模式 | 原审批与禁用行为保持有效 |

实施后运行相关 Python 行为测试、Rust 单测、原生构建及 `git diff --check`；涉及前端界面时再补前端 build 和浏览器检查。真实 Windows 验收不能只以模拟返回成功代替。

最后在用户授权范围内复测原网页任务，固定模型、权限和环境，记录输入是否生效、截图是否实际进入模型、任务是否完成、模型往返数、重新观察次数与本地耗时。区分网页网络等待、上游推理与本地执行；不以工具次数减少单独宣称体验改善。
