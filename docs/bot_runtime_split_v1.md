## 调用链和状态归属

Host 启动和单 Bot 启动继续从原入口创建 `BotRuntimeFactory`。`BotRuntime` 仍是一个带 slots 的数据类；生命周期组合类使用空 slots，保留原有构造参数、37 个字段的类型及初始化/展示约定，再增加内部启动结果、停止标记和生命周期锁。原有调用方法、属性和完成事件 helper 的签名保留，类型注解可以正常解析。

每个 Bot 继续使用同一个引擎、实例租约、插件代次运行时、会话队列和任务 Store。会话收件箱与 Host Job Store 仍连接引擎已有的实例数据库；各任务运行时继续共用引擎的后台执行器、执行 Broker 和完成发布入口。共享桌面卫星服务仍按 Bot 提供能力，显式 Bot 的设置覆盖仍隔离在自己的配置视图和提示缓存命名空间中。

`plugins.py` 中的 worker 项目根和默认市场索引路径按新的目录层级定位到仓库根。主人私聊、桌宠、QQ 群、照料状态和跨会话读取继续使用原有策略对象与真实存储，本轮保留这些归属规则。

启动仍先启用插件和必要的已验证回退，再建立命令/事件/Hook 桥接，恢复会话和任务，绑定完成回调与 Hook，最后启动主人私聊群记忆镜像。镜像启动成功后才写入已启动状态。

关闭仍先撤销回合准入，再排空会话队列、私聊群记忆镜像和 Agent 回合，然后解绑完成回调、发送引擎停止信号、关闭 QQ 后续任务和插件、关闭语音，最后关闭引擎。语音和引擎的阻塞清理仍在线程中执行，保持兄弟 Bot 在同一 Host 截止时间下并发关闭。

若队列、镜像或回合路由没有确认排空，引擎保持延后清理，后续可以再次调用 `stop()` 重试。已经完成清理流程的关闭结果沿用原有缓存，包括失败信息。Bot 关闭后的实例锁仍由进程保留到退出，避免替换进程与尚未释放的底层句柄重叠；构造失败时的锁释放顺序也保留。

## 复现与修复

1. 镜像启动失败或被取消时，原实现已写入 `_started`，重试会误报运行正常。现在只在全部启动步骤完成后保存启动结果。
2. 插件降级启动后再次调用 `start()`，原实现会返回 `active`。现在重复启动保留初次启动的真实降级状态和原因。
3. 同一 Bot 的并发启动会重复恢复队列，并发关闭会重复清理共享服务，启动和关闭交叠时还可能在引擎关闭后继续装配。现在同一运行时的生命周期操作串行执行，兄弟 Bot 的独立生命周期仍可并发。
4. 停止请求已撤销准入、队列却尚未排空时，原实现仍可能报告“已经启动”。现在停止标记在等待清理前设置，即使排空需要重试，也不会重新报告运行正常。
5. 路由停止信号、镜像关闭和回合排空异常原来直接抛出。现在返回带原因的降级结果并明确标记引擎清理延后，允许后续重试；保留任务仍可能使用引擎的事实。
6. 完成回调解绑异常原来会跳过剩余清理。现在记录失败并继续尝试关闭其他服务；插件明确返回未停止状态时，也不会因缺少清理失败计数而报告关闭成功。

新增 `tests/test_bot_runtime_boundaries.py` 的 17 项检查覆盖启动失败/取消、降级、并发、交叠、未排空重试、清理异常、实例锁归属和插件路径。首批 12 项中有 11 项在修复前复现失败，另 1 项保护进程继续持有实例锁的既有约定。构造失败检查在引擎绑定、会话绑定、任务绑定、语音绑定及引擎创建前注入故障，验证真实实例锁可以重新获取，并验证清理异常不会覆盖原构造异常。

扩展验收另发现两个旧测试替身落后于既有接口：多 Bot 路由缺少场景使用的照料/时间线端口和新记忆设置使用的 QQ 字段，桌宠照料替身缺少会话参数。用拆分前原始 `bot_runtime.py` 复跑仍有同样的失败。现在补齐测试替身并增加照料会话断言，保留原有路由、身份和会话隔离断言。
