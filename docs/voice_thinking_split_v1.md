# 语音生成任务职责拆分

本片把 `companion_v01/voice_runtime/thinking_agent.py` 从 900 行收为 25 行历史导入入口，实际实现放进 `thinking_runtime/`。原执行器、启动结果、任务上下文及恢复事件工厂仍可从原路径导入。

## 职责导航

| 文件 | 职责 |
|---|---|
| `thinking_agent.py` | 历史导入入口 |
| `thinking_runtime/executor.py` | 唯一执行器、任务/回调登记、取消围栏及共享锁 |
| `thinking_runtime/context.py` | 不可变任务上下文、MemCore/候选文本解析、回调查询和恢复事件工厂 |
| `thinking_runtime/commands.py` | 生成/取消命令的同步 observation、校验和登记 |
| `thinking_runtime/scheduling.py` | 在 Host 接受 `generation_started` 后提交真实后台生成任务 |
| `thinking_runtime/recovery.py` | 恢复待处理任务上下文、将不可验证的旧进程生成状态收为失败 |
| `thinking_runtime/stream.py` | 模型流消费、文字/语音观察、取消及终态收尾 |

五个职责 mixin 使用同一个执行器的任务、回调、取消状态和 `RLock`，没有额外创建会话状态、模型请求队列或第二把业务锁。六个实现模块的纯迁移规模为 98–215 行。

模型请求仍在 Host 持久化并接受启动 observation 后才开始；普通回复仍从已落盘的 MemCore 输入投影取得上下文。候选回复仍是临时只读生成，不写成正式助手记忆。TTS、真实客户端回执和语音产物继续走原 Host 链路。旧进程正在生成的回复仍通过 `voice_thinking_runtime_restarted` 收口，不能在下一场通话重新请求模型。

## 纯迁移验证

拆分前与纯迁移后的相同 155 项检查均通过：生产装配及边界、Host 及边界、TTS、播放上下文及回执边界、持续通话路由和冷导入。

25 个历史方法 AST 完全一致；四个历史类的方法签名、运行时类型注解解析、22 个历史模块绑定及 `__all__` 状态通过核对。编译、Ruff 正确性检查和 `git diff --check` 通过。

未做真实桌面、音频设备或外部 ASR/模型/TTS 验收，未测量性能，也未重启日常服务。工作区其他改动保留。

## 任务生命周期修复

- 关闭状态加入既有取消围栏。已经排队的任务不再进入模型，运行中的流在下一事件边界停止消费；读取播放上下文和暂存最终展示信息后也重新检查关闭状态，晚返回的 final 不写成正常助手记忆。迭代器通过原 `finally` 尝试关闭，任务登记清理移到外层 `finally`。
- 命令执行、上下文解析后的任务发布、重启恢复登记和实际后台提交处检查关闭状态。准备列表与提交之间发生关闭时返回 `voice_thinking_executor_closed`，不重建关闭对象的任务。任务占位和提交共享原执行器锁；并发启动同一任务只提交一次，另一请求得到重复状态。
- 再次登记轮次但未提供回调时清除原通道回调。任务收尾只移除仍由自己拥有的登记；同一轮的新 factory、模式、通知或展示回调，以及其他任务的上下文，不被旧任务删除。候选任务完成后仍保留原来供最终输入使用的轮次上下文。
- 调度失败通过原 Host 追加失败 observation，确认后释放未用任务和回调。异常正文不进入事件或启动结果。
- 生成失败事件构造、journal 提交或提交确认失败时，执行器保留待收尾记录和已经构造的同一事件。后台工作结束后不再算运行中，但待确认任务不会重新进入模型；后续启动只补做原事件确认，确认后唤醒原交付通道。journal 已提交、确认返回丢失时仍按原 event id 恢复，避免多写失败事件。
- 关闭也补做待确认失败记录；未确认时抛出稳定的 `voice_thinking_shutdown_settlement_pending`，生产层保留资源并返回关闭未完成。并发或重入的确认由同一执行器中的占位保护，不能提前报告已收口。完成确认后关闭可重复调用。

待收尾记录使用原执行器的锁，保存原 Host、不可变任务上下文、失败原因和事件；不另建数据库、模型请求队列或会话状态。跨进程恢复仍由原 journal、Host 及生产装配顺序负责，已运行的旧模型流仍按原规则失败收口，不重跑。主人私聊租约结算继续走既有接口。
