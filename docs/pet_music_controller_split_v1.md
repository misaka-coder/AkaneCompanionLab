# 桌宠音乐控制器拆分

2026-10-03，拆分 `desktop_pet_next/src/pet/music.js`。原文件 1,238 行；保持主窗口、附件播放、设置命令和宿主音乐工具的既有接口。继续复用 `desktop-music-player.js`、系统媒体和场景播放桥接。

## 第一片：工作区音频

- `music/workspace.js`（203 行）拥有音频暂存/准备请求、目录刷新、推荐和当前请求的忙碌状态。入口暂为 991 行。
- 播放选择的 revision 与现有运行时 scope 共同判断异步结果归属；直接切歌、暂停或停止会使旧准备请求失效。重复点播同一待准备音频共享任务。
- 从暂存开始显示 loading。取消后立即结束忙碌状态；旧任务完成不能清除新任务状态，也不能在另一会话通知界面。
- 目录刷新允许新会话请求越过尚未返回的旧请求；目录 getter 不返回旧 scope 的缓存。失败原因留在模块内部，失败清空目录不会伪造成功。
- 删除只由工作区单首播放调用的旧批量拖入准备分支。附件仍按现有流程先导入工作区，再显式播放；不恢复自动拖入播放。

验收：8 项真实控制器行为测试通过，原实现有 5 项失败；命名接口/状态归属检查、完整控制器装配 smoke、宿主音乐工具、媒体命令、媒体上下文、附件 smoke 通过。前端构建和 `git diff --check` 通过。

## 第二片：播放、控制和表情

- `music/playback.js`（442 行）拥有队列、当前曲目、播放状态、播放中的 Promise 和选择 revision；`music/controls.js`（87 行）路由本地/系统媒体命令；`music/emotion.js`（76 行）拥有音乐表情与恢复计时器。入口暂为 487 行。
- 切歌先结束上一首的播放状态；新曲目真正启动前，loading 可观察，失败不会继续报告“播放中”。播放失败仍保留原因，原来的调用方错误处理继续生效。
- 自动切歌先决定目标，只完成本次选择；旧自动播放结果不能继续执行循环或停止新曲目。自动播放失败进入既有播放错误处理，避免未处理的异步拒绝。
- 场景占用播放资源时，暂停后恢复本地音乐同样遵守场景所有权。
- 随机播放直接从其他曲目中选择，移除重复抽样循环，仍避免连续播放当前歌曲。

验收：新增 5 项行为检查，其中 4 项在上一片实现上失败；共 13 项通过。39 模块边界检查、完整装配、宿主音乐工具、媒体命令、媒体上下文、实时语音打断 smoke、构建和差异检查通过。

## 第三片：歌词请求、快照与最终装配

入口最终为 116 行，只创建模块、桥接两个持久设置并提供原有 39 项接口，其中 8 个 getter 保持实时、只读语义。构造和快照读取不启动音频或网络工作。

| 文件 | 行数 | 拥有的职责 |
| --- | ---: | --- |
| `music.js` | 116 | 装配、设置与兼容接口 |
| `music/playback.js` | 394 | 播放选择、队列和本地播放器 |
| `music/workspace.js` | 206 | 手边音频准备、目录与推荐 |
| `music/timeline.js` | 206 | 歌词上传、分析、轮询、取消与附件 scope |
| `music/snapshot.js` | 214 | 本地/系统媒体快照与歌曲目录投影 |
| `music/controls.js` | 87 | 活跃媒体命令与反馈 |
| `music/emotion.js` | 76 | 音乐表情及空闲恢复 |

跨模块通过命名接口访问拥有者；前向接口复制 property descriptor，保留 getter 的实时性。`pet-runtime-check.mjs` 只允许同一功能内部的组装导入，继续检查跨领域导入、临时状态归属和缺失标识符。

- 歌词请求在开始时捕获身份和 Bot endpoint。读取本地资源、读取 Blob、上传、解析响应和分析的每个异步边界都核查原 scope、曲目对象与请求 revision。换曲和关闭会 abort 正在执行的请求；已取消请求的晚结果不能再写入歌词、通知或重试。
- 同一音频进入另一会话时重新上传，旧附件编号和歌词时间线不能进入新会话请求。快照通过纯读取投影隐藏旧 scope 的附件和时间线；没有副作用的快照不会重置真实播放器。
- 后端本地歌词分析固定使用本地曲目快照；本地音乐暂停、系统媒体变为活跃后，分析不会误用系统歌曲标题或 source ID。
- pending/processing 保持轮询，失败保留原因并延迟重试，ready 结束轮询。本地 LRC 继续走本地歌词，不上传分析。
- 目录读取途中再次导入音频，刷新请求合并为一次补发；旧请求不丢掉最后一次刷新，也不覆盖较新的目录任务。
- 原 `addDroppedAudioFiles` 与 `enqueueMusicTracks` 两个内部函数的批量/自动播放分支已无真实调用方，替换为单首工作区准备和 `queueAndPlayMusicTrack`。音频仍须先进入工作区并显式点播。队列导航、删除、播放模式和原有公开接口保留。

AST 对照原文件的 60 个内部函数，保留 58 个；删除的两个函数对应上述旧分支。参数变化只有播放方法新增兼容的内部 request 选项，以及三个私有歌词/目录 helper 显式接收任务或 scope。公开 39 项接口与顺序保持一致。
