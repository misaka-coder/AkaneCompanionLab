# 能力目录差量更新与运行绑定实施记录

日期：2026-10-03。依据：[执行单](capability_catalog_delta_and_runtime_binding_plan_v1.md)。代码与本地依赖已更新，用户已授权提交和重启。下文记录实现及重启前的受控验收；部署后的健康检查与缓存计量另行确认。

## 用户和模型会看到的变化

- 真正新增、修改和移除能力时，尾部只通知对应工具或 Skill。基线仍保留完整目录，模型仍通过现有准确名称和加载入口获取完整契约。
- 已知 MCP 的连接故障与恢复不再反复撤销、重新加入工具。普通聊天、目录读取、加载和契约检查不再按健康有效期触发网络探测；真正调用仍返回真实连接失败。
- 同一插件产物或同一 MCP 声明的重启不再构成公开契约升级。下一次调用重新绑定当前处理器；真实实现或声明升级仍拒绝旧契约，授权撤销仍即时生效。

## 实现范围

目录事实由已有工具选择与 `SkillRegistry` 同一快照提供，隐藏记录保存结构化状态，`memcore_integration/catalog.py` 直接计算差异并使用固定模板，不增加模型请求。工具描述不截断；Skill 正文修订也可产生对应名称的更新。仅插件提示块摘要或诊断变化不重发目录。

当前压缩代内已发布消息保持原位置和内容。真实压缩成功后新基线合并最终状态，旧代通知沿用已有请求投影过滤机制；失败、取消和普通重进不强行切代。客户端、会话、角色和授权作用域保持原隔离。旧隐藏状态无需全库迁移；不带结构化元数据的轻量宿主保留原文本兼容行为。

`McpHostManager` 保存成功发现的声明，并防止过期配置、运行代和其他 profile 的旧缓存覆盖较新的共享声明。并发发现共用一个在途任务；单个等待者取消不取消其他等待者。执行中的新声明会通过现有配置写入链原子持久化，并保留当前权限与暴露覆盖项。重连发现契约变化时复用宿主既有的结构化拒绝结果，明确 `executed=false` 并给出准确的重新加载入口，避免被误归类为网络故障。

公开插件修订复用受管产物 digest。普通安装和 editable 安装从分发文件、实际源码取得稳定修订，不导入插件代码；无法确认来源时保留原有保守运行代失效。内部运行 ID 继续用于生命周期、在途授权和执行日志。`ContractBoundHandler` 从同一次当前选择取得契约与处理器，匹配时换新绑定，在途插件调用仍保留已捕获执行代。

通用依赖 `F:/Akane/capcore-adapter-mcp` 升至 0.1.1，主仓库同步精确版本约束。新增 pooled client 的可选 `expected_tool` 和无 I/O 的 `confirmed_tools`，以及发送目标调用前的 `McpToolContractError`。实现使用官方 SDK 的工具列表变更通知，未修改 `.venv` 内源码，未引入项目专用提示、权限或记忆逻辑。已通过仓库现有本地 wheel 构建和安装流程同步运行环境。

## 历史只读回放

选择执行单中的同一压缩代两条旧更新，用当前差异生成器回放。旧记录未保存结构化用途时，从原目录还原对应描述；保留全部历史契约指纹变化，不假设它们均为无效运行代变化。

| 样本 | 原通知字符 | 差量通知字符 | 保留信息 |
| --- | ---: | ---: | --- |
| 四个 MCP 暂时消失，同时 28 个契约指纹改变 | 8,988 | 2,473 | 四个移除名称、28 个准确契约变化名称与重新加载入口 |
| 四个 AnySearch 工具重新出现 | 26,534 | 20,103 | 四个准确名称、原始完整用途与加载入口 |
| 合计 | 35,522 | 22,576 | 减少 12,946 字符，约 36.4% |

回放没有修改生产数据库或重发消息。差量机制本身的降幅不等于缓存命中率。第二条仍较长，因为四个第三方工具的原始描述本身很长；新版连接故障保留已确认声明，不会因这种健康波动生成移除和重新新增事件。回放未将健康新行为虚算进节省数字，也未截断用途。
