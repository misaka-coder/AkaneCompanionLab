# 语音合成执行器职责拆分

本片将 `companion_v01/voice_runtime/tts_executor.py` 从 631 行收为 26 行历史导入入口。五个实现模块放在 `tts_runtime/`，原执行器、命令路由、文本/音频端口协议、任务对象和两个兼容辅助函数仍可从旧路径导入。

## 职责导航

| 文件 | 职责 |
|---|---|
| `tts_executor.py` | 历史导入入口 |
| `tts_runtime/executor.py` | 唯一执行器、Host/通知绑定、关闭及取消状态和共享锁 |
| `tts_runtime/commands.py` | 命令路由、任务与制品端口协议、命令上下文与归属字段校验 |
| `tts_runtime/scheduling.py` | 每会话容量限制、共享后台合成 lane、任务结果及原 Host 回执收尾 |
| `tts_runtime/synthesis.py` | 语音文本解码、真实 provider 调用、同步/异步结果解析和不可变音频保存 |
| `tts_runtime/results.py` | 确定性事件及音频引用、失败观察和已保存音频恢复 |

四个职责 mixin 共用原执行器的任务表、关闭状态、Host 和 `RLock`，不另建会话状态或请求队列。纯迁移后五个实现模块为 72–161 行。

音频仍通过原制品端口保存后才生成 `voice.tts.ready`；结果不可确认时仍保留原执行中回执并由原音频引用恢复。合成 lane、每会话两个任务的容量限制、插件调用的取消信号和来源元数据、确定性 invocation id、命令幂等键及真实客户端播放回执规则保持原有行为。

本片未重启日常服务，未做真实桌面、音频设备或外部模型/TTS 验收，未测量性能。工作区其他改动保留。

## 生命周期与结果确认修复

- 同步执行在关闭后不再读取文本制品；文本解码及 provider 调用准备完成后重新检查取消状态。合成或音频保存期间关闭时，已经返回的真实音频仍按原引用保存，但最终观察收为失败，不能以迟到的 `ready` 触发播放。普通阻塞 provider 仍须等待返回；插件调用继续使用原取消信号。
- 任务占位与提交共用原锁。后台入口只接受仍由自身拥有的任务，重复调用不会再次合成。尚未开始的排队任务可以在关闭时通过原回执链收为失败，之后的队列回调不再进入 provider。
- 调度失败、关闭预检失败和重启阶段预检失败保留已经构造的同一组观察，直到 Host 确认。失败回执暂时写入失败后，补做原回执，不丢失已知失败原因，也不重新排队。
- 音频写入抛出异常时返回结构化的结果未知，因为文件可能已保存而确认返回丢失。后台任务结束后的结果未知可以重新核验原音频引用；暂时不可读或读取异常仍保持未知，可读后恢复相同音频。正在运行的任务不会因此提前确认，缺少可靠音频时不再次合成。
- 并发恢复只发布一组完成观察；成功合成和恢复共用音频结果构造及取消检查，减少重复处理。插件来源、确定性事件/音频/invocation 标识继续来自原路径。
- 任务清理通过 Host 的实际回执结果确认。会话状态中已移除的任务，若最终完成标记或释放回执写入失败，仍保留归属；提交后确认丢失也可以从原持久回执核验。容量和清理不再单凭 `pending_commands` 中是否存在任务判断。
- 关闭在同一个执行器内占位，补做已有回执，并通知已完成任务的原交付链。仍有运行任务、未知结果或未确认回执时抛出 `voice_tts_shutdown_settlement_pending`，生产资源管理层保留执行器并返回可重试的未完成状态。并发/重入关闭不能提前报告完成；确认后重复关闭成功。

任务对象增加两个具有默认值的内部标记，用于区分后台任务已开始和回执已确认；原有三个构造参数及字段类型保持兼容。命令只保留当前语音单元的归属字段。没有新增数据库、持久格式或 TTS 请求队列；跨进程恢复仍使用原 journal、命令回执和音频制品。
