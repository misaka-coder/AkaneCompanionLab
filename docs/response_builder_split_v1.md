# 回复上下文构建拆分

## 基线与边界

`companion_v01/engine_services/response_builder.py` 原为 1670 行，其中 `prepare_context()` 占 981 行。它负责客户端和角色上下文、MemCore 历史投影、能力目录与工具冻结、最终提示组装、压缩与预算保护。

保留 `prepare_context()` 的调用签名和返回协议。历史仍由 MemCore 提供，媒体和 provider continuation 只叠加到本次请求；压缩后的新 generation 必须重新采样能力和插件上下文。后端不接入新的桌面界面依赖。

拆分前，10 个相关测试模块共 260 项通过，涵盖 MemCore、原生工具实际请求结构、provider continuation、紧凑回读、共享身份、QQ、语音、视觉、角色和插件观察。

## 第一片：纯辅助函数

抽离目录与媒体叠加、MemCore 投影与失败诊断、预算估算与裁剪、提示规则，共 19 个辅助函数。逐一核对 AST，函数实现和签名全部保持一致，`prepare_context()` 此时仍保持原实现。原入口继续静态导出这些兼容名称。

测试中的记忆后端选择改为替换统一配置 `config.MEMORY_BACKEND`，让入口和独立投影函数使用同一配置来源。

本片完成后，同一组 260 项回归全部通过，Python 编译、项目 lint 和差异检查通过。

真实供应商、QQ 传输和桌面互动需要实际运行验收；本地回归使用受控响应和临时存储。

## 第二片：明确的准备阶段

最终入口为 135 行，`prepare_context()` 从 981 行降为 88 行（含原来的完整签名）。调用顺序为：环境解析 → 历史投影 → 角色与视觉材料 → 工具曝光和目录协调 → 提示组装 → 预算保护 → 返回协议收尾。

| 模块 | 行数 | 职责 |
|------|------|------|
| `response_contracts.py` | 90 | 本次请求、客户端环境、上下文分区和材料的明确数据契约 |
| `response_materials.py` | 409 | 客户端和 care 策略、角色、视觉资源、稳定与临时贡献 |
| `response_projection.py` | 498 | MemCore surface、当前消息、失败恢复、影子比较及请求内历史状态 |
| `response_catalog.py` | 200 | 目录基线与更新筛选、当前轮次的媒体和签名证据叠加 |
| `response_exposure.py` | 319 | generation 内工具冻结、原生 schema、目录写入及提示刷新 |

请求、环境和材料采用显式数据类；可变的历史裁剪状态和工具曝光协调器只属于一次调用，不缓存到引擎。预算重建读取当前投影和当前曝光结果，继续保留冻结的能力选择、插件稳定块、provider continuation 和本轮输入。20 个原有辅助函数的实现 AST 完全一致，兼容导出仍指向唯一实现；原入口的参数、类型注解、默认值和返回类型均保持一致。

移除未使用的 `projection_state` 临时变量、重复的投影读取参数和重复的工具提示组装。旧实现从未读取两个 legacy summary 输入，相关字符串始终为空；删除这两个空状态字段及不可达的 episodic 裁剪循环，调用入口仍接受旧参数，不恢复旧的历史读取权威。测试文件同时清理两个无用导入。

## 顺手修正的行为

1. 压缩期间关闭原生工具或供应商失去支持时，旧实现会残留上一份 schema 和排除项。现在每次建立新计划都清除旧 schema、排除项、原生名称和别名；对应的轮次提示一起刷新。即使压缩失败、generation 未变化，也能正确恢复兼容工具提示。
2. 共享私聊使用同一历史时，旧的压缩后筛选漏传 `client_scope`，可能采用另一客户端的目录基线或更新。初始化和压缩后统一通过同一筛选入口，继续保持 QQ／桌宠目录隔离。

在未修改的原始文件上复现了 QQ／桌宠两个共享目录失败分支及原生工具关闭／供应商降级两种失败；修复后对应回归通过。另覆盖压缩失败时关闭原生工具、投影刷新失败立即终止、新请求之间的历史和预算隔离、legacy 裁剪保护当前输入且不修改调用方数据。

新增结构检查覆盖全局名称绑定、模块全部可达、无反向或循环导入、兼容签名与默认值、辅助函数唯一归属和模块大小边界；常规测试发现会自动收录这些检查。

最终 24 个相关测试模块共 525 项全部通过，覆盖上述分支以及提示构建、插件稳定块、工具续接、原生协议、完整轮次和 care 归属。Python 编译、项目 lint、额外的未使用导入／变量检查和差异检查通过。本轮没有前端改动；真实供应商、QQ 传输和桌面互动尚未进行现场验收。
