# 能力目录与执行上下文生命周期 V1

## 目标

模型应当随时知道当前能加载哪些 Skill/MCP、当前在哪个目录工作，以及本轮有哪些工具可用；这些事实不能互相污染，也不能在每次工具调用后重复写入 MemCore。

本设计只建立三个清晰边界，不引入新的轮数、大小或行为限制：

1. **能力目录**：低频变化、可版本化的环境事实；
2. **执行坐标**：会话当前工作目录等即时运行事实；
3. **本轮工具提示**：由本轮实际工具定义派生的操作说明。

## 三个事实源

### 1. 能力目录

能力目录只列出可按需加载的 Skill 和 MCP，每项保留名称与一句描述。原生工具已经通过工具 schema 暴露，不在目录中重复列举。

加载 Skill/MCP 只读取能力，不改变目录；安装、更新、删除才改变目录内容。

目录采用 `base + latest update`：

- 每个 MemCore 压缩代第一次请求写入一份 `catalog_base`；
- 同一代目录变化时，在变化发生后的时间线位置写入完整替换型 `catalog_update`；
- 同一代无论变化多少次，模型只看见 base 和最新 update；
- 下一压缩代以当时的完整目录建立新 base，旧 update 不再投影。

目录记录不参与检索、不生成长期记忆，也不进入阶段摘要。历史版本可留作运行审计，但不会同时投影给模型。

### 2. 执行坐标

执行坐标由当前会话工作区状态实时计算，包含平台、Shell、`working_directory`、项目和访问边界。

- 它不写入 MemCore；
- 它不跟随每次工具结果重复追加；
- 工作目录切换后，下一次模型请求立即看到新值；
- 单次工具显式 `cwd` 只由该工具结果的 `effective_cwd` 说明，不改变会话默认工作目录。

### 3. 本轮工具提示

本轮工具提示由当前真实暴露的工具和能力状态生成，只在当前请求中出现。它包含兼容工具说明、媒体路由和必要的工具调用反馈，不冒充历史事实。

## 提示布局与缓存

请求布局保持稳定：

1. 稳定 system prompt；
2. 当前压缩代的能力目录 base；
3. 当前执行坐标；
4. 本轮工具提示；
5. MemCore 时间线（其中最多保留最新 catalog update）；
6. 当前消息和临时材料。

能力安装后的 update 追加在旧前缀之后，因此不改写已经可缓存的历史。普通工具轮不创建新目录记录；工作目录不变时执行坐标字节也保持不变。压缩本来就会形成新上下文代，目录在该边界自然 rebase。

## 失败语义

- 目录读取失败时不把错误文本写成新的权威目录；保留模型当前可见的 last-good 目录，并把失败作为本轮运行状态反馈。
- MemCore 写入或刷新失败时不伪造更新成功；本轮仍可使用真实工具 schema，下一轮重试目录同步。
- 旧 `material.runtime_context.capabilities` 单体快照停止写入并从模型投影排除。

## 验收

1. 连续普通工具轮只有一个 base，不产生 update；
2. 工作目录切换不会改变能力目录 revision；
3. 安装、更新、删除能力后，下一轮立即看见完整 update；
4. 同一代多次变更只投影最新 update；
5. 压缩换代后出现新 base，旧 update 不再可见；
6. 历史单体快照不会进入模型上下文；
7. `system_prefix_hash` 与 `tool_schema_hash` 在普通工具轮保持稳定；
8. QQ 群聊长任务不会再反复看到旧项目坐标或旧 MCP 目录。
