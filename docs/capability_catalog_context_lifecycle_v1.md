# 能力目录与执行上下文生命周期

更新：2026-09-11。本文以统一工具暴露实现为准，替代早期 G1 加载后扩充 schema 及仅保留最新目录更新的行为。

## 事实源与边界

能力目录由现有注册、领域、可见性及权限选择产生：宿主工具、插件工具、MCP 工具按单工具区分常驻与按需；Skill 保留自身简表和正文加载链。程序专用服务、不可见及禁用能力不会因“全目录”获得模型暴露许可。

原生 tools 只包含当前发布的常驻声明、固定 `capability_list`、`capability_load`、`capability_invoke` 和可选 `capability_search`。按需简表给出精确 ID 与用途，完整契约和调用结果通过真实工具消息追加到尾部。load 不扩大 tools，也不授予权限。搜索是子串匹配，可分页列举或直接按精确 ID 加载。

执行坐标继续由当前会话工作区生成，不写入能力目录；切换工作区会改变这部分请求，不能据工具稳定推断整个请求稳定。本任务不全面重排角色、检索、时间或媒体材料。

## 支持的压缩生命周期

仅 `MEMORY_BACKEND=memcore` 且实际使用可用权威请求投影和真实压缩代时提供本保证。legacy、dual 保留既有记忆路径，共用新工具执行链，按后续请求即时呈现配置；不模拟 MemCore 代次。权威投影或快照失败时返回明确失败，不伪报边界生效。

1. 本压缩代第一次请求建立常驻声明、插件稳定块及目录基线。快照属于现有 MemCore 命名空间中的隐藏运维记录，不是权限注册表。
2. 目录变化在当时的时间线位置追加 update。**同代全部已发布 update 按原位置保留**，普通工具轮不重复写入同一更新。打开的工具回合内更新归入该回合，避免被消息分组移到工具结果之后。
3. 加载契约不改变安装目录。安装、更新、移除、可用性及偏好变化可形成版本更新；相同描述下的可观察 generation 变化也能产生通知。
4. 新工具可立即 load/invoke。旧常驻 schema 保留本代发布绑定，失效时返回配对的未执行结果；加载新契约后用固定入口恢复。不能拿旧参数静默调用最新实现。
5. 真实压缩成功后合并最终状态并建立新目录基线；没有差异或安装后卸载的净零变化不强制更改 tools/system。压缩失败继续保留原代和待合并状态。
6. 宿主重启、会话重进恢复既有基线；新会话按目标偏好建基线。无压缩的原会话可以长期待合并，不定时强制整理。
7. 插件 system 块普通新增等待边界，撤销/替换旧规则立即移除，正确撤销优先于前缀稳定。纯文本客户端的提示块也有独立的压缩代基线，不污染工具客户端的声明。

身份、会话、角色、客户端和授权身份共同确定快照及契约作用域。历史工具回执可按既有机制回读，但不证明当前权限或契约有效。目录和声明快照不参与长期记忆检索、语义化或阶段摘要。
