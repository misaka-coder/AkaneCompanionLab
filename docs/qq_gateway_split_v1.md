# QQ 网关拆分 v1

`companion_v01/qq_gateway.py` 从 5,558 行收敛到 957 行。实现按职责放入
`companion_v01/qq_gateway_runtime/` 的 17 个实现模块（13 个实例处理器、4 个
辅助模块），入口负责明确的依赖装配和兼容转发。

拆分保留 `NapCatQQGateway`、`QQMessageContext` 和原有调用入口。与拆分前
源码核对，原有 149 个方法的签名一致，8 个原有属性继续存在。处理器的可变
状态由每个网关实例独立持有；模块不反向导入入口，内部依赖无环。

## 切片一：上下文与会话配置

| 模块 | 职责 |
|------|------|
| `context.py` | 已准入消息的不可变上下文及模型、投递载荷投影 |
| `definitions.py` | 共享常量、限制和兼容名称 |
| `validation.py` | 角色、服装、会话、模型、回复模式和文件名的校验 |
| `preferences.py` | 会话覆盖配置、共享状态锁、状态加载和原子保存 |

原文件本切片降至 5,016 行。配置字典继续保持原有公开属性及引用身份，
不同网关实例的配置独立。重新加载以原字典清空后更新，避免消费者保留旧引用。

### 同切片修复

- 原实现给每类配置分别加锁，然后把各自快照写入同一个状态文件，两个并发
  保存可以让旧快照最后覆盖新值。现在各类配置共享一个重入锁，快照、临时文件
  写入和替换保持有序。交错线程测试在原实现上失败，在新实现上通过。
- 无效 UTF-8 状态文件原先会抛出未处理异常。现在状态接口保留安全的错误类型，
  修复文件后重新加载可恢复；不公开异常中的路径或私有信息。

### 验证

- 拆分前 QQ 网关、命令、身份、投递身份、多 Bot、商城和 Channelcore 相关
  187 项测试全部通过。
- 同一组回归加 `tests.test_qq_gateway_modules`：192 项全部通过，新增检查涵盖
  并发保存、真实文件重载、网关隔离、写入/替换失败清理和编码错误恢复。
- Python 编译检查、`git diff --check` 通过。

未启动真实 NapCat/QQ、桌面音频或外部 TTS 服务。这些验收不由单元测试结果代替。
已有技能运行时、技能说明和 `tools/` 改动独立保留。

### 同切片修复与清理

- 原先同一表情的并发请求都能通过去重检查，导致重复发送。现在同会话、
  同指纹的发送中请求会返回 `delivery_in_progress`；失败或异常释放占位，
  允许后续重试。显式设为零的间隔继续允许重复发送。
- 原先慢请求结束后会覆盖更新的表情记录。现在通过请求标记判断是否仍为
  最新请求，旧结果不能改写新状态；不会在网络发送期间持有状态锁。
- 冷却间隔原先从发起请求时计时，慢发送完成时可能已经过期。现在从成功
  完成时开始计时。并发、重复和慢发送回归同时覆盖图片和 mface；使用
  拆分前网关运行，在六个子用例中复现原缺陷。
- 流式回复原先在 mface 有意跳过后仍发送图片回退。现在去重、发送中、
  群表情禁用和文件投递回合的跳过结果会保留；实际不可用或失败仍可回退。
- 会话状态计数在配置锁内取快照；配置保存统一走一个实现，删除六个内部
  重复保存方法，入口旧名称继续兼容。小程序存储只初始化一次，删除每次
  调用无效分配的新对象以及已由构造器负责的重复缓存初始化。
