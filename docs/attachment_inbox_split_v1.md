# 附件工作台拆分 v1

## 范围与兼容边界

本轮承接 `attachment_ingest_split_v1.md`，拆分 `companion_v01/attachment_inbox.py` 的正文读取、上下文渲染和会话材料管理。原入口有 2,344 行、81 个方法和 10 个模块级常量/日志对象。

- 保留 `AttachmentInboxService` 的导入位置、构造参数、原方法签名及常量导出。
- 工作台材料继续由当前用户和会话解析，受管文件和 `workspace:` 来源沿用现有路径校验。
- 保留 Focus、Manifest、自动聚焦、材料时间线、私有来源状态和清理语义。
- 不修改其他任务正在进行的共享记忆、关怀、QQ、模型协议和前端改动。

计划按三个切片本地提交：读取与分页、上下文渲染、材料管理。

## 切片 1：正文读取与分页

已抽出安全路径解析、范围选择、文本/表格/文档读取、正文展开 API 和分页。

直接相关的修复：

1. 文本前缀从 `read_bytes()[:limit]` 改为限量读取；指定深处行时分块扫描并只收集目标范围，不再受开头字节预算限制。
2. 字节预算落在 UTF-8 字符中间时保留解码器的未完成尾部，避免把正常中文误识别成另一种编码。
3. CSV 正文取消前 500 行硬截断，指定范围按 CSV 记录读取，并保留带引号字段中的换行。
4. 显式行范围、页范围及 Word 表格、Excel 指定行不再被静默缩短。正文仍受字符提取预算限制。
5. 同一 section 的续页复用实例内快照，避免重复提取、解码及构造整个正文回执。
6. 提取时多检查一个字符，区分恰好 4M 字符的完整正文和超过窗口的正文；预览回退也保留不完整状态。窗口耗尽时不声称已读全文。

分页约定：

- 保留原 `p1.as` cursor 格式、目标/section/偏移/正文指纹字段及首/续页预算。
- 每次读取先重新确认当前会话材料仍可用，再以 64 KiB 块校验源文件内容；即使大小、mtime 相同，也能发现内容变化。
- 每实例快照最多 8 个条目、总计 8M 字符、有效期 300 秒；缓存不写磁盘，不进入提示词、日志或游标。
- 缓存过期、容量淘汰或服务重新创建后，重新提取并验证正文指纹，现有有效 cursor 可以继续。
- 4M 是单个 section 的提取窗口。窗口外内容需指定更精确的行、页或 sheet 范围；本轮没有新增自动遍历完整超大附件的行为。
- 续页仍需流式校验整个源文件，因此减少的是重复解析与正文分配；不是跳过文件变化检测。
- 注入的旧附件服务仅实现 `read_section` 时，工具处理器保留原分页适配路径。

验证：

- 修改前：162 项相关测试，161 通过，1 跳过。
- 新增测试先在旧实现上复现五个缺陷：全文件读入、范围缩短、深处行遗漏、CSV 后半部分不可读、续页重复提取。
- 切片 1：187 项，186 通过，1 跳过；覆盖真实文本分页、GB18030、UTF-8 边界、CSV 换行、实际 Excel/Word、PDF 页范围适配、4M 边界、游标隔离、源文件变化/删除/清理、缓存淘汰和重新创建。
- 原 81 个方法签名和 10 个导出定义经 AST 对照；改动仅限构造缓存及上述读取链。
- Python 编译与 `git diff --check` 通过。
- 跳过项是现有工作区符号链接测试，当前环境不能创建该链接；没有跳过本轮分页测试。

没有启动真实桌宠、QQ、外网服务或浏览器验收。该切片是后端读取和工具回执变更，PDF 页范围测试使用解析器适配桩，不能代替所有实际 PDF 的解析验收。

## 切片 2：上下文渲染

将工作台正文/活动索引、Focus 预算、图片描述、媒体与 Manifest 卡片、操作回执和标签格式化分开。材料内容和状态仍来自原服务与存储层，渲染模块不访问桌面界面。

新增回归测试先复现并修复两处直接相关问题：

- Focus 中未能按预算展开的材料现在优先进入 Manifest，保留 handle 和识别元数据，不把正文预览混入 Manifest，也不修改实际 Focus 选择。
- 短预览即使远未用尽字符预算，也会根据 `preview_is_truncated` 明确提示这里只展开了预览，避免把预览误当成原文件全文。

147 项附件/读取/存储相关测试中 146 通过、1 项为同一符号链接环境跳过。AST 对照、编译与差异检查通过。

这一阶段的桌宠集成测试曾被工作区另一任务正在修改的 `engine_services/desktop_care_pet.py` 中 `desktop_care_scope` 导入错误阻挡；未修改该任务文件，最终切片会重新检查集成状态。

## 切片 3：材料管理与最终边界检查

将状态/时间线、聚焦与查看、清理与托管删除、目标匹配、序号选择和原生图片输入分别迁出。原入口最终为 **86 行**，只保留兼容导出、静态组合和实例初始化。20 个实现模块中最大的是 `matching.py`，265 行；没有从实现模块反向导入入口或运行时注入方法。

新增测试先复现并修复：

- 精确 handle/ID 与按 ID 等待不再因为最近材料列表的数量上限漏掉旧记录。仍通过存储层的用户/会话和有效状态过滤，已清理对象不可续读。
- 文件已不存在时，只有通过托管根目录路径校验后才报告“本来已不存在”；目录、外部工作区、越界路径仍保留。清理同步移除对应正文缓存。
- Excel 指定 sheet 可展开超过预览行数的正文和第 40 列之后的值；`全文` 按预算遍历所有 sheet。sheet 名匹配优先于名字内的数字序号。
- PDF 默认前五页是部分窗口，越界页返回不可展开状态，不再悄悄替换为末页；没有文本层时不把页标题当成成功读取正文。
- 请求原文件中不存在的范围，或缺失原文件而缓存预览没有目标行时，不替换成另一段开头预览。

验证汇总：

- 附件主回归 200 项：199 通过，1 为现有符号链接环境跳过。
- 生成文件交付、执行资源、图像材料、可选媒体绑定等扩展回归 67 项全部通过。
- 浏览器下载/附件注册与 QQ 路由 6 项全部通过。
- 合计 **273 项有效检查，272 通过、1 跳过，无功能失败**；阶段 2 暂时被阻挡的 42 项桌宠/QQ/工作区集成复查已通过。
- 原 81 个方法的参数、返回注解和装饰器，以及 10 个原常量/日志导出定义经 AST 对照保留。方法归属、依赖可达性与无循环由结构检查覆盖。
- Python 编译与工作区/暂存差异检查通过。

PDF 范围、越界和无文本层测试使用解析器适配桩；Word、Excel、CSV、长文本及分页使用真实临时文件。未启动真实桌宠/QQ/外网服务，也未验证所有实际 PDF 的第三方解析行为。续页仍流式校验源文件；Word/PDF 的结构加载成本仍取决于第三方解析器。自然语言相对序号选择沿用原有近期窗口，精确 handle/ID 的查询已不受该窗口限制。
