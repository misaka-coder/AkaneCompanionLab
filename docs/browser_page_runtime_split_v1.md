## 所有权与调用链

工具处理器继续通过原入口选择会话执行器并执行；控制授权仍由现有工具处理器和执行器代理负责。实现模块通过静态 mixin 组合共享一个 runner 实例，所有状态由 `runner.py` 初始化。

每个用户/会话拥有独立的页面、浏览器上下文、观察和下载跟踪。页面动作和对象关闭都交给该 runner 的单线程执行器，Playwright 同步 API 的线程归属保持一致。能力探测使用独立线程，兼容异步 HTTP 调用方。

原有 `browser_page_observation.py` 和 `browser_page_download.py` 继续分别管理观察证据和下载附件登记。它们是独立服务；本轮直接复用。

## 保留的行为约定

- 页面读取先捕获某一时刻的快照。首段使用 `paged_reading` 的既有字符/行数预算，续读取同一个不可变快照，保持用户、会话和来源绑定。
- 浏览器自动恢复只发生在安全读取动作尚未开始且浏览器已关闭时。已执行或执行状态未知的控制动作保持原回执，由后续观察确认页面状态。
- 点击成功后观察失败，返回已执行、观察失败及 `snapshot` 建议。对话框策略在一次动作结束时清空。
- 旧观察、变化的 DOM、变化的坐标像素或密码遮罩区域，均在控制之前验证。采集过程中页面变化时，观察标记为不稳定并撤销可操作的视觉证据。
- 短批次遇到失败、对话框、新页面、新文档或不完整观察时停止，保留已经完成的步骤回执。
- 显式允许私网的配置保持有效；公开链接检查继续执行。

## 同轮修复

1. 候选链接和新页面接管检查完整解析 URL，拒绝嵌入用户名/密码及无效端口。畸形 IPv6 返回不可用链接，避免一个错误链接中断整次页面观察。
2. 元素摘要中的 href 复用同一检查，保留元素标签文字，省略不合格链接；候选过滤保留原 DOM 索引。
3. 会话管理器关闭时，只限制调用方的等待时间。等待结束后，排队中的 runner 清理仍继续执行；重复关闭不会取消这些任务。

新增边界用例先在修复前复现失败，再验证修复结果。凭据用例只使用合成字符串。
