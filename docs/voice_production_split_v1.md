## 初始化与重试

构造过程登记已创建的执行器和私聊租约。存储构造异常、投影/命令回执恢复失败、候选清理失败、历史命令或生成状态恢复失败，都在服务状态锁外关闭已构造对象；一个对象关闭异常不会跳过其他对象。未完成清理继续由服务持有，再次解析该会话时先补做清理，仍未完成则返回 `voice_runtime_initialization_cleanup_pending`，不另造一个运行时。

Host 和执行器缓存改为在所有恢复步骤及恢复任务启动成功后一起登记。启动失败不会把失败的 Host 缓存成下次可用的成功结果。若启动已提交了部分后台工作，失败回收先停止相关执行器，并确认该会话的思考 lane 空闲后才允许重新初始化；不让旧任务与新 Host 同时写同一份历史。

初始化入口在实际装配前重新检查关闭状态，轮次创建在登记及返回成功时重新检查。规范会话身份的编码/类型错误在创建存储前返回 `voice_realtime_identity_invalid`。恢复顺序、原 journal/Host receipt/制品格式、TTS 来源核验和 `plugin_tts_service_execution_plan_20260911.md` §4.4 的未知结果不重合成/孤立播放不重播规则保持原样。

## 关闭与异步开启

关闭先停止新请求，再把需要清理的对象移交给本服务持有的回收记录。关闭序列有独立互斥：并发或重入的关闭返回 `voice_runtime_shutdown_in_progress`，不会提前报告已停止。业务状态仍使用原服务锁，各对象的回收和 worker 等待在该状态锁外执行。

播放通道关闭结果参与最终状态，拒绝或异常会保留稳定原因和待处理对象。执行器异常不阻止其余对象和后台 worker 回收。正在运行的 worker、未完成的播放收尾、尚在开启/回收的 ASR 会话或私聊租约关闭失败，都会得到 `degraded`；再次关闭补做未完成项，已完成的对象不重复回收。只有通道、执行器、后台工作和 ASR 开启均已收口，才释放私聊租约并报告 `stopped`。

ASR 开启在等待 provider 返回时计入正在开启的请求。服务关闭后晚返回的 session 会先取消，不能返回可用通话。取消异常或拒绝转换为 `asr_provider_cancel_failed`，该 session 继续由服务持有；后续关闭在它原来的事件循环中重试取消，完成后才移除。原事件循环不可用或取消仍未确认时保留未完成状态，不把调度取消等同于取消成功。正常多轮通话仍复用一个 provider session。

## 会话与通道归属

同一主人私聊会话的并发请求从实际共享 Host 获取租约，避免初始化窗口里临时创建的另一份租约进入轮次上下文。通话身份核对加入 Host 签发的 `conversation_ref`；实时协议创建后续轮次时沿用初始通话请求，只替换轮次和音频流 ID，因此正常多轮调用保持兼容。

活动播放轮次重复登记返回冲突，不覆盖原通道。终态回调携带原通道对象，仅在服务登记仍指向该对象时注销，旧回调不能移除替换后的通道。轮次构造失败会关闭并注销自己尚未使用的通道；失败清理没有确认成功时继续保留资源供服务关闭重试。关闭造成的轮次登记失败返回服务不可用，避免误报用户输入无效。
