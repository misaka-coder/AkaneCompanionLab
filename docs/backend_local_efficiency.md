# 本地请求准备：最新状态记录索引

每轮提示构建都会读取上一条 `eval_turns`，恢复人物和场景状态。此前两个最新记录查询只有 `trace_id` 主键可用，SQLite 扫描整张表并建立临时排序结构。随着历史积累，这项开销会持续增长。

`MemoryStore._init_db` 在兼容字段迁移后创建两个普通索引：

- `idx_eval_session_time(session_id, created_at)`：按会话读取最新记录。
- `idx_eval_profile_session_time(profile_user_id, session_id, created_at)`：按用户和会话读取最新记录。

时间列采用升序。SQLite 的普通索引还按隐含 `rowid` 升序排列相同键；反向遍历就能满足原查询的 `created_at DESC, rowid DESC`，保留同一秒内的写入顺序，包括 `INSERT OR REPLACE` 后的新顺序。查询和返回字段均保持原实现。

常规最新记录查询由全表扫描变为 B 树定位。指定角色时，仍按原条件过滤当前会话内的候选记录：查找成本约为 `O(log N + k)`，其中 `k` 是找到对应角色前跳过的候选数。这里没有为每种筛选组合增加额外索引，避免扩大每轮写入的维护成本。

索引创建幂等，旧记录不重写，不改变事务提交和向量索引故障回退。首次启动会创建索引；代码回滚后仍可读取同一个数据库，留下的普通索引也不改变查询结果。

## 短文本计数与请求审计复用

`estimate_prompt_tokens` 保留原有 Unicode 范围、舍入和输入转字符串的规则。相同短文本的计数在进程内复用，最多保留 1024 个不超过 4096 字符的条目；完整长提示和大型工具 schema 直接计数，不进入缓存。缓存只返回整数，不替代历史读取、授权核验、模型请求或服务商的提示缓存。

请求审计此前分别对 `native_tool_schema` 和 `request_field_fingerprints.tools` 序列化并计数同一批工具。两者引用同一个工具列表时，现在复用一次计算的数字与摘要，并复制成各自的审计条目；不同列表继续分别审计。后续工具变化会重新计算，原有记录保持独立。

隔离对照使用真实请求构建器、350 条合成历史和 63 个工具定义，不访问模型网络、不写生产记忆。两种模型路径各进行 60 组交替顺序对照，排除前两组预热后：

| 请求构建路径 | 改动前中位数 | 改动后中位数 |
|---|---:|---:|
| Gemini，OpenAI 兼容协议 | 7.918 ms | 5.434 ms |
| DeepSeek，OpenAI 兼容协议 | 7.234 ms | 4.864 ms |

120 组完整请求逐项相等；审计除生成时间戳外逐项相等。40 项计数、缓存边界、并发、审计、缓存用量和流式响应检查通过。以上是请求打包这一段的合成数据测量，收益约 2.4 ms，不代表完整后端请求或服务商响应时间。历史、记忆、提示词内容、工具能力及音频播放策略保持原有语义。
