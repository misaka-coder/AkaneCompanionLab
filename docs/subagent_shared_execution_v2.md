# 子代理共享执行基座 V2

状态：实施中，尚未部署。接续 `subagent_runtime_v1.md`，本文件是能力扩展与调度改造的执行单；V1 的 Job、权限主体和独立记忆边界保持有效。

## 目标与边界

从父任务当时实际可用的能力出发，再按任务子代理的职责过滤。父子使用同一 ToolSpec、Resolver、Broker、审批和执行器；不另建编程工具白名单或权限系统。子代理负责工作和报告，父代理负责面向用户交付。

保留文件、Shell、搜索、浏览器、产物及适用的 Skill/MCP/插件能力。过滤伴侣记忆、人设、主会话投递/表现控制和递归派发。会改变父会话坐标的操作在拥有独立坐标语义之前不开放，不能让子代理悄悄切换父项目。筛选同时约束 schema、延迟加载与执行，不只隐藏工具名。

## 实施切片

1. **能力继承**：移除 `_CODING_TOOLS`，集中表达任务职责的排除规则。从父选择取交集，保持现有权限检查；验证新普通能力无需修改子代理名单即可继承。
2. **共享批调度**：父子调用同一调度函数。连续、已声明只读的调用可并行；写入和未分类调用作为顺序屏障。每个调用保留独立结果、异常与取消回执；记录真实开始、结束和耗时，不能用批次落库时间冒充执行耗时。
3. **长任务生命周期**：复用 `exec_run/status/cancel` 和 Host Jobs，不增加 child 专属同义工具。ID 表示接收而非完成；核对未完成任务、取消、重启和正确 child 的续跑归属。当前 child 内普通 long_task 仍同步运行，不宣称已支持异步唤醒 child。
4. **产物交接**：修复现有登记对已授权外部项目绝对 cwd 的不一致；父子共用登记和所有权校验。模型选择最终产物，父代理使用同一真实句柄，不重写报告来换取句柄。
5. **提示与缓存**：只提供任务、执行坐标、能力用法、ID 和交付语义。共享工具说明，不携带伴侣历史，不逐轮追加能力快照。
6. **验收和部署**：逐片测试、聚焦提交；完成后检查运行版本，再进行真实 QQ 任务和交付验收。单测不是云端、桌宠或模型效果验收。

## 验收清单

- 父级新能力自动继承；过滤在 schema、延迟调用和最终 dispatch 一致，父选择不被修改。
- 单 child 的两个只读调用真实重叠；读写混合不越过顺序屏障；异常不丢其它回执。
- 多 child 并行与单 child 工具并行分别验证。
- 长命令返回 ID 后能做独立工作并读取结果；未完成、取消和重启如实结算。
- 完成事件不误唤醒父角色或其它 child，权限不扩大。
- child 文件到父验证、发送的哈希保持一致；越权路径仍拒绝。
- 普通工具轮 system/schema 稳定，历史工具调用与结果完整配对。

## 不在本轮实现

递归派发、多种专职角色、完整驻留子代理系统、网页正文清洗。确实需要扩展生命周期时先修公共契约，不用提示词模拟能力。

## 进度

- 已核查：固定白名单限制了继承；child 批调用仍串行；父批调度把所有读取移到写入之前，且未知 metadata 默认为并行。
- 已实现并本地验证：切片 1、2 的能力组合与共享调度。`subagent_policy.py` 集中排除父会话职责；`tool_batch.py` 为父子唯一批调度器，保持每次调用的结果配对和上下文变量；取消后跳过的调用也有回执，已完成产物保留。
- 延迟 MCP 名称复用普通 dispatch 解析器，保留父级上限；不把 deferred schema 全部塞进 child 请求。元数据解析失败明确拒绝子任务准入，不当作已授权。
- 诊断记录 `scope_id/call_id/started_at/finished_at/duration_ms`，不记录参数、路径或密钥，不进入模型反馈；计时不再依赖批次写入时间。日志失败不影响已执行结果。
- 验证：213 项扩大回归通过（subagent、Host Jobs、公共工具、项目工作区、主回合、插件 hooks）；最后的计时回执隔离改动又通过 33 项定向回归；语法与 `git diff --check` 通过。测试使用真实宿主编排和 MemCore、可控模型/工具夹具，不是外部模型或群聊实测。
- 基线债务：扩大到 `test_capability_adapter_mcp_orchestration` 时，两条仍写入旧 `mcp` 权限名的测试失败；在内存加载 HEAD 原版 `tool_rounds.py` 复跑同样失败。本轮没有修改权限兼容逻辑，也不将这两条计入通过数。
- 待实施：切片 3、4、5 的完整生命周期/产物/提示验收，以及切片 6 的部署和用户表现验收。child 内普通 long_task 仍同步执行，Shell 的已有 ID 仍靠状态查询；不承诺异步 child 唤醒已接通。父子新工具范围的端到端执行、运行中安装后使用新能力也尚未逐项实测。
