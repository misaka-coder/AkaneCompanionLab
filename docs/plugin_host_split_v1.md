# PluginHost 拆分与定位

`companion_v01/plugin_host.py` 从 2322 行收为 125 行，保留对外入口和构造签名。实现位于 `companion_v01/plugin_host_runtime/`，共 25 个实现模块，最长的注册器为 301 行。

## 运行边界

- 生产调用仍由 `plugin_generation_worker.py` 创建宿主，`PluginGenerationRuntime` 负责进程换代。宿主内部拆分没有建立另一套进程管理或插件目录。
- 公共导入仍为 `PluginHost`、`PluginStatus` 和 `PluginContributionSnapshot`；原有注册模型和辅助函数继续从旧入口兼容导入。105 个原有方法与辅助函数的签名、15 个常量及公共导出保持一致。
- 创建宿主不发现或加载插件。安装产物审计、工厂加载、同步注册、描述符校验和健康检查在启动阶段执行。
- 注入的服务与权限在注册前确定，注册完成后封存。服务绑定仅允许在宿主的 `created` 状态执行。
- `active` 和 `degraded` 可以处理已注册贡献；准备、停止或不可用状态拒绝新调用。服务缺失、健康失败和写入失败继续返回真实原因。

## 本轮修复

1. 取消单个插件激活时，关闭该插件已暂存的适配器；取消后续插件或已准备插件的激活时，也关闭前面已接受的注册资源。取消继续传回调用方。
2. 启动和停止清理使用现有 SDK 的排空机制。重复取消不会中断关闭流程；适配器的逆序关闭、身份去重和关闭超时仍然保留。
3. 准备阶段部分失败后直接重试，先清理上一轮资源，再创建新一轮状态，避免覆盖注册表后遗留适配器。
4. 后台任务完成回调核对当前任务和控制器的身份。旧服务在关闭宽限期后退出，不能覆盖重启后的服务状态；任务异常仍被读取，公开状态只保存原因码。
5. 资源范围创建或初始化失败时，也会释放调用计数并关闭范围，返回明确错误，避免默认无限等待的停止流程被遗留计数拖住。
6. 事件声明的后续回合需要继续使用范围时，正常交给 broker 关闭；初始化失败则立即清理。初始化仍在切换当前范围之前执行，保留父调用已捕获的来源和回合信息。
7. 补齐事件和任务服务的创建阶段绑定约束，避免注册时捕获的旧端口与调用时的新提供者不一致。
8. 删除重复的后台调用工厂初始化，修正宿主 `restart` 注释中关于进程换代尚未实现的过时说明。
