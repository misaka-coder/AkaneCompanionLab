# QQ 指令、帮助与专属状态图

群聊先用 QQ 的真实 @ 选中目标 Bot，再发送指令；私聊直接发送。昵称文字不能代替 @。

## 帮助入口

- `/help`：分类首页，优先发送图片。
- `/help 群聊`：查看某个分类。
- `/help 插件 2`：较多插件指令的第二页。
- `/help 回复 文字`：发送可复制的文字版。

分类根据当前会话、主人身份、养成功能和已注册插件生成。未启用的功能不展示；实际权限仍由各指令处理器检查。图片字体、素材或投递不可用时，自动回退文字并保留失败原因。

`/` 指令的图片与文字回复直接发送，不附带引用框，给卡片保留展示空间；普通聊天继续沿用既有引用策略。

## 正式指令

| 分类 | 指令与示例 |
| --- | --- |
| 模型 | `/模型`、`/模型 列表`、`/模型 <名称或序号>`、`/模型 默认`；`/思考 开`、`/思考 关` |
| 角色 | `/角色`、`/角色 列表`、`/角色 <ID或名称>`、`/角色 默认`、`/角色 内置`；`/服装 [列表\|ID\|默认]`；附带 QQ 商城表情后发送 `/表情包 happy` |
| 回复 | `/回复`、`/回复 文字`、`/回复 语音`、`/回复 双发`、`/回复 默认` |
| 群聊 | `/搭话 [关闭\|活跃\|自然]`、`/识图 [开\|关]`、`/表情 [开\|关]`、`/私人记忆 [开\|关\|状态]` |
| 养成 | `/签到`、`/养成`、`/商店`、`/购买 三色团子 ×2`、`/背包`、`/投喂 <物品> [×数量]`、`/供奉 [物品\|状态]`、`/抽签`、`/赛钱 10`、`/赛钱箱`、`/额度` |
| 材料 | `/材料`、`/材料 清理 [目标]`、`/材料 删除原文件 [目标]`、`/停止` |
| 权限 | `/权限 [本机\|扩展\|全部] [开\|询问\|关]`、`/审批`、`/批准 [编号]`、`/拒绝 [编号]` |
| 插件 | `/help 插件` 展示当前注册的插件指令，参数由插件定义 |

方括号中的参数可省略，一般用于查看当前状态。材料目标可填“最近”、名称或句柄；省略时清理当前会话全部材料。“清理”保留原文件，“删除原文件”按既有材料管理规则删除托管文件。

群设置修改继续要求群主、管理员或主人；私人记忆接收开关仅主人可修改。模型、思考和权限继续使用既有主人限制。回复方式和模型选择沿用现有会话作用域。

## 主人私人交流写入群记忆

桌面控制中心 → **系统与诊断 → 记忆与 QQ** 可以开启“桌宠与主人 QQ 私聊共用记忆”和“将主人私人交流写入指定群”，并直接选择接收群。总开关对应 `OWNER_PRIVATE_SESSION_SHARED`、`OWNER_PRIVATE_GROUP_MEMORY_MIRROR`，保存后显示当前运行值与待重启状态；重启后端后才生效。受管理的本地桌面支持“重启后端并应用”：等待同一后端中的对话结束、完成收尾，再由既有启动器重启；新进程和设置应用确认后才显示成功。远程连接或无受管理启动器时，请在后端所在设备重启。

接收群开关按 Bot 保存，和 QQ 指令使用同一份状态，保存后立即生效；不向群发送通知。群列表优先使用 QQ 群名，离线时仍显示可信已有群及已开启群；可按群名或群号筛选。只读取群元数据，不读取对话正文，也不在模型请求中刷新列表。已选择但当前角色尚无群记忆的群，会在该角色形成可信群会话后接收。

各群默认关闭，仍可由主人在希望接收的群发送 `@目标Bot /私人记忆 开`。`/私人记忆` 或 `/私人记忆 状态` 查看设置，主人还能看到待写入数量、重试数量和安全的错误类型。`/私人记忆 关` 停止新复制并使旧待写入失效，已经形成的群记忆保留。关闭后重新开启只接收新完成的交流，不补旧历史。

复制范围是主人 QQ 私聊与已绑定桌宠的新输入、同轮追加输入及模型最终回复，限同 Bot、同角色的可信已有群会话。仅工具操作、静默、取消和临时语音候选不生成副本；工具调用、结果、私人工作台和物理文件仍留在源会话。原私人材料编号不等于本群同号材料，原工具证据继续按既有授权显式选择 `conversation="master"` 回读。

完整交流按写入顺序追加到群末尾，保留原事件时间、来源和主人身份。群正忙时等当前任务结束，私人回复不等待群模型。复制不会发群消息、启动模型或重放养成与工具副作用。群按自身窗口压缩这些副本，私人摘要和长期记忆不搬运，也不接收群消息。

待写入记录持久化，失败按群独立重试；重启恢复使用同一去重身份。宿主总开关暂停时保留待写入，重新启用仍需复核主人、群资格和该群接收配置。启用后各群会增加少量记录、索引和后续压缩成本；频繁私人交流可能让群更早触发正常压缩。

## 单次角色对话与售货员

`/<角色包ID> 正文` 临时找已安装角色说这一句话，例如 `/reimu 今天过得怎么样`；ID 见 `/角色 列表`。下一条普通消息仍交给默认角色。`/角色 reimu` 继续表示持久切换。内置和插件指令优先，冲突的定向入口不会抢占它们；正文不递归执行宿主指令。

`/售货员 正文` 使用同一个聊天模型和分句投递流程，以文字回复。它服务接收消息时的默认角色；临时找灵梦不会改变下一次售货员的服务对象。要管理灵梦商店，先 `/角色 reimu`。当前回复模式和桌宠角色选择不变。

主人可通过自然语言新增、改名、调价、调整效果、修改介绍或下架自定义商品，例如 `/售货员 上架草莓蛋糕，售价12，饱腹+22、精力+6、好感+6，介绍写新鲜草莓和轻盈奶油`。普通用户可交流和查看，写权限依真实 QQ 发言人核验；未配置主人时不开放写入。售价在桌宠对应金币，在 QQ 对应兑换额度。

商品直接保存到原有角色配置，下一次 `/商店` 图片和文字会读取新内容。实际变更成功后，售货员会在服务角色当前 QQ 会话的原始时间线末尾追加一条简短商品事件，下次和该角色聊天就能读到，不额外请求模型。通知写入失败会如实报告，不影响已经保存的商品。

各角色保存自己的对话与工具轨迹；售货员工作记忆按所服务角色分别保存。群聊同样需要真实 @ 目标 Bot。请求正在处理时，另一个对象的消息排入下一轮，同一对象仍可追加输入；队列里的对象和服务目标不会随之后的默认角色切换而改变。

辅助定义独立放在 `companion_v01/assets/dialogue_services/*.json`，包含 `id`、`name`、`command`、`persona`、`tools`，更新后重启后端生效。它们复用现有 Engine、MemCore 和工具权限，不进入正式角色包列表。模型只能发现和执行该辅助定义允许的能力。

## 专属状态图

`/养成` 优先返回请求者的状态图，包含好感度、金币、兑换额度、连续签到，以及当前角色的饱腹度和精力。群聊依然需要真实 @ 目标 Bot。

标题使用当前消息发言人的显示名：群聊沿用消息接入层的显示名解析，优先群名片，没有群名片则用 QQ 昵称；私聊使用 QQ 昵称，不写死为示例中的“小伙伴”。昵称或群名片变更后，下次查询会更新图片；缺少可用显示名时暂用 QQ 号码。

数据直接来自现有 `CareRuntimeStore.snapshot_for_client`：金币、兑换额度、签到和背包按 QQ 用户和角色共享；好感按会话中的用户分别保存，饱腹与精力按当前会话保存。主人两端绑定启用后，桌宠与主人 QQ 私聊使用同一份私人身体、关系和 QQ 账户，其余群聊和私聊互不影响。图中的“饱腹度”对应已有 `hunger` 字段，值越大越吃饱。

关闭养成功能时返回明确的未启用状态；数据、字体、底图或图片投递失败时回退真实文字状态，不填造数值。卡片缓存包含用户、角色和展示数值，状态变化后生成新图，不向模型或日志输出整份养成快照。

此查询不调用 LLM 或 TTS。普通签到、投喂、供奉等互动沿用现有处理流程。

## 缓存统计图

`/缓存` 查看当前 QQ 会话、当前角色在北京时间当天的缓存图；`/缓存 昨天` 或 `/缓存 2026-10-01` 查看指定日期。与模型设置一样由主人查看，群聊须真实 @ 目标 Bot。

一张图包含当天命中率、有效请求数、未报告数、每小时趋势及各模型统计。按有效样本的缓存输入 token 总量除以输入 token 总量计算，不平均各轮百分比；明确报告 0 的请求计入，缺报和无效 usage 单列，不画成 0%。图中 95% 线只是参考目标，不代表实际已经达标。

模型明细使用实际请求的模型名称；上游返回的别名保留在审计中。已有带会话归属的记录，只有原请求审计能唯一对应模型时才恢复请求名，否则保留上游名称。模型列表和编号切换统一按 QQ 默认模型及其路由分组排序，会话临时切换不再改变编号顺序。

调用本地数字统计，不请求模型或读取聊天正文。统计从新版运行后产生的请求开始，完整 prompt 审计开关关闭也可收集；旧记录没有可信会话标签时不猜测归属。无数据时显示空态，图卡失败回退文字。目录 `logs/cache_usage` 仅存模型名、会话摘要标识和 token 数值，按 UTC 日分文件，查询换算为北京时间。

一轮工具调用中的多次模型请求分别计数，一次流式请求的累计 usage 只记一次，按请求结束记录的时间归入日期和小时。缓存字段缺失、整份 usage 缺失或不合理的 token 值标为未报告。Anthropic 原生接口先将缓存读取、缓存写入与未缓存输入相加作为输入总量，依据其[官方统计口径](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#tracking-cache-performance)归一后再计算比例。

## 商店与背包

售货员实际上架、修改或下架商品后，会自动发送一张单品确认图，注明服务角色的商店名、商品介绍、售价和效果。无实际变化或重复调用不重复发图；图片不可用时发文字确认，商品编辑结果与图片交付状态分别保留。

角色包可在 `character.json` 的 `dialogue_services.shopkeeper` 中选配 `name` 和 `persona`，入口仍是 `/售货员`，服务当前主角色。省略配置使用通用售货员；不扩展工具权限，也不创建售货员自己的商店。`care.care_preferences.favorite_items/disliked_items` 及喜欢／不喜欢标签作为模型的角色背景，用于自然回应投喂和礼物。字段说明见 `desktop_pet_creator_kit/docs/character_pack_guide.md`。

`/商店 [页码] [文字]`、`/背包 [页码] [文字]` 默认返回图片，每页最多 5 种物品，图片随内容延长。可用 `/商店 2` 翻页，或 `/商店 2 文字` 获取完整说明和可复制的文字；背包同样支持。越界页码返回明确提示，空背包仍有真实的空态图片。长说明在图中显示摘要，文字版保留完整说明。

QQ 沿用桌宠商品编辑器保存的当前角色商品配置。在桌宠商店新增或编辑商品，并勾选“也在 QQ 商店上架”，QQ 下次查询和购买会读取新名称、售价、说明与效果，无需重启。兼容角色包的 `shop_items` / `shopItems`、`usable_in` / `usableIn` 字段；未勾选的商品不会出现在 QQ 商店，也不能在 QQ 购买。原有 QQ 特殊物品和节日商品继续可用。

商品定义共享：桌宠使用金币购买，QQ 使用同一售价的兑换额度，`/赛钱 <金币数>` 可兑换额度。QQ 背包和余额继续按 QQ 用户、角色保存。背包优先显示当前商品名和当前投喂效果，商品下架或删除后，已购买的 QQ 物品仍保留；删除后使用购买时保存的信息。同名商品会附上 ID，可用 `/购买 <ID>`、`/投喂 <ID>` 精确选择。

QQ `/购买` 成功后发送紧凑的图片回执：用户显示名、商品配图、购买数量、背包数量、消耗与剩余兑换额度，以及投喂指令。数据来自本次结算，不额外调用模型；图片失败回退文字确认，不重复购买。余额不足等失败保持文字提示。

商品配图可在桌宠商店的“管理商品 → 调整食物／新增商品”中上传、预览或恢复默认。支持静态 PNG、JPG、WebP，最大 4 MB、1600 万像素；后端校验并缩至最长边 768px，去除原始元数据后原子保存到角色包 `assets/shop/`。商品的 `image` 保存包内相对路径，`art_kind` 可选 `auto/dessert/drink/meal/gift`，不改变商品效果或玩法分类。默认插画同时提供 SVG 和 PNG：桌宠使用矢量版，QQ 使用对应 PNG。QQ 商店、背包、商品变更回执与桌宠共用商品配图；QQ 新购入物品保留图片引用，商品下架后已有背包仍可展示。更换图片不删除旧文件。图片缺失时使用分类插画；极端密集的长名称列表优先保留完整文字。配图不会发给聊天模型，也不会触发图片生成。

投喂成功后，当前商品介绍会作为本轮互动信息传给聊天模型，和实际效果、投喂后状态一起供角色自然回应。桌宠和房间投喂也带上介绍；没有介绍时省略此行。QQ 新购买或获得的物品同时在背包保存介绍，商品已下架或删除时使用这份快照；已有旧背包数据不补造介绍。在售商品优先读取最新介绍。此信息追加在本轮上下文，不增加模型请求，也不改变稳定提示前缀和数值结算。

商店和背包图片共用状态卡的底图、字体和安全缓存，不调用生图、LLM 或 TTS。查询只传递展示字段；图片失败回退当前页的真实文字并保留失败原因。购买仍使用原有事务与重复事件拦截，卡片不会替代购买或投喂的实际结果。

## 迁移与实现

只保留以上正式指令，不兼容旧的自然语言口令、昵称前缀或英文别名。全角 `／` 视为输入格式，`/HELP` 可识别。未命中正式指令、已安装角色或辅助入口的 `/` 指令，以及错误参数，在本地返回简短用法，不进入模型推理。

`companion_v01/qq_commands.py` 同时提供解析和帮助元数据，网关与路由共同使用。帮助图由 `qq_help_cards.py` 在本地绘制；专属状态图由 `qq_care_cards.py` 绘制；商店和背包图由 `qq_commerce_cards.py` 绘制；字体、底图与原子缓存共用 `qq_card_artwork.py`。运行时不调用生图模型。塞西莉亚使用用户选定的轻笔书签风格，其他角色使用通用样式。

帮助目录和分类以无框文字排版，养成指令可在一张长图中完整展示；过多插件指令仍分页。固定页眉和页脚保留人物、装饰比例，只有中间纸面按内容延展。

## 开发者入口与新增指令指南

开发者修改或新增一条 QQ 宿主命令时，遵循单向清晰调用链路：

1. **语法定义与帮助元数据**：
   - 在 `companion_v01/qq_commands.py` 的 `COMMANDS` 元组中声明 `QQCommandDefinition(name, category, usage, description, kind, ...)`。
   - `resolve_qq_command()` 负责参数解析并产出 `QQCommandResolution(payload=...)`。注意 `kind`（如 `selector`、`simple`）仅为参数语法形态，**不是**业务路由键。
2. **事件分派（Dispatch）**：
   - 事件层建立 `command_context` 后解析一次，将结果传给两个命令入口；`None` 也直接复用，不再重新解析。消息准入层和停止协调器的独立分类仍按原流程工作。
   - 在 `companion_v01/qq_command_handlers.py` 的 `QQCommandHandler.handle()` 中，通过 `match res.definition.name:` 精确分派到对应领域私有处理方法（如 `_handle_reply_mode`、`_handle_character` 等），并直接传递解析后的 `command=payload` 字典副本。
   - 前置检查与错误参数（如 `/help`、`/缓存`、语法错误）在 `handle_early()` 中完成，不进入后续分派。
3. **业务实现与出口模式**：
   - **本地直接响应**：返回包含 `JSONResponse` 的 `QQCommandOutcome(response=...)`，如 `/回复`、`/角色 列表`。
   - 已选中的本地业务缺少结果时，命令层返回实际失败，不交给模型推理；网关层的文本入口仍可供独立业务调用。
   - **动作已完成并继续模型回合**：返回 `outcome`，并在 `outcome.action_note` 和 `outcome.message_override` 中填入动作说明，由后续媒体与模型流水线处理（例如 `/服装 水手服`、`/投喂`）。
   - **停止与外部接管**：`/停止` 不在命令层拦截为未知指令，直接交由 `QQTurnRuntime` 的停止协调器；插件指令在 `_handle_plugin` 中由当前 Bot 的 broker 处理；定向角色消息（`/<角色ID> 正文`）在上游消息准入层直接作为对话转发，不递归为宿主命令。
4. **测试与验证**：
   - 从 `tests/test_qq_command_dispatch.py` 或 `tests/test_qq_commands.py` 复制真实路由夹具，验证解析单次性、同类 `kind` 不串线、参数透传及副作用持久化。
