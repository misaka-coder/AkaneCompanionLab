# MemCore 摘要参考与工具参数紧凑历史执行单

日期：2026-10-03。状态：源码实现、离线与真实 provider 验证、提交、线上启用和重启检查已完成；连续聊天缓存指标仍需线上实测。验证记录见末节。

本轮解决两个问题：聊天摘要混入过多历史操作摘要；已完成任务的长工具参数继续大量占用聊天上下文。摘要模型只参考上一条聊天摘要，工具历史保留原生调用结构，仅收起过长的字符串参数。原始记录可回读，普通调用和正在执行的工具链保持完整。

实现分为 MemCore 通用能力与 Akane 接入两部分。MemCore 不引入 QQ、角色名或具体工具名的特殊规则。暂不调整原始历史压缩触发阈值、完整回合切点、记忆检索权限、角色输出格式或工具轮数。

## 1. 代码与样本依据

当前摘要参考来自 `get_visible_episodic_summaries(limit=episodic_visible_max)`。查询未在 `LIMIT` 前限定聊天摘要类型，渲染时又同时拼接 `diary_summary` 和 `core_facts`。因此参考可能包含操作摘要，并重复呈现同一批信息。聊天可见层另有事后类型过滤，所以也可能被操作摘要提前占掉可见名额。

当前 `compact_after_terminal` 只收起工具结果，明确保证调用参数不变。该枚举是已发布的持久化协议，不能直接改变其语义。长参数能力需要新增独立策略。

| 只读核查样本 | 结果 | 对实现的约束 |
| --- | --- | --- |
| 10 月 1 日论文任务的摘要输入 | 对话正文 1,698 字符；参考摘要 32,080 字符，其中操作摘要 29,217 字符 | 缩减参考，不继续压缩已经很短的对话正文 |
| 同一批参考 | 10 条中有 5 条聊天摘要、5 条操作摘要 | 必须在查询阶段过滤类型，再取上一条 |
| 近一周主人私聊与 87 群的 1,082 次调用 | 参数 JSON 中位数 83 字符；约 93% 小于 1,000 字符 | 普通调用保持原样，只处理少量大参数 |
| 论文任务结束后的历史投影 | 约 61,712 token；写文件和补丁参数约占 48,524 token，即 78.6% | 结果卡片已生效，主要剩余开销来自长调用参数 |

字符数是本地记录的实际长度，表中的 token 是现有宿主计数器估算，不是上游计费或缓存 usage。参数统计不包含工具 schema、图片和其他消息开销。

## 2. 第一片：摘要模型只参考上一条聊天摘要

1. 在 MemCore 中建立独立的“上一条聊天摘要”查询，不复用聊天可见窗口条数。本轮参考固定为至多一条，无可用前文时不注入参考。
2. 查询限定同一记忆命名空间和当前会话，类型为 `memory.episode_summary`。先过滤类型、有效性和覆盖范围，再排序并 `LIMIT 1`。
3. “上一条”依据摘要覆盖的原始对话顺序确定：只选择覆盖范围在当前压缩批次之前、且不与当前批次重叠的摘要。不能直接按摘要创建时间取最新一条，以免回填或重试读到后文。旧记录缺少覆盖时间时，优先依据现有来源关系；无法确定前后关系就省略参考。
4. 参考只渲染日期与 `diary_summary`，不再重复拼接 `core_facts`、操作摘要和额外语气说明。参考用于保持事实连续，不能当作本批新增事实再次写入。
5. 修正共享的聊天摘要可见查询，让类型过滤发生在 `LIMIT` 前。显式读取操作摘要继续走其原有查询，不删除操作摘要，也不扩大默认检索范围。

聊天模型看到多少阶段摘要、阶段摘要何时进入长期记忆，仍由原有配置控制。不能把 `episodic_visible_max` 改成 1 来实现本项。

保留当前压缩事务：模型生成聊天摘要，代码生成操作摘要，两者与来源关系一起提交。摘要生成失败时继续保留原始历史，不提交空摘要。本片不增加模型请求。

主要修改位置：MemCore 的 `compaction.py`、`store/sqlite_store.py` 及存储接口声明。内部查询留在 MemCore 中；Akane 不直接操作 MemCore 私有数据库。

## 3. 第二片：保留原生调用结构，收起长字符串参数

### 3.1 新增策略并保留旧策略

新增 `compact_arguments_after_terminal`，表示成功完成回合后，执行现有工具结果紧凑化，并处理符合门槛的长参数。两个现有值保持原义：

| 策略 | 行为 |
| --- | --- |
| `full_until_raw_compaction` | 完整调用与结果保留到原始历史压缩 |
| `compact_after_terminal` | 回合结束后收起较长结果；调用参数保持原样 |
| `compact_arguments_after_terminal`（新增） | 回合结束后收起较长结果及合格的长字符串参数 |

库和宿主的缺省策略保持现状。实现完成、离线验收通过后，再在实际运行配置中显式选择新策略。旧策略关于参数逐字节相同的测试继续保留，不放宽断言。

### 3.2 只改变参数中的长字符串值

保留工具调用 ID、名称、类型、调用与结果配对关系，以及参数对象的键、层级和类型。保留短字符串、数字、布尔值与 `null`。第一版递归处理字典中的字符串叶子，数组整体保持原样，不裁剪元素或改变顺序。

讨论后确认的规则如下：

- 单个字符串达到 **1,024 UTF-8 字节**才尝试收起；判断对象不是整个参数 JSON。
- 保留最多 **96 个字符**的前缀，追加英文短标记和原始调用 `source_id`；不重复字符数、工具名或调用 ID。
- 替换后节省须严格超过运行配置指定的原字符串 UTF-8 字节比例，否则仍保留全文。收益门槛沿用已经冻结的 settlement 保存比例；初次部署为 50%，后续调整为 30%，对比记录见第 9 节。
- 参数仍是字符串；不改成卡片对象，不向工具参数增加 schema 外字段，不依赖工具名称白名单。
- 预览沿用现有安全净化规则，不在标记中追加凭据、内部路径、哈希或冗余调用 ID。

示意如下，标记表示历史正文被收起，不是原调用的真实内容：

```json
{
  "path": "report.md",
  "mode": "replace",
  "content": "# 报告\n……\n[truncated source_id=action-id]"
}
```

OpenAI 的 `function.arguments` 仍是合法 JSON 字符串；参数解析后，只对确实需要紧凑化的调用替换并重新序列化。Anthropic 的 `tool_use.input` 保持原来的对象结构。没有符合条件的字段时，不重新序列化调用，保留原投影字节。

第一次只支持能够明确定位参数的现有协议。未知形状、无法解析的参数或无法安全处理的签名内容保留完整投影，并记录可诊断原因。保留参数以外的 provider 扩展字段；不能伪造签名，也不能因为结构合法就宣称上游接受改写后的历史。

### 3.3 仅在回合成功结束后生成一次紧凑历史

正在执行的回合始终使用完整参数和结果。只有 `complete_turn` 成功提交最终回复后，才基于该回合冻结的实际请求投影生成紧凑历史；不能在每次模型请求前重新裁剪。

原始 action、observation、来源关系和实际请求账本保留。紧凑历史是给后续请求使用的另一份投影，不覆盖原始数据，不自动重写旧回合。失败结果的状态和原因继续按原有结果卡片规则保留。

新增参数门槛与预览长度在 `begin_turn` 冻结并持久化。新策略的配置指纹包含这些值及渲染版本；旧策略保持既有指纹算法。旧数据库新增字段缺省不改变历史读取，新投影按回合和 provider profile 幂等保存，重启后直接复用。

当前 settlement 的“是否发生紧凑化”只检查 observation。需要同步纳入 action，保证只有参数缩短、结果很短的回合也记为 `settled`，后续请求和原始历史压缩计数都使用实际紧凑投影。不能出现参数已经缩短、计数却仍使用原长度的情况。

主要修改位置：MemCore 的 `config.py`、回合模型与存储迁移、`settlement.py`、`memory_system.py`、必要的 `projection.py` 协议定位代码。优先扩展现有结算路径，不另建宿主压缩器。

## 4. 原文回读与模型说明

调用参数标记引用原始 action 的 `source_id`，结果卡片继续引用原始 observation 的 `source_id`，两者不能混用。复用现有入口：

```text
open_memory(memory_id=source_id, view="content", detail="full")
```

验收必须确认该入口能在当前授权范围内返回原始完整参数，而不是再次返回紧凑预览。支持原有批量回读，继续执行会话与命名空间校验，不新增无边界查库工具。

Akane 当前稳定说明称“工具调用参数仍完整可见”，启用新策略后需要改为准确且简短的说明。建议文案：

> 已结束轮次的长工具参数或结果可能只保留预览和 source_id，原文仍可回读。需要具体内容、复制或复用被收起的参数时，用 open_memory 打开原文；已有信息足够时无需回读。当前执行中的工具链保持完整。

旧策略继续使用准确描述旧行为的提示。新提示在启用新策略或可见历史含新策略投影时稳定注入一次；切回旧策略后也要能说明仍可见的新历史。不要每轮添加计数、时间戳或长例子。

另外，在 `workspace_write` 与 `workspace_patch` 的工具说明中各补一句适用场景：新建或确实需要整篇替换时使用 write；追加或局部修改优先使用 patch。使用当前已有的无行号补丁格式，不新增 append 模式，不改变执行权限或强制指定工具。这样能减少开放回合中反复传入完整文件的开销。

## 6. 验证与验收

### 6.1 摘要与记忆

- 构造聊天摘要与操作摘要交错的记录，确认过滤在 `LIMIT` 前，操作摘要不会占聊天摘要名额。
- 覆盖无前文、仅有操作摘要、跨会话、回填、同时间戳、参考已进入长期层和摘要生成失败；最多只注入一条符合来源顺序的聊天摘要。
- 确认聊天可见窗口与长期层压缩阈值不变，操作摘要仍可显式读取。
- 用已有压缩前快照复制出的隔离数据库，重建论文样本的摘要输入。记录对话、参考、模板各自长度；参考只含前一条聊天摘要，不能继续携带约三万字符的操作摘要。

### 6.2 原生工具与结算

- 覆盖 OpenAI、Anthropic 及 canonical 投影，检查调用 ID、工具名、参数键与值类型、并行调用和乱序结果配对。
- 覆盖短参数、嵌套字典、数组、门槛前后、中文与 ASCII、不足收益、非法 JSON、未知扩展、带签名内容和失败结果。
- 开放回合完整；失败或未完成回合不提前缩短；成功结束后只生成一次。重复结算、配置变化、重启、切换策略均不改变已冻结投影。
- 对“长参数＋短结果”单独验收，确认 settlement 状态、请求历史和 token 计数一致。
- 用 `source_id` 回读原始调用，逐字段比对原参数；原始 action、observation 与来源覆盖数量不变。越权回读仍被拒绝。
- 重放只做历史投影，不重新执行历史写文件、命令或其他工具。论文样本以约 61,712 个估算 token 的紧凑历史为基线，分别报告参数与结果减少量，不能仅输出总比例。
- 真实 provider 验收包含任务后继续调用工具和原文回读。若某类签名历史不能接受参数改写，保留其全文并记录限制，不丢弃签名来伪造兼容。

### 6.3 缓存与性能

参数紧凑化不调用模型。摘要参考缩减不增加模型请求。结算允许在成功结束时做一次线性遍历和持久化，后续请求直接读取冻结结果，不能引入每轮全历史解析。

离线比较相邻请求、下一轮和重启后的稳定系统提示、工具 schema、已冻结历史前缀。区别“结算导致一次历史替换”与“之后每轮不断改写前缀”，后者属于实现错误。

线上按同一会话、角色、模型统计真实输入 token 与 cache-read token，以 token 加权命中率验收。目标为连续聊天 **95% 以上**；压缩、首次切换和新建前缀需要单独标记。沿用 `/缓存` 与现有审计，不为统计新增模型请求。上游缺报时明确缺报，本地前缀稳定性不能替代上游命中率；无法确认原因时保留证据交由用户实测。

## 7. 启用与回退

启用前备份运行配置和一致的数据快照，先确认新 wheel 与依赖闭包能通过启动检查，再选择新增策略。已有冻结历史继续原样读取，新规则仅作用于之后开始并成功完成的回合。

回退优先在支持新数据结构的版本中切回旧策略，保留已有紧凑历史及回读提示，不反复展开与压缩旧回合。不能把旧 wheel 直接换回并让它读取未知新策略；如必须回退代码，需要在隔离环境验证对应数据版本，或恢复匹配的一致备份，并处理备份后新增数据。

交付报告需说明实际参数门槛、论文样本前后体积、原文回读结果、provider 兼容范围与缓存实测情况。只有这些证据齐备，才将执行单状态改为完成。
