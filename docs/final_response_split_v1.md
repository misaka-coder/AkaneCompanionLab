# 最终回复生成拆分

本次处理 `companion_v01/engine_services/final_response_streamer.py`，目标是让请求准备、输出判定和流式执行分别有清楚的维护入口。

## 模块入口

| 模块 | 职责 |
| --- | --- |
| `final_response_constants.py` | 重试反馈、恢复反馈和缓存布局版本 |
| `final_response_policy.py` | 工具决策、可交付文本、损坏 JSON、重试原因和解析恢复判定 |
| `final_response_recovery.py` | 模型纯文本恢复、默认表现字段、已交付语音与恢复尾文合并 |
| `final_response_failures.py` | 服务与 MemCore 失败状态、安全原因码和恢复指标 |
| `final_response_contracts.py` | 本轮请求的身份、投影、模型路由、输出上下文和恢复输入 |
| `final_response_request.py` | 共用上下文准备、投影观察器、请求参数、缓存路由和输出来源标记 |
| `final_response_sync.py` | 同步结构化请求、格式重试与最终纯文本恢复 |
| `final_response_stream.py` | 流式启动、尝试调度、请求独立状态与最终交付收尾 |
| `final_response_events.py` | 增量事件转发、精确前缀去重、底层生成器释放 |
| `final_response_fallback.py` | 流式到非流式再到无缓存请求的有限降级与来源判定 |
| `final_response_streamer.py` | 31 行静态组合入口，保留原来的引擎方法和常量导出 |

## 第一片：输出判定与恢复

使用静态 mixin 组合保留方法签名和 `self` 调用，原有实例覆写和测试替身继续有效。合法工具调用仍进入普通工具循环，格式修复不会自动撤销工具权限。宿主默认答复不能冒充模型输出；解析恢复必须有原始输出证据。

删除了输出判定中已被前面的 `parse_fallback` 分支覆盖的不可达条件。纯文本恢复对 `ModelRequestCancelled` 直接上抛，交由主流程取消处理，避免将用户取消误作普通恢复失败。

## 第二片：请求准备

同步和流式入口使用 `FinalResponseRequest` 携带同一轮的身份、图片、模型路由、上下文和观察器。该对象固定这些绑定，仍使用原有可更新的 MemCore 请求投影状态；不复制或另建一条时间线。

请求共用系统提示、用户投影、历史、临时尾部反馈、工具结果、图片和缓存参数。结构化请求额外带宿主 fallback 和稳定的原生工具 schema；纯文本恢复继续明确禁用工具，仅使用模型真实文字。四处重复的输出归一化、原生 reasoning 和 memory annotation 来源处理也收敛到同一方法。

保留流式惰性启动：创建生成器不会准备请求，第一次推进先准备上下文和观察器并发出 `turn_start`，后续推进才登记缓存和请求模型。上下文投影失败在观察器、事件、缓存和模型请求之前返回明确失败。

## 第三片：流式执行

`_stream_final_response()` 保留 69 行启动入口；128 行执行方法负责尝试调度，事件转发、传输降级和收尾分别由 70、73、59 行的方法承担。同步入口与流式入口继续是两种真实传输，共用请求、输出判定和恢复规则。

`FinalResponseStreamState` 只属于当前请求，保存已交付句子、最后输出、重试反馈和失败信息。恢复只抑制精确的连续前缀重放，开始新尾文后保留有意重复的句子；结束时不重放已经发出的事件。原生工具 preface 的流式标记及普通工具续接保持原有语义。

底层流在 `finally` 中显式关闭，适用于外层生成器关闭、取消、异常及正常完成。关闭失败仅记录异常类型；取消信号仍交给主流程处理。

补测先在原实现中复现了以下问题，再确认修复：

- 关闭或取消外层流时，外部仍持有的底层生成器没有及时释放。
- 流式降级绕过统一终态判定，带传输错误的非空 fallback 可能误报恢复成功，JSON 外的正文可能被忽略。

降级输出现在通过同一套终态判定：传输失败不能成为模型答复；JSON 外正文和文本工具协议不能直接当作完整交付。能由原始输出证明的完整 speech 或模型纯文本可以正常恢复；合法原生工具调用继续进入工具循环。仍然只在未交付完整句子时尝试等价非流式请求，非流式传输失败才尝试一次清空缓存键的请求；连续限流和投影拒绝按原边界终止。

## 规模变化

| 位置 | 拆分前 | 拆分后 |
| --- | ---: | ---: |
| `final_response_streamer.py` | 1709 行 | 31 行静态入口 |
| `_build_final_response()` | 265 行 | 201 行，位于同步模块 |
| `_stream_final_response()` | 548 行 | 69 行启动入口，另有 128 行调度方法 |
| 最大实现模块 | 1709 行 | 359 行，请求准备模块 |

源代码仍承载完整行为：目前 11 个相关模块共 1894 行，新增部分主要是明确的请求/状态契约、模块边界和失败处理。入口行数的减少不等同于删除了全部实现，也不表示产生了同等幅度的性能提升。
