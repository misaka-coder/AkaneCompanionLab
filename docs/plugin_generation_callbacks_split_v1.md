# 插件反向回调拆分与边界验收

## 职责与入口

原 `companion_v01/plugin_generation_callbacks.py` 的 885 行实现已迁到 `plugin_callback_runtime/`，原文件保留 72 行兼容入口。七个历史类、41 个历史导入绑定和原 `__all__` 继续可用，调用方仍通过原入口访问同一套实现。

| 模块 | 行数 | 职责 |
|---|---:|---|
| `router.py` | 280 | 单一共享状态、端口绑定、协议与权限准入、控制通道响应 |
| `scopes.py` | 97 | 普通调用和服务作用域、授权撤销、调用关闭及结果归属 |
| `host_ports.py` | 175 | 能力、事件、任务、连接、资源和通知的真实宿主调用 |
| `scheduling.py` | 162 | 回调调度、重复请求准入、取消、备用事件循环和线程关闭 |
| `worker_ports.py` | 234 | 六种 worker 端适配器、统一请求记录生命周期、各端口结果解码 |

宿主路由继续持有一份锁、调用表、回调控制表和 Future 表。三个职责 mixin 直接使用这些状态；worker 端继续使用原共享 pending 表和 generation 控制通道。原能力、事件、任务、连接、资源及通知端口均接入原调用链，没有引入另一套权限或资源注册中心。

## 保留的调用约定

普通调用与后台服务的作用域仍按原上下文和已批准权限创建，私有连接结果仍只通过私有回调通道返回。普通作用域保留原事件初始化入口；服务作用域保留其原有初始化行为。能力调用的结果净化、依赖结果收据、事件与任务的权限判断及资源 representation 检查沿用原逻辑。

能力、事件和任务在取消时继续向宿主发送信号，并等待真实终态后才释放 pending 记录；重复取消也经过 SDK 的 `drain()`。资源、连接和通知保留原来的直接取消行为。新的共享请求 helper 将请求发出前后的失败都纳入 `finally` 清理，端口各自的输入检查和结果解码仍由各自实现负责。

关闭先撤销新回调准入及现有作用域授权，再取消已提交的 Future。备用线程负责排空自己的任务；线程未确认退出时保留句柄并报告失败。同步 `close()` 保留原来的两秒 join 上限，后续可再次调用以确认清理。旧代次清理和后台自动重试策略没有在本轮扩展。

## 复现与修复

1. 路由关闭后原来仍能接收回调、创建作用域，甚至再次启动备用线程。现在关闭状态在调度和作用域注册中都校验，返回或抛出稳定的 `callback_router_closed`；已经存在的作用域立即撤销，仍允许执行其结束清理。
2. 同一 callback ID 的查重与 Future 登记原来分属两次加锁，并发提交可能重复执行。现在在同一次加锁内完成准入与提交；完成回调的注册和错误响应的写出放在锁外，避免同步回调或响应接收方重入时死锁。
3. 调度失败原来会遗留尚未开始的回调控制记录。现在失败时关闭未提交的 coroutine，并清理对应记录；任务开始时发现记录已因关闭被撤销，也会返回取消/过期结果并完成清理，不再抛出 `KeyError`。
4. 备用线程正在启动、事件循环尚未登记时，原来可能重复创建线程。现在复用仍存活的启动线程并等待原 ready 事件；线程启动失败返回真实不可用结果，不遗留 coroutine。
5. 备用线程关闭超时原来仍会丢弃线程和循环句柄。现在报告 `callback_cleanup_incomplete` 并保留所有权，重试关闭时只发送一次 stop 信号，防止打断正在排空的循环。实际受控线程测试确认了超时后的保留和释放后的退出。
6. 作用域原来在资源关闭前从调用表移除；清理异常会丢失记录。现在先撤销授权，确认清理成功后才移除原对象，失败时保留供重试；旧对象清理结束不会移除已替换的新作用域。
7. 资源回调原来依赖 provider 自行登记任务。现在路由本身持有请求引用，作用域关闭会等待正在执行的资源工作，临时文件持续保留到实际结束，撤销后的结果不会返回文件路径。
8. 六种 worker 端口原来都在进入清理 `try/finally` 前发送请求，发出失败会遗留 pending Future。现在共用一个请求 helper，完整覆盖发出、等待、取消和释放，同时保留各端口原有取消约定。
9. `PluginGenerationProcess.stop()` 在 worker 已标记关闭时原来直接返回成功，可能跳过尚未结束的回调清理。现在重复关闭先调用已有回调路由的 `close()`，清理未确认完成时继续保留失败，确认完成后才返回 `already_stopped`。这个消费方只有一行行为改动，其余实现保持一致。

新增 `tests/test_plugin_callback_boundaries.py` 的 16 项检查，含六种 worker 端口和三种受控宿主回调的子用例。覆盖关闭后的请求、作用域清理失败/重试、资源文件保留、并发重复提交、响应重入、线程启动及关闭失败、真实慢线程清理、旧作用域替换，以及重复停止消费方。使用拆分前回调源码及消费方源码执行，14 项复现失败，另外两项保护原有两类取消约定。
