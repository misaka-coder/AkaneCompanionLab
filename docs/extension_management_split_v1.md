# 插件管理拆分与事务边界验收

## 排队与取消

重载和卸载先取得管理锁，再读取持久选择与安装清单。排队请求因此能看到前一操作已经提交的状态，避免把旧启停配置重新发布或把刚安装的插件误报为未安装。

重载、启停、安装、卸载、制品回滚和候选丢弃共用一个串行事务入口。仍在等待锁的请求被取消时不开始工作；已经取得锁的请求被取消时，继续持有锁，等待完整提交或失败恢复结束后才向调用者返回取消。重复取消也不能让后台线程提前脱离管理锁。取消、显式同步超时不会撤销已经开始的安装决定；调用者可通过既有状态接口读取最终结果。默认同步入口仍没有人为设置的总时间限制。

市场、wheel 和源码暂存仍保留原取消策略：先等待安装线程结束，再丢弃已生成候选，最后释放管理锁。市场使用同一条取消收尾链。丢弃候选也在线程中执行并等待终态；失败保留取消类型及稳定的 `plugin_stage_discard_failed` 原因，现存候选仍可从管理清单查询和重试清理。

## 失败与恢复

1. 运行时端口异常转换为 `plugin_runtime_reconfigure_failed`。安装发布后的激活异常会走既有制品、选择和运行时恢复链；卸载已提交后发生的运行时异常明确返回 `removed_runtime_degraded` 和重载要求。
2. 启停、安装及卸载的回滚不能仅凭调用返回就认定成功。校验拒绝发布、degraded、完整插件集合以及原启停状态；缺失、残留或状态错误均返回 `rollback_failed` 与操作对应的稳定原因。
3. 已明确拒绝且 `published=False` 的候选仍保留原可用代次，不额外重启旧插件。安装恢复只修正制品和选择，再核对现存代次；继续使用真实调用持有的目录保留机制。
4. 市场暂存取消时不再假定失败结果具有 `stage_id`；无候选结果正常保留取消行为。
5. 同步管理提交与运行循环关闭发生竞争时，关闭尚未调度的协程并返回循环不可用，避免协程泄漏和裸异常。
6. 启停的“无需变化”分支核对目标的真实运行状态。配置已经启用但实际不可用时仍尝试激活；真正等待依赖的目标继续返回 `waiting_dependency`，不会被误报为已启用。

启停、重载、安装、卸载等成功返回结构继续兼容；用户可见的变化集中在操作并发、取消和失败报告。界面、授权范围、QQ/桌宠状态归属及服务绑定激活方式没有新增变更。
