# QQ 自身 @ 与主动快讯静默 repair pass（2026-09-08）

## 问题与根因

- 真实入站消息已经命中 `group_mention`，结构化目标也是 `assistant`，但可读正文仍把
  自身 @ 展示为账号昵称，模型曾回答“你是在问山城高岭吗”。入站准入正确不等于模型理解正确。
- 金融插件 0.8.4 已要求空 `speech`，但真实历史里仍出现 `【暂不推送】` 后接解释并被发送。
  只验证新提示哈希、或只看到一条正常快讯，不能证明静默问题已解决。
- 实机回放又发现 `channelcore-onebot 0.1.0` 的群成员响应投影丢弃 `user_id/group_id`。
  宿主无法核验昵称属于当前 Bot；只 mock 宿主返回值的测试未覆盖这一层。

## 实现与权威边界

- 当前 @ 自身统一投影为 `@助手（本群昵称：天为）`，`actor_id=assistant` 明确表示在叫当前助手。
  仅附当前群昵称，不把账号昵称、人设名字再拼成身份说明；没有修改 QQ 昵称、群名片或角色配置。
- 群昵称通过绑定账号的真实 `get_group_member_info` 查询并核验身份，短期缓存隔离到账号与群。
  查询失败、身份不符时只保留 `@助手`，不冒用其他昵称。引用消息不冒充当前显式 @。
- `channelcore-onebot 0.1.1` 在既有响应规范化入口保留群成员身份字段，并结构化拒绝畸形身份值。
  协议规范化仍由包独占；宿主只做产品身份展示，没有旁路 HTTP 解析或第二套 OneBot 实现。
- 静默的正式协议仍是模型明确返回空 `speech`。宿主增加狭窄的旧标签兼容保护：
  仅针对 QQ `plugin_event`、`single_message`、有结构化事件类型的主动通知，识别正文开头
  `【不推送】/【暂不推送】` 等旧否定标签（含相应 ASCII 方括号和有限同义变体）。
  普通聊天、引用标签、正常分析、失败降级不会被当成静默。
- 保护在最终工具循环之后、持久化与交付之前执行；自动前缀、标题、链接和表情一起不发。
  不伪造模型的空回复：保留原 provider envelope，不写入被拦正文或虚构 assistant 回复，
  另写宿主 `event.notification.delivery` 回执：`suppressed / legacy_notification_silence / text_sent=false`。
  模型不能通过伪造宿主专用字段触发该状态；回执写入失败会结构化报告，不恢复被拦正文。

## 未覆盖与后续风险
