# AI 协作协议 v1

本项目由作者（代码零基础）驱动多个 AI 协作完成。本文件固化「谁干什么」和「怎么把大任务勘探清楚」，让每个 AI（Claude / GPT / 探路模型）照同一套规则走，作者不必每次口头转述。

## 1. 风险分工（按风险分，不按阶段分）

这个项目真正会出事的环节是**执行**（碰承重链路时改错地方、假成功、改坏兜底、留活死不分的中间态、泄漏路径），不是计划。计划可逆、评审能拦；一个对 `engine.py` 回合循环的坏改动是悄悄塌的那种。所以分工按「这一步的风险」切：

| 工作 | 谁主 | 理由 |
|------|------|------|
| 计划初稿、备选方案、广度铺陈 | **GPT** | 铺面快、不被历史锚定 |
| 代码级勘查、把计划收敛成「安全顺序 + 边界 + 不变量」的可验证切片 | **Claude** | 已内化 INV 不变量 + 完成度纪律 |
| 低风险、边界写死的机械切片（照紧 spec 加 fixture/常量/测试） | **GPT 执行** | spec 写到没有判断余地，落 diff 便宜；Claude 抽查 |
| 承重切片（回合循环 / 输出归一化 / 能力门控 / 删 fallback / 翻关键开关） | **Claude 执行 + 验证** | 失败模式正是作者核心痛点，需内化约束兜底 |
| 「表现到位」验收（气泡 / 表情 / TTS / 音乐 / 文字不打架） | **Claude** | 最容易被「字段存在 = 完成」骗过去 |

两条硬护栏（不管谁写）：
1. **作者 ≠ 评审**：谁写的那段，另一个 AI 红队评审。这是抓「双轨残留」的网。
2. **一个最终拍板人 = Claude**：作者代码零基础、易对自己判断不自信；两个都自信的 AI 吵起来作者会卡住。架构 / 边界的最终决定权归 Claude 一处，GPT 负责广度与挑刺。

## 2. 勘探简报模板（开大任务前先让探路模型跑一遍）

> **勘探任务（只读，不改代码）**：围绕 `<任务 X>`，定位——
> 1. 入口 / 调用链；
> 2. 会被影响的承重点（对照 `docs/engineering_invariants_v1.md`）；
> 3. 隐含假设 / 历史包袱（哪里默认了某个旧字段 / 旧路径是主路）；
> 4. 配置门 / 开关（默认值 + 所有读取处）；
> 5. 现有验收入口和怎么跑；
> 6. 风险点（并发 / 兜底 / 双轨 / 字面匹配之类的坑）。
>
> **输出形式**：每条 `文件:行 + 现状一句话 + 潜在问题`。**不下结论、不给改法——结论留给把关的 AI 用完整上下文来下。**

为什么是这个格式：它给定位和事实，不给判断，所以把关的 AI 接起来快、又不会被探路模型的判断带偏。实战验证过一次（native-first 的 N3）：勘探暴露了「生产模型不在 native 登记表、翻开关其实空操作」，直接避免了一次无效改动。

## 3. 流程

1. 作者说要做 `<大任务>` → 让探路模型按 §2 模板勘探 → 产出简报。
2. Claude 用简报 + 自身上下文 + `docs/` 不变量，定**安全顺序 + 边界**，拆成可验证切片。
3. 按 §1 分配执行：机械切片可给 GPT，承重切片 Claude 自己来。
4. 作者 + 另一个 AI 评审 diff（作者≠评审）。
5. 有疑议时 Claude 拍板架构 / 边界。
