# QQ 单次角色对话与辅助人物执行单

日期：2026-10-01。核查基线：`521ba9e8` 及编写时的本地工作区。

状态：三阶段实现已接入并完成隔离行为验收。保留工作区其他改动；真实 QQ 投递和模型服务端缓存命中仍需运行验收。运行后端尚未重启。

本执行单用于接入两类 QQ 对话：使用 `/角色包ID 正文` 单次请求已安装角色，以及使用 `/售货员 正文` 请求服务当前主角色的辅助人物。复用现有 Agent 对话、流式输出、工具轮次和 MemCore；每个对象只使用自己的记忆。第一版不增加共享背景、跨角色记忆检索、完整对话转述或角色间自动协作。按用户后续补充，商品实际变更后，在服务角色的当前 QQ 会话时间线末尾追加一条事件，供下次聊天读取。

## 目标行为

假设当前会话的默认角色是塞西莉亚，且已安装 ID 为 `reimu` 的角色包：

| 输入 | 本轮说话者 | 对话记忆归属 | 默认角色与业务数据 |
| --- | --- | --- | --- |
| 普通消息 | 塞西莉亚 | 塞西莉亚原有范围 | 按现有逻辑处理 |
| `/reimu 今天过得怎么样` | 灵梦 | 灵梦原有范围 | 默认角色仍是塞西莉亚 |
| `/售货员 上架一个草莓蛋糕` | 售货员 | 售货员服务塞西莉亚的工作记忆 | 按权限修改塞西莉亚的商品配置 |
| 下一条普通消息 | 塞西莉亚 | 塞西莉亚原有范围 | 不继承上一轮的说话者 |
| `/角色 reimu`，随后找售货员 | 售货员 | 售货员服务灵梦的工作记忆 | 持久切换后的主角色为灵梦，管理灵梦商店 |

群聊仍需当前消息真实 @ 目标 Bot；私聊直接使用入口。`/角色` 保持持久切换语义，`/角色包ID 正文` 只作用于这一条消息。`reimu` 是示例 ID，实际入口来自安装结果，不硬编码为某几个角色。

对话记录与业务结果分别保存。售货员的完整对话、工具轨迹和回复只进入自己的工作记忆；商品变更保存到服务对象的商店。只把商品实际变更事件写入服务角色的当前会话，不补写售货员的完整对话或聊天摘要，不额外请求主角色模型。

- `to_turn_payload` 的 `memory_message` 优先来自原始 MessageChain。只修改 `clean_message`，不能保证 `/reimu` 前缀已从落库正文移除。
- 当前 `charpack_core` 会枚举 `characters/` 下带 `character.json` 的目录，没有辅助用途过滤。第一版辅助定义放在独立注册位置，保持现有正式角色包格式和枚举行为。

## 本轮对象与扩展边界

增加一个宿主持有、可序列化的本轮对话上下文，集中保存以下信息。字段名称可按代码习惯调整，含义必须一致：

| 信息 | 正式角色对话 | 辅助人物对话 |
| --- | --- | --- |
| 说话者类型和 ID | 已安装角色包的规范 ID | 注册的辅助人物 ID |
| 人设与资源来源 | 现有角色包加载器 | 辅助定义；第一版只要求文字人设 |
| 记忆 domain | 原来的角色包 domain，保持已有映射 | 辅助 ID 与服务对象组成的稳定 domain |
| 服务对象 | 无额外指定；原有业务沿用本轮正式角色 | 接收消息时的默认主角色，整轮固定 |
| 能力范围 | 沿用当前有效授权 | 当前有效授权与辅助工具范围的交集 |

用户身份、QQ 会话、消息 ID、群权限证据继续使用原始入站结果。现有 `actor_stable_id` 和 `actor_profile_user_id` 表示真实发言用户，不得改成灵梦或售货员。

本轮对象由宿主解析器生成并验证。外部 payload、插件参数或模型工具参数不能直接指定记忆 domain、替换服务对象或冒充辅助身份；队列保存的是已接收的固定上下文，恢复时仍检查其合法性。

辅助定义只需 ID、显示名、入口、人设和所需工具列表。通过宿主注册表或独立配置加载，新增相同类型的辅助人物应主要增加定义与工具实现。角色包继续由现有加载器负责；不为售货员补建 Live2D、养成、商店或完整桌宠资产，也不改变 Creator Kit 的包格式。

辅助入口不进入 `/角色` 的持久选择列表，也不能通过手动传入 ID 设成默认正式角色。辅助定义可以收窄权限，不能授予用户原本没有的能力。文件加载沿用宿主的受控目录与安全路径规则，不允许定义指定任意 Python 模块或外部路径。

第一版售货员服务对象只能是当前默认主角色。一次 `/reimu 正文` 不影响下一次售货员的归属；要管理灵梦商店，先用既有 `/角色 reimu` 持久切换。工具参数暂不开放任意角色目标。

## 阶段一 接通单次正式角色对话

已实施。以下分项保留为实现约束，真实投递与服务端缓存验收另列。

- 建立轻量入口解析与对象解析。复用现有 slash 分词，只解析当前正文开头的入口；引用、转发、代码段里的 `/reimu` 不成为路由指令。
- 内置指令与已注册插件指令保留其既有含义。角色或辅助入口与它们冲突时，明确禁用冲突入口并报告原因，不静默抢占；安装角色仍可用 `/角色` 选择。注册变化时重新检查冲突。
- 角色入口仅接受已安装、可解析的规范包 ID。若增加别名，必须显式声明并检查重复，不使用人物名字猜测或模糊匹配。
- 在 webhook 和 Bot 身份检查之后识别定向入口，并在可能启动默认角色回合的插件入站、引用升级、被动记录和主动观察之前确定路由归属。
- 群聊先沿用真实 @ 门禁。未选中本 Bot 时不执行定向对话，不回执，不创建该对象的记忆，也不把已识别的定向对话送入默认角色的记忆或注意力窗口。其他现有群指令与普通旁听政策不顺带改写。
- 去掉一个入口 token 后，正文整体作为本轮输入，不递归把正文解释成另一条宿主指令。无正文时本地返回简短用法；未知入口保持现有未知指令反馈。
- 同步生成正确的模型正文和记忆正文，保留原始消息作为传输证据。真实用户身份、附件、引用和转发证据继续绑定当前来源，不能因替换正文而丢失。
- 直接把本轮正式角色交给现有 Engine；不先请求塞西莉亚再转交灵梦，不持久修改 Gateway 的角色 override，也不临时改全局 persona。
- 入队时保存固定对象，出队和恢复时校验规范 ID 与类型。若包已卸载或不可用，返回明确失败，不回退默认角色代答。
- 沿用现有物理会话队列与串行处理规则，保持停止、取消与异常释放行为。定向对话不更新默认角色的主动参与状态，也不引发她的额外模型请求。
- 正式角色沿用自己的回复资源与语音配置，保留现有结构化输出、分句、工具消息投递和重复投递抑制。投递中断后不能又由默认角色重发一遍。
- 群聊仍按现有规则标注真实群成员；私聊保持正常 user、assistant、tool 结构。不得把多个 AI 角色拼成一段“群聊天记录”注入。

本阶段完成后，验收“塞西莉亚普通对话 → 单次灵梦对话 → 塞西莉亚普通对话”，确认两边历史和持久默认设置都正确，再继续辅助人物。

## 阶段二 接入辅助人物与独立记忆

已实施。第一版售货员只提供文字对话、记忆读取和同步商品管理工具。

- 注册一个售货员定义，入口为 `/售货员 正文`。复用同一个 Engine 的模型请求、工具轮次、重试和流式投递流程，不另写一套 NPC Agent。
- 模型选择继续使用当前 Bot 和会话已有的聊天模型配置，包括会话模型 override、provider 协议与思考设置。不增加单独的售货员模型请求链，也不再让主角色模型加工售货员的回复。
- 在进入 Engine 时按说话者选择人设。辅助人物不继承当前主角色的人设、情绪参考、服装或养成提示，也不因没有角色包而触发默认人设回退。需要保留的是共用的对话与输出协议。
- 复用现有结构化输出、解析、frame 和 QQ 分段投递。speech 与 utterances 的选择沿用共用协议及对象能力规则，不另造辅助人物专用 JSON；显示 text 汇总与 say 的语音分句继续交给现有适配器。分段沿用标点、长度上限和投递设置，不额外规定一个 JSON 项就必须发一个气泡或合成一段音频。
- 第一版辅助人物使用文字投递；不要求配置语音，不套用塞西莉亚的声音，也不要求额外生成日语 say 或参考音频 style。此设置仅作用于本轮，不修改会话持久回复方式。正式角色的现有 QQ 和桌宠语音流程保持原行为。
- 在宿主 MemCore 适配层拆开记忆 domain 与角色资源来源。正式角色继续使用原有 Namespace；辅助人物使用带类型区分、可稳定重建且不会与合法包 ID 冲突的 domain。核对 MemCore 对 domain 编码的约束后固定映射。
- 用户和物理 conversation ID 沿用现有规则，不通过创建虚假 QQ 用户、伪造群消息或改写会话 ID 实现角色隔离。
- 售货员工作记忆按服务对象区分：同一 QQ 会话内，服务塞西莉亚与服务灵梦是两个固定范围；切回塞西莉亚后恢复此前工作记忆。
- 贯通历史读取、用户消息保存、assistant 保存、工具轨迹、流式结束、失败记录、重试续轮、摘要压缩与关闭维护。所有操作使用同一本轮对象，不只修改最终回复的落库参数。
- 接通正确的压缩人设提供者，辅助摘要使用辅助人设。检查后台维护、延迟任务和已有 fallback 是否仍根据最新默认包加载人设或读取物理会话全量历史，避免跨对象串入。
- 记忆工具默认读取当前说话者范围。保留既有同一角色的跨会话权限政策，不增加跨角色或跨辅助服务对象检索；辅助人物不自动检索主角色的聊天历史。
- 将对象上下文传至 ToolExecutionContext 和所有续轮；发现目录、插件会话引用与延迟工具返回同样不得逃出本轮范围。不能沿用默认角色的 conversation ref 代替辅助范围。
- 保持正式角色的稳定提示与缓存范围兼容。相同角色用默认入口或单次入口时，不因为路由形式新增稳定提示或缓存家族。
- 辅助人物按固定身份和服务对象使用稳定缓存范围。工具 schema 在同一未结束回合内保持稳定；消息 ID、随机任务 ID、动态商品快照、时间与入口原文不进入稳定前缀或分桶身份。
- 不修改 MemCore 的通用 Namespace 定位，不迁移、复制或重写已有角色记忆；不直接修改 `.venv` 中的 MemCore 或 charpack_core 安装文件。

缓存验收要同时比较稳定系统前缀、实际 history 归属、工具 schema 与 provider 请求序列。缓存 key 相同不能单独证明缓存保留；新对象首次使用允许冷启动，真实命中率以服务端返回的 usage 为准。

## 阶段三 接入售货员商品工具

已实施。商品与记忆事件使用既有服务，通知失败与商品保存结果分别返回。

已提供 `read_character_shop` 和 `edit_character_shop` 两个接口：

| 接口 | 模型参数 | 宿主绑定与结果 |
| --- | --- | --- |
| 读取商店 | 无需传角色 ID | 使用本轮服务对象，返回可编辑商品与 revision |
| 编辑自定义商品 | 新增、修改或下架动作；名称、简短介绍 description、价格、效果、渠道可见性，以及所需的商品 ID、revision | 调用既有商品服务，返回实际结果与最新版本；不允许模型改变服务对象 |

- 实现真实 handler，并注册到现有能力体系。复用 `care_shop_settings` 的 read、create、update、delete，不从工具 handler 直接拼文件路径或重写整个 `character.json`。
- 第一版写操作仅按已验证的主人身份授权；群会话共享 profile 不等于当前发言人是主人。普通用户的聊天或读取按现有政策处理，写入不足权限时返回清楚的拒绝原因。
- 商品工具仅暴露给售货员；正式角色的工具选择不增加这组管理能力。辅助工具范围与宿主有效授权取交集，schema、执行 dispatch、延迟发现和目录刷新同步限制；handler 缺少可信服务上下文时直接拒绝，不能只靠提示词约束。
- 本轮服务对象由宿主保存，不把角色 ID、owner QQ 或路径作为模型可填的授权参数。切换默认角色只影响新接收的回合，不能让在途工具改写另一家商店。
- 编辑范围先覆盖自定义商品。现有 QQ 特殊物品、节日机制与经济事务保持原实现，不开放任意余额、好感、额度或养成状态修改。
- 复用字段范围、商品数量上限、桌宠和 QQ 可见性校验及安全路径校验。模型提供部分修改时，根据匹配的 revision 补齐既有服务所需字段，保留未修改的特效键；版本已变化时报告冲突，不悄悄覆盖。
- 售货员可新增、单独修改或清空商品简短介绍。description 使用已有最多 120 字符的校验，提示写适合卡片展示的简短正文；不提供介绍时保留旧值，明确传空字符串时清空，不能把未传字段当作清空。
- 对没有可编辑商店的正式角色，返回已有不可用状态。不能因为调用售货员就替该角色创建养成配置，更不能给售货员自己初始化商店、关系或钱包。
- 复用已存在的调用凭证与重复事件控制，验证同一个逻辑写调用重放不会重复新增商品。若现有机制无法覆盖这条写链，补足最小操作凭证或稳定新增标识；随机商品 ID 和 revision 校验本身不等于幂等。
- 超时、取消或中断后如写入结果不明，先核对实际提交结果；无法确认时如实反馈，不盲目重做，不让模型声称成功。权限不足、冲突、商品不存在与服务故障都保留可公开的原因，不泄露文件路径。
- 写入成功后 QQ `/商店`、购买与投喂，以及桌宠商品编辑页读取同一份配置。使用临时角色包与钱包验证，不借测试修改真实用户余额或删除现有商品。
- 保存成功后的下一次 `/商店` 图片与文字查询使用最新名称、介绍、价格和效果；背包仍按既有规则使用在售商品的实时信息。沿用现有读取与按内容缓存的渲染链，不维护另一份商品图片数据、不另建同步任务。介绍变动即使余额不变，也不能命中旧内容图片；介绍较长时沿用最多两行摘要与文字版完整展示。渲染不调用 LLM 或生图。
- 成功新增、修改或下架后，复用 `MemcoreManager.append_standalone_event` 在服务角色当前会话末尾追加商品事件；只带实际变更，不复制辅助对话。稳定 source ID 防止重放重复追加；冲突、取消、失败或无实际内容变化不产生事件。商品保存和事件写入是两个事务，通知失败时返回真实的 `event_notification` 状态，不把已保存商品说成编辑失败，不额外调用主角色模型。

售货员人设保持短而明确，例如：你是当前角色商店的售货员，按用户需求维护自定义商品；先查看现有商品再修改，缺少影响价格或效果的必要信息时再询问；以工具结果说明完成情况。当前服务角色的显示名由宿主提供，内部 namespace、存储路径和权限凭据不进入提示。

| 默认群旁听和主动搭话 | 仍使用持久默认角色；定向对话不被再次旁听或算作默认角色参与 |
| 正式角色语音与辅助文字回复 | 正式角色沿用自己的语音与分句，辅助没有冒用主角色声音或触发第二条 TTS 链路 |
| 当前会话切换聊天模型，辅助回复包含多句或超长正文 | 使用同一模型选择流程和输出解析器；流式分句、长度处理、工具续轮与重复抑制沿用普通聊天行为，不按 JSON 项机械发送 |
| 普通用户要求写商品，伪造参数身份或调用隐藏工具 | 无真实写入；发现和执行均不绕过授权与辅助范围 |
| 主人新增、改名、调价、改效果、下架自定义商品 | 真实配置变化；QQ 与桌宠都读取到结果，未修改的特殊字段保留 |
| 商品实际变更后再与服务角色聊天 | 原始历史保持前缀，末尾读到变更事件；其他正式角色及辅助工作范围不混入事件，重复请求不重复追加 |
| 只修改或清空介绍，余额和其他字段不变后查询商店 | 图片与文字均反映最新介绍，缓存签名随内容变化；价格、效果与库存保持原值，桌宠编辑页读取同一结果 |
| 商品重名、非法字段、商店缺失或 revision 冲突 | 返回可理解的真实状态，不创建售货员钱包，不覆盖新版本 |
| 重复 webhook、相同写调用重放、取消后恢复 | 无重复新增、重复扣款或重复投递；结果不明时不假成功 |
