# 本地 QQ 扫码接入 V1

范围：Windows 桌面控制中心接入**已安装、可信的 NapCat Shell**。
不自动下载软件，不接管远端 NapCat，不自动停止 QQ，不发送测试消息。

## 用户入口

控制中心唯一入口仍为 `control-center-lab.html`，在「系统与诊断 → QQ 接入 · 本地扫码」。
后端停止时仍展示接入面板；普通浏览器预览与远端 Bot 不提供本机启动按钮。

本地 QQ 启动脚本新增可选开关，可启动后直接打开此页：

```powershell
pwsh -File .\start_akane_local_qq_test.ps1 -OpenQQSetup
```

也可双击 `start_akane_local_qq_test.bat`；该入口默认打开接入页，失败时保留报错窗口。
它不同于 `start_akane_local_test.bat`：后者使用 `11999` 端口且关闭 QQ，供不接 QQ 的本地桌宠测试。
两个入口都不连接云端 Bot，但已配置的远程模型服务仍需要联网。

默认本地测试配置的后端端口为 `12001`，OneBot 为 `3003`。
没有绑定本地 QQ 启动配置的桌宠会明确提示缺少配置，不猜测账号或使用云端密钥。
启动脚本仍负责原有的本地实例初始化与依赖契约检查，不因为此次 UI 改动跳过这些检查。

1. 检测当前启动配置指定的 NapCat，或通过原生目录选择器选定可信安装。
2. 点击「配置并启动 NapCat」；已经运行时不重复启动，不自动杀进程。
3. 点击「打开扫码登录页」，由用户在 NapCat 页面扫码并处理认证。
4. 点击「重新检查」，读取后端真实自检并核对实际登录 QQ 与本地目标账号。
5. 自检通过只确认 OneBot 可访问、QQ 在线且账号匹配；双向消息收发仍需单独实测。

首次登录尚未生成账号的 OneBot 文件时，只启动以供登录，不伪造配置文件结构；
登录后需要退出这份 NapCat，再配置并启动。已有进程的配置不匹配时也是明确提示退出重启，
不会静默重配正在运行的 QQ。登录页端口被其他服务占用或由 NapCat 自动改动时，
本版报告端口冲突，要求确认配置；不猜测其他端口上的 NapCat 身份。

## 边界与安全

### 目录归属：先认实例，再找角色

`start_akane_local_qq_test.bat` 对应 `local-qq-test`，默认资料根为
`%LOCALAPPDATA%\Akane\local-qq-test-runtime`。启动输出会列出本次实际角色库；
如果传了 `-DataRoot`，以输出为准。角色工坊「打开角色包目录」打开的也是这个实例的目录。

| 位置 | 作用 | 是否影响当前本地 QQ |
| --- | --- | --- |
| 当前资料根 `characters/<角色ID>` | 当前实例安装并使用的角色包；日常编辑以这里为准 | 是，选择该角色后使用 |
| 项目 `desktop_pet_creator_kit/characters` | 角色制作源包、示例，不是当前实例实时读取目录 | 否，需要明确导入 |
| 当前资料根 `napcat/shell-v4.18.19` | 默认 NapCat 安装位置；也可由接入页选择其他可信安装 | 仅 QQ 接入，不放角色包 |
| `%LOCALAPPDATA%\Akane\local-test-runtime` | 无 QQ 测试实例 | 否 |
| `%LOCALAPPDATA%\Akane\satellite\personal` | 云端伴随桌面实例的本地资料 | 否 |
| `%LOCALAPPDATA%\Akane\characters` / 自定义 DataRoot 目录 | 其他或历史启动配置的资料 | 不能据目录名称推定；以对应启动实例为准 |

命名实例仅在首次空库时播种示例，不会持续合并制作目录，以免覆盖已编辑的角色。
后来新增的塞西莉亚等角色需在**当前实例的角色工坊导入**。导入不切换角色、不搬迁记忆。
命令行等价方式为 `node desktop_pet_creator_kit/scripts/import-character-pack.mjs <zip> --to <当前资料根>/characters`；
不要省略 `--to`，省略时是导入制作工具目录。跨盘导入也先在目标盘暂存、验证，再原子移入。

不要通过逐个复制到所有 `characters` 目录来找“哪个生效”，也不要未经核对清理旧目录。
日常修改当前实例内的包；要回填制作源包时显式导出、核对版本，不能把两处都称为“当前包”。

- UI 组件只渲染数据；通过既有动作路由、数据源与原生 `local_qq_setup` 命令执行本机动作。
- Rust 主入口仅增加模块、命令注册和可选启动页分支；未改旧 Electron、兼容 settings 页、CSS、角色或提示词实现。
- 原生命令只接受 settings 窗口，校验当前 host、所选 Bot、启动 Bot 与 loopback 后端绑定；
  不接受 UI 任意传入安装路径、命令、登录 URL 或密钥。
- 选择目录后和异步探测后再次检查绑定。前端操作串行，切 Bot、停止与迟到响应失效；
  取消、失败、慢响应和账号不匹配都不显示已连接。
- 配置来源仍是本次桌面进程继承的 QQ 启动环境。只更新原有
  `akane-local-qq-api` / `akane-local-qq-webhook` 两项，保留其他服务的连接。
- 写入前保留原始配置备份，临时文件写完并同步后 rename；不覆盖已有恢复备份。
- 安装子路径规范化后必须位于选定根内。原生探测只访问 loopback，禁用 HTTP 代理和重定向，
  有超时及响应体上限，并检查 NapCat WebUI 页面标识。
- 私密登录链接由原生宿主直接交给系统浏览器，不进入 renderer 状态、模型历史或日志。
  系统浏览器可能保留本地登录链接，用户仍应保护本机浏览器访问权限。
- 目录选择只存桌面私有状态；公开结果白名单不携带目录、token 或登录 URL。
- 后端自检不再用配置的 QQ 代替缺失的实际登录身份；缺失时返回 `account_identity_unknown`。
- 原有 QQ 自检仍走后端通道，不受本地扫码向导限制，保留远端 Bot 自检兼容。
