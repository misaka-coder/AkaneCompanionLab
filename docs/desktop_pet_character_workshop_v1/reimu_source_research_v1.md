# 博丽灵梦原作资料建设 V1

Status: research baseline
Scope: source acquisition, evidence extraction, characterization synthesis
Runtime impact: none in this slice

## 1. 当前结论

现在不应直接写一份“最终灵梦提示词”。

现有 `desktop_pet_creator_kit/characters/reimu/character.json` 更接近一份桌宠化
演示设定，其中混合了：

- 可以确认的基础身份；
- 尚未附带来源的原作印象；
- 为陪伴产品新增的 adaptation；
- 常见二创中容易被放大的标签和口头禅。

如果直接把这些内容扩写成长提示词，模型会变得稳定，但稳定的是创作者印象，
不一定是原作中的灵梦。

正确顺序是：

```text
合法取得原作
  -> 建立来源登记
  -> 按场景记录可观察行为
  -> 归纳带反例的角色主张
  -> 建立关系、事件和话题立场
  -> 编写角色核心提示词
  -> 用 OOC 问题回归
```

## 2. 现有人设审计

### 2.1 可以暂时保留

- 姓名与博丽巫女身份；
- 以异变和幻想乡秩序为核心的知识域；
- 桌宠角色包 ID、立绘、布局和声线等产品配置。

这些基础事实仍应在正式资料中补充来源引用。

### 2.2 必须标为桌宠改编

- 与当前用户的陪伴关系；
- 偶尔称用户为“主人”；
- 提醒工作、休息和熬夜；
- 不会抛下用户、守在用户旁边等陪伴承诺；
- 主动唤醒和点击台词。

这些可以成为好的 adaptation，但不能被描述为原作事实。

### 2.3 不能未经研究直接写进角色核心

- “穷但有尊严”；
- “爱喝茶”；
- “偶尔撒娇”；
- “毒舌”；
- “关键时刻一定可靠”；
- “提到钱和供奉就会积极”；
- 固定反复说“真麻烦”“先喝口茶”“供奉呢”等句子。

这些印象可能有原作支持，也可能只在特定作品、情境或二创中突出。研究阶段
需要记录支持场景、反例和适用条件，不能先把结论写死。

当前 `persona.md` 是生成模板，不是灵梦资料，应继续禁止进入运行时提示词。

## 3. V1 原作范围

建议第一版采用：

```text
Windows 时代官方作品为主体。
以 ZUN 创作、编剧、原作或明确参与设定的作品为依据。
PC-98 时期单独标记，不自动与当前人格合并。
官方授权二次创作不作为原作人格证据。
```

原因：

- PC-98 与 Windows 时代存在表现和设定边界，直接混用会制造假连续性；
- 授权作品可以提供产品设计参考，但其角色描写仍可能是二次创作者的解释；
- 先限定范围，关系和事件发生冲突时才有可执行的裁决规则。

每条记录都应保存 `canon_scope`，例如：

```json
{
  "canon_scope": "touhou_windows_official",
  "continuity_note": "不自动包含 PC-98 和授权二次创作"
}
```

## 4. 来源优先级

### S0：原作游戏内资料

优先收集创作者合法持有的：

- 角色设定文档、附带说明和手册；
- 灵梦路线的开场、关卡前后对话和结局；
- 符卡、能力与系统说明；
- 同一人物在不同路线中与灵梦互动的差异。

游戏对“遇到事情时她怎么说、怎么判断、怎么行动”最直接。不要只提取剧情
梗概，还要保留对话发生的对象、压力、目的和结果。

### S1：官方出版物

优先研究灵梦日常行为和长期关系较丰富的作品：

- 《东方茨歌仙》；
- 《东方铃奈庵》；
- 《东方三月精》系列；
- 《东方儚月抄》；
- 其他由 ZUN 担任原作、编剧或作者的官方出版物。

出版物适合观察神社日常、人妖边界、钱与经营、魔理沙和紫等长期关系，但每条
结论仍要记录作品、卷数、话数和具体情境。

### S2：ZUN 的访谈和作者说明

用于理解创作意图、世界观边界和角色设计原则。作者访谈不能替代作品中的实际
表现，也不应被改写成角色亲口说过的话。

### I0：索引和导航资料

可以使用 THBWiki、Touhou Wiki、角色索引站等资料寻找：

- 出场作品；
- 日文名、别名和称号；
- 设定文档位置；
- 可能相关的章节和访谈。

百科只负责“带我们找到原作”，不直接负责最终裁决。任何重要人格结论都要回到
可识别的原作来源。

### N0：非原作参考

授权游戏、语音产品、同人作品、视频解说和社区共识只能标为：

```text
adaptation_reference
```

它们可以帮助设计桌宠动作、声音和交互，但不能证明灵梦在原作中的稳定人格。

## 5. 可取得资源

目前可行的合法入口包括：

- Steam 上由上海爱丽丝幻乐团作为开发者发布的多部原作；
- BOOK WALKER 等正规电子书渠道中的东方官方漫画和出版物；
- 东方 Project 25 周年角色站，用于作品与角色导航；
- 东方我乐多丛志、东方夜话新闻中的 ZUN 访谈和官方信息；
- 创作者自己合法持有的实体游戏、书籍和杂志。

部分早期原作、绝版刊物和日文材料确实不容易取得。V1 不追求一次收全，而是
要求明确：

- 已研究哪些作品；
- 哪些作品尚未取得；
- 当前结论覆盖到哪个时期；
- 哪些问题只能回答“不足以确认”。

## 6. 本地研究账本

研究资料与运行时 `lore/` 分开。建议私有工作目录：

```text
desktop_pet_creator_kit/characters/reimu/research/
  manifest.json
  sources.jsonl
  observations.jsonl
  claims.jsonl
  relationship_claims.jsonl
  conflicts.jsonl
```

`research/` 默认不进入公开导出包。运行时只消费经过审核、重新表述后的
`lore/` 记录。

### 6.1 来源记录

```json
{
  "id": "source_example",
  "title": "作品名",
  "source_type": "official_game",
  "creator_role": "ZUN",
  "canon_scope": "touhou_windows_official",
  "edition": "合法持有版本说明",
  "language": "ja",
  "review_status": "pending",
  "notes": ""
}
```

### 6.2 场景观察

观察记录描述“发生了什么”，暂时不写“她本质上就是怎样的人”。

```json
{
  "id": "obs_example",
  "source_id": "source_example",
  "location": "路线、关卡、卷数或话数",
  "participants": ["reimu", "other_entity"],
  "situation": "当时面对的问题、风险和目标",
  "observable_action": "灵梦实际做出的行动",
  "speech_features": ["简短", "直接"],
  "attitude_signals": ["警惕", "不耐烦"],
  "outcome": "行动或对话的结果",
  "possible_interpretations": ["解释 A", "解释 B"],
  "short_private_excerpt": "",
  "review_status": "observed"
}
```

不要把完整游戏脚本或整章漫画复制进角色包。必要的短摘录只留在私有研究记录，
运行时使用自己的事实摘要和行为归纳。

### 6.3 角色主张

```json
{
  "id": "claim_example",
  "subject_id": "reimu",
  "claim": "限定情境下的角色规律",
  "applies_when": ["情境条件"],
  "does_not_imply": ["容易被错误扩大成的结论"],
  "supporting_observation_ids": ["obs_a", "obs_b"],
  "counter_observation_ids": ["obs_c"],
  "confidence": "medium",
  "truth_mode": "inference",
  "review_status": "draft"
}
```

正式提示词应主要来自审核后的 `claims.jsonl`，而不是直接来自百科段落或单句
台词。

## 7. 灵梦研究矩阵

### 7.1 人格与行为

- 懒散、不耐烦和认真履职分别在什么情境出现；
- 她如何判断某件事是否值得处理；
- 面对危险、异变、弱者、熟人和陌生人时有什么差异；
- 直觉、规则、责任和个人好恶如何共同影响决定；
- 她的温柔是语言表达、实际行动，还是后来解释出来的印象；
- 钱、香火、神社经营在她的优先级中究竟处于什么位置；
- 她何时会开玩笑、威胁、敷衍、追问或直接动手。

### 7.2 人际关系

第一批至少覆盖：

- 雾雨魔理沙；
- 八云紫；
- 茨木华扇；
- 东风谷早苗；
- 森近霖之助；
- 博丽神社常客、人类村落与普通妖怪。

每段关系分别记录：

- 对对方的称呼；
- 平时相处模式；
- 冲突点和信任边界；
- 共同经历；
- 对方遇险或违反规则时的反应；
- 关系在不同作品时期是否发生变化。

不能只写“朋友”“宿敌”“互相嫌弃”这种标签。

### 7.3 语言风格

统计并归纳：

- 句子长短和信息密度；
- 陈述、反问、命令和调侃的比例；
- 对熟人、神明、人类、妖怪和敌人的语气变化；
- 认真办事时与神社日常时的差异；
- 哪些说法只出现一次，不能升级为口头禅；
- 哪些中文表达来自翻译风格，而不是日文原文的稳定特征。

原作没有统一官方声线。授权产品的配音表演不能反向证明她在所有原作中的语气。

## 8. 归纳门槛

建议采用以下规则：

- 单一明确场景可以支持一个具体事实；
- 稳定人格主张尽量需要两个以上不同场景；
- 重要主张必须主动寻找反例；
- 有反例时优先写成条件规则，不写绝对形容词；
- 漫画日常表现与游戏战斗对话都要覆盖，不能只取一种状态；
- 翻译造成的语气差异必须保留日文来源位置供复核；
- 社区常见印象只有在原作证据支持后才能进入 `inference`；
- 没有足够证据时保持 `unknown`，不为了提示词完整而补写。

例如，不要直接写：

```text
灵梦很懒，但关键时刻绝对可靠。
```

应归纳为类似：

```text
她在没有明确职责或收益的日常琐事上容易嫌麻烦；一旦把事情判断为异变、
神社职责或会破坏幻想乡平衡的问题，行动会明显变得直接。
```

这仍然只是待证主张，必须由多个原作观察记录支持后才能进入角色核心。

## 9. 第一轮最小语料

不要一开始研究全部作品。第一轮建议：

1. 三部创作者合法持有、灵梦可操作的官方游戏，覆盖不同年份；
2. 《东方茨歌仙》，观察神社日常、华扇和经营话题；
3. 《东方铃奈庵》，观察人妖边界、村落和小铃；
4. 《东方三月精》或《东方儚月抄》，补充魔理沙、紫和神社日常；
5. 一到两篇与灵梦设计直接相关的 ZUN 访谈。

第一轮目标不是“读完东方”，而是获得：

- 60 条左右可复核场景观察；
- 20 条左右带条件和反例的角色主张；
- 6 到 8 段主要关系记录；
- 20 个容易诱发二创刻板印象的 OOC 测试问题。

达到这个规模后再写第一版角色核心，质量会比先写数千字百科式提示词可靠得多。

## 10. 进入运行时的规则

研究记录进入正式角色包前必须：

1. 去掉大段原文，只保留自己的事实摘要；
2. 保留稳定 `source_refs`；
3. 标记 `official`、`inference` 或 `adaptation`；
4. 将人格规律写成带情境的行为规则；
5. 将人物关系拆成有方向的关系记录；
6. 将桌宠陪伴设定明确放在 adaptation 层；
7. 为高风险刻板印象增加反例测试。

最终固定提示词只放高置信度角色核心。作品事件、关系细节和具体事实仍通过
`character_lore_prompt_v1.md` 设计的动态检索进入每轮对话。

## 11. 公开与版权边界

- 只研究创作者合法取得的原作；
- 不把完整脚本、整章漫画、破解资源或未经授权翻译打进角色包；
- 私有短摘录仅用于核对，不进入 prompt、日志或公开导出；
- 公开包保存来源编号、位置和自行撰写的摘要；
- 角色包、立绘、语音和商业发布仍需分别遵守东方 Project 二次创作指南及素材许可；
- “官方授权二次创作”不等于“原作正史”。
