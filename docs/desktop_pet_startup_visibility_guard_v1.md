# 桌宠启动失败时的窗口保护

验证日期：2026-10-04。

## 问题与排查

桌面入口 `启动Akane本地QQ（独立记忆）.bat` 使用持久化的
`local-qq-test` 配置。此次异常表现为桌宠进程和透明置顶主窗口存在，
界面没有显示，也没有在该实例下留下界面就绪标记；窗口遮挡了桌面点击。

排查时后端健康检查正常。当前源码的真实入口浏览器检查通过，关闭异常
桌宠进程后，通过同一桌面入口启动，立绘与后端连接恢复。最初导致界面
没有初始化的触发条件未稳定复现，不将其归因于记忆、角色图片或后端故障。

另有两项已经确认的启动保护缺口：

- 等待界面失败或超时会报错，但保留异常进程及其透明窗口。
- 重复启动只确认进程存在，随后激活窗口并返回，没有核对界面就绪状态。

## 修复

- 主窗口默认隐藏；主界面报告可显示状态后才展示。直接启动时，界面能
  报告的失败状态仍可显示供诊断；启动器会处理失败回执并清理异常进程。
- 初始化尚未完成时，桌面激活事件不能把隐藏的空窗口显示出来。
- 等待失败或超时时只停止本次等待的桌宠 PID，并核对进程启动时间，
  防止误停已经复用该 PID 的其他进程。保留后端、设备执行器与实例数据。
- 重复启动也检查相同实例、相同 PID 的就绪标记，再激活现有窗口。

没有迁移或删除独立记忆，没有修改活动角色或 QQ 配置。

## 验证

- 旧版真实进程夹具复现：缺少就绪回执、明确失败回执都留下未就绪进程。
- `tests.test_desktop_startup_guard` 覆盖正常就绪、失败原因、无回执、损坏
  JSON、错误实例、错误 PID、进程已退出；失败清理不影响旁边的独立进程。
- 上述测试与本地启动器、公共入口测试合计 19 项通过。
- `pet-runtime-smoke.mjs`、`pet-runtime-browser-smoke.mjs` 通过；浏览器检查
  使用真实入口和 DOM，界面初始化、交互和重新进入均无页面错误。
- `npm run tauri -- build --no-bundle` 通过，包含前端生产构建。
- 在隔离目录启动真实 release 程序，禁用页面脚本并使用独立 WebView2
  数据目录：主窗口保持隐藏，激活事件仍不能显示它，超时后进程被清理。
  窗口可见性按该进程的具名主窗口检查，避免把系统辅助窗口当成桌宠。
- 使用原桌面入口启动新版，立绘加载、界面就绪与后端连接恢复；最终启动
  使用普通配置，没有保留临时远程调试参数。
- 再次点击同一桌面入口，检查就绪标记后激活原窗口，主桌宠 PID 保持
  不变，没有产生第二个桌宠窗口。

检查不发送测试 QQ 消息或模型请求。本轮验证解决窗口残留与启动成功
判断的问题，不声称已经复现最初的 WebView2 卡住条件。
