# 下一轮：做完整的一段陪伴体验

详细设计见 [互动剧情与演出设计 V2](interactive_story_v2_design.md)（2026-09-20，待评审）；本文保留上一轮的方向与收口记录。

更新：2026-09-19。保留当前 Vue / TypeScript / Pixi / Tauri 技术栈，继续复用宿主的模型、记忆和养成服务。

## 本轮收口

- 退出、停止剧情回复会释放前端忙碌状态，丢弃迟到响应，并通知宿主取消生成。
- AUTO 的一次播放完成只自动通知一次；推进失败后由用户点击重试，避免每帧重试。
- 同一剧情节点的重复请求共用生成任务；不同输入并发时明确返回忙碌。
- 结局事实只进入统一 outbox，使用同一 source_id 重投；明确标注尚未确认送达，实际展示和语音仍以 delivery 回执为准。
- 本次演出保存剧本副本；新导入的版本用于新演出，不悄悄替换已有存档路线。背景、音乐延续到后续节点，除非节点指定替换。
- 固定剧情阶段的输入框解释点击推进方式；AI 节点开启输入；说话人和背景名称跟随剧情。

验证以现有测试、类型检查、构建和已复现问题的短行为探针为主，不为低概率情况扩展大型测试矩阵。原生窗口、实际 TTS / BGM 听感和 Windows 缩放仍需桌面验收，不能用浏览器通过替代。

## 1. 先做一段 5–10 分钟的完整体验

以现有夜间小屋为样例：进入房间 → 收到自然邀请 → 一个固定演出段落 → 玩家选择或自由回应 → 一次真实投喂或换装 → 角色反馈 → 结局 → 返回日常。

重点不是增加节点数量，而是让用户不读教程也知道下一步：何时点对白、何时输入、何时做选择、如何退出和继续。剧情内触摸、换装、投喂的反馈需要明确的插入与恢复规则，避免覆盖正在播放的剧情。

验收：完整走一遍主线和另一条分支；中途离开后能继续；失败可重试；真实库存/装备变化与角色反馈一致。

## 2. 沿着这段体验打磨视觉和声音

收敛入口文案，突出角色与对白；调整选择卡片、结局卡和抽屉层级，避免遮住需要阅读的对白。夜景使用合适的角色亮度和界面对比。接好逐句表情、语音、BGM 压低与恢复，确认点击和 AUTO 的节奏舒服。

验收采用 1280×800 主尺寸和 1024×720 小窗口各一次浏览器检查；原生音频和 DPI 留给真实桌面体验。只针对看到的问题改，不预先搭建大型主题系统。

## 3. 再降低内容制作成本

用现有 Markdown 剧本和资源导入完成第二个短故事。补清楚素材名称、缺失资源提示、导入后的预览与新版本生效时机。先把“导入就能用”做顺，再决定是否需要可视化剧情编辑器。

实现继续拆在 story / presentation / stage / bridges 等已有模块中。新增功能不继续堆入 engine.py、main.rs 或 workshop.js；只在真实重复出现时抽取共享模块。

## 暂不展开

多角色舞台、Live2D、任意走位、大型剧情编辑器与插件市场等，等上述完整体验得到实际反馈后再排序。
