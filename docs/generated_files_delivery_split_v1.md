## 真实调用链与资源归属

实现仍接收原来同一个 `GeneratedFileService`，通过它访问既有存储、附件服务、路径解析和内容卡片，不新增资源存储或状态副本。跨模块共用的名称歧义格式化使用明确的包内导入，其余已有服务调用保留，没有反向导入兼容入口或运行时方法注入。

公开服务方法的私聊资源 scope 装饰器和 QQ 会话范围保留。目标解析继续只读，只有发送准备才将生成物登记为待交付；实际 QQ/桌宠交付仍在既有工具事件及下游运输层。原始附件与持久项目文件的所有权、安全路径解析及文件登记服务保留。

正文续页仍由 `InspectGeneratedFileToolHandler`、既有 `gf` 游标和用户/会话绑定处理。本轮只修复提取窗口及失败结果，不改变游标协议、页预算或来源变化检查。现有超过 4M 字符 JSON 的完整续读和来源变更拒绝检查继续通过。

## 同轮复现与修复

1. 损坏 ZIP 的异常被写成正文，并由检查入口返回成功，可能把异常中的内部路径带入提示。现在 ZIP 失败统一抛出稳定的 `GeneratedFileReadError`，服务及工具返回 `generated_file_read_failed`，不发布成功检查事件。选定成员不存在或模糊匹配有多个候选时也拒绝读取，要求使用明确的成员路径；默认 ZIP 概览仍可回退到文件列表。
2. 缺少 Word、Excel 或 PDF 解析器时，原逻辑返回“缺少依赖”的文字并当作已读正文。现在返回同一稳定读取失败，不把状态说明冒充文件内容。
3. 普通文本先全量解码再截断，ZIP 成员也会整份解压再截断。现在两者共用按字符预算读取的前缀解码，只读取提取预算外一个字符来判断后续内容，保留 BOM、GB18030、换行及小型 JSON 成员的格式化。ZIP 二进制成员仍提供元信息，不解压写入磁盘。
4. Word、Excel、PDF 在恰好碰到提取预算时提前停止，后续正文可能被误判为已结束；PNG 内嵌文本也少读了一个探测字符。文档共用增量字符计数与窗口，PNG 内嵌文本保留同样的探测字符，真实 Word/Excel/PDF/PNG 的续页能覆盖边界后的最后标记。PNG 读取仍限于内嵌 `Description` 文本，没有新增 OCR。
5. 长文件的 `tail` 原先取得前部提取窗口的末尾。现在普通文本流式扫描到 EOF，只保留末尾窗口；Word/Excel/PDF 从同一文档行生成器保留实际末尾，PNG 从内嵌文本取末尾。Office/PDF/PNG 的末尾检查直接走对应读法，减少重复前缀解析。
6. Excel 正常读完、提前返回或行读取失败时都没有明确关闭工作簿。现在读取在 `finally` 中关闭行生成器及工作簿；PDF 的源文件也由上下文管理，正常/提前返回和解析失败后都释放句柄。
7. 归档/删除后的数据库更新返回空值时，原逻辑构造一个“已移除”记录当作成功；更新异常也会直接抛出。现在仅把确认更新后的记录计入成功，返回 `record_update_failed` 和不含异常正文的原因类别，保留部分成功及可重试失败。已删除本体但记录更新未确认时，失败项如实带 `file_deleted=true`，分别说明两步结果。
8. 文件在存在性检查与 stat/unlink 之间消失时，可能抛异常或误报删除失败。解析现在返回既有 `missing_on_disk`；删除阶段发现文件已消失时，按“本体已缺失”继续归档记录，保留 `file_already_absent`，不声称本次删除了文件。

新增 `tests/test_generated_file_delivery_boundaries.py` 的 22 项检查使用真实临时文本、压缩包、Word、Excel、PDF、带内嵌文本的 PNG、生成文件存储和工具调用。只在文件消失、依赖不可用、解析失败及数据库失败处注入可控故障。首批 19 项在修复前复现 18 个失败方法；PNG 精确边界续页的补充用例也先复现丢失末尾，再确认修复。
