目标与依赖以[优化方案](plugin_system_optimization_v2.md)为准；以下只记录已进入真实调用链的切片。

## P0a：完整 JSON 与模型预览

2026-09-08，代码与本片验证已完成；正在运行的实例尚未重启加载。

### 用户和作者会感受到的变化

- 查询结果不再因超过 64 项、4096 字符或 64 KiB 而直接报错；`token_count`、`/help` 和操作路径能够正常返回。
- 标量 `0/false/null` 不再被展示成空返回；名为 `content` 的业务字段不再被当成 MCP 内容块，其他字段不会因此消失。
- 程序取得完整 JSON；模型先看有明确完整性标记的预览。过长内容存入当前会话既有文件库，返回真实句柄；通过 `inspect_generated_file` 续读同次结果，不重新执行工具，不自动发送文件。
- JSON 材料沿现有文件管理生命周期保存；删除/清理后不能继续读取，会返回现有文件不可用状态。本片没有另建结果数据库或自动过期机制。
- 连接接口已提供的私密值按插件代次记录，禁止原样混入公开结果；普通字段名与路径不再被用来猜测是否保密。插件仍必须遵守公开输出契约，此检查不是恶意代码沙箱。

### 实现与旧路径收敛

`plugin_result_projection.py` 仍是所有 Host 消费入口的 JSON 快照权威，删除旧内容猜测和通用小上限。循环引用、非法键、非有限数字、不可编码值等分别返回 `code/message`，不统一伪装成 `plugin_result_not_safe`。

`plugin_result_presentation.py` 只协调模型预览和现有 `GeneratedFileManagedArtifactSink`，没有自己的目录或存储实现。BotRuntime 将该 sink 绑定到现有插件 bridge。预览预算使用启动配置 `AKANE_PLUGIN_RESULT_PREVIEW_CHARS`，默认 16000 字符；它约束展示正文，不改变程序值，续读说明另附。没有存储或存储失败时明确 `complete=false`，不编造句柄、不重跑动作。

接入时发现并修复了原有文件续读的问题：

1. 第一页把“内容已截断”提示计入原文偏移，续读会跳过少量正文；现在正文与提示分开。
2. 固定 400 万字符提取窗口可能被当成全文终点；现在按当前读取位置扩展窗口，并保留下一字符判断是否还有内容。
3. 读取提示要求“不要重复调用”，而 cursor 又要求继续调用；现在提示只要求依据已读证据回答。
4. 正文读取异常被拼成正文返回，可能带出存储路径并显示为成功；现在进入既有结构化工具失败链，不把异常文字当作文件内容。

旧 `CapabilityResult` 和 `PluginResultPayload` 形状继续可用；经验字段自己的声明限制、v1 保留元数据键和权限规则仍存在。`MAX_PLUGIN_RESPONSE_BYTES` 兼容导出为 `None`，表示不再有该通用上限。

### 验证内容

- Host 与 HTTP 的长中文、长列表、深层 JSON、特殊字段、标量和非法 JSON；结果快照与原对象隔离。
- 真实 worker 跨进程返回超过旧预算的数据；连接真实值混入普通键，以及下次调用回传缓存凭据，均返回明确错误。
- 工具 bridge → 真实 JSON 材料 → 原有读取工具连续分页，拼回结果与原值一致；续读不增加原插件调用次数，跨会话不能读取同句柄。
- 超过 400 万字符的 JSON 连续分页无丢失；原文件变化后旧 cursor 失效。
- 存储失败保留实际动作状态，并在模型结果中报告展示不完整；没有假发送、假完成。

## P0b-2：统一输入、输出 Schema 与规范结果值

### 用户和作者会感受到的变化

- 完整 `input_schema` 可表达嵌套对象、数组、组合条件、枚举和内部引用；
  同一份声明经过真实 worker、原生工具投影和执行门禁，复杂约束不再被静默丢弃。
- 输入错误在执行前指出字段和约束；声明错误在激活、源码/安装包预检以及
  `manage_extension` 的模型结果中携带 `schema_errors`，作者能找到需要修正的位置。
- 成功结果的 `value` 保存输出 Schema 对应的规范 JSON，`content` 保持 V1 展示兼容。
  `0/false/null`、数组、体验提示和文件产物不会互相改变业务返回类型。
- 输出不符合声明时明确返回 `plugin_result_schema_mismatch`、

- 原生 OpenAI/Anthropic 调用保留独立的原始参数对象，业务字段 `type`、
  `arguments` 和 `_tool_*` 不再因内部调用封装而被覆盖、错误展开或丢弃。

### 收敛与兼容边界

CapCore 删除旧的两套递归子集校验，legacy slots 只转换为同一 JSON Schema。
声明采用自包含引用，不触发网络取 Schema；未知普通关键字、非法约束和无法解析的
引用均明确拒绝。`format/default` 按默认词汇表作为注解，不伪称执行了格式校验或
补默认值。字符串是否可空由 `minLength/type` 决定，`required` 只表达字段存在。

`outputs` 继续描述文件交付元数据，不能据此猜测业务输出对象；作者用显式
`output_schema` 声明规范值，未声明时允许合法 JSON。结果值在 Host 及跨进程
文件回填时保留，正式程序组合入口将在 P1 使用它。

V1 的同步 `model_followup=optional` 会注入宿主参数 `finish_turn`，无法保持任意
完整 Schema 的内部引用、封闭对象和同名业务字段。完整 `input_schema` 与该模式
混用现在会在激活时定位报错；默认 required 模式可正常使用，旧 slot 模式保留兼容。
这是到 P4 结果级 followup 的明确迁移窗口，届时必须删除该限制及被替代的注入路径。

## P2a：执行作用域撤销 repair pass（已验证）

准备异步事件链路时发现：旧调用任务可以捕获取消，宿主直到工作进程返回才撤销
反向调用作用域；等待清理期间可能再启动依赖。按工程护栏先修复这一点，P2 事件
发布本身仍未完成，不能把本片当作“两个插件事件→动作”的验收。

现有 `ResourceInvocation` 增加立即撤销与受监督执行，继续作为唯一调用作用域。

  `cancelled` 分别投影为公开运行/暂停/终态；generation 或 invocation 失效时返回
  `stale`，不另建任务数据库、调度器、权限系统或模型循环。
- `ActivePluginGeneration` 在代次切换和宿主停止时主动调用 Task 撤权监听；旧代运行中
  任务被标记为 `plugin_task_generation_revoked` 并收尾，迟到的旧代请求只能得到
  `task_generation_expired` 的终态回执，不能复活任务。
- 新增 `examples/plugins/akane_sdk_turn_game`：创建游戏并登记 Task，发布
  `game.state_changed`，通过 Observation/Timeline 记录状态，只有
  `request_game_turn`/`resume_game` 显式请求正常 Agent 回合。`submit_action` 必须带
  当前业务 `state_version`；过时动作返回 `stale`、`side_effect_applied=false`、
  当前状态和 `next_action=observe_state`，不改变局面。暂停、恢复、取消、胜负、
  结束态门禁和重复事件 `event_key` 幂等均由插件真实处理。
- `Event.version` 只标识宿主签发的事件流；游戏 `state_version` 由领域状态维护，
  两者在示例回执和测试中分别读取。事件/观察/时间线不会隐式请求模型；模型回合仍
  通过既有会话队列和真实 `TurnReceipt` 入口。

## F2：可恢复 Task 与合作式暂停边界（2026-09-10）

F2 将 F1 的 Task 从“当前 worker 仍在内存中即可控制”推进为诚实的可恢复契约，仍然只复用
`HostJobStore`，没有新增 task 数据库、调度器、权限系统或模型循环。

- `HostJobStore` 新增 JSON checkpoint、业务版本、内容指纹、checkpoint 代次和更新时间，
  以及 `recovery_state`/`recovery_reason`/恢复轮次和恢复所有者轮次。写入在 SQLite 事务内完成：
  同版本同值幂等，同版本不同值返回冲突，旧版本返回 stale，乱序请求不能覆盖新 checkpoint。
  checkpoint 同时校验 task、profile/session/character-pack scope、plugin_id 和 generation_id；
  错误会话、角色、插件、代次不能读取或推进它。写入失败不会把仍在运行的 Task 伪装成终态，
  生命周期仍由 `status` 表示，具体写入结果由 `reason` 表示。
- SDK 新增 `TaskHandle.checkpoint()`、`checkpoint_status()`、`TaskContext.open()` 和
  `pause_at_boundary()`。回执公开 checkpoint metadata。宿主/worker 重启后，失联 claim 投影为
  `recovery_unknown`；每次新的重启都会开启新的恢复轮次，新的 generation 可以在原子交接中
  接管，旧 generation 仍被 fencing。不自动重放未知副作用；插件必须显式打开、读取最新
  checkpoint、resume 并重新声明 running，才可以继续。恢复不会重发旧模型回合、旧动作、
  Timeline 或 completion 事件。
- Task pause 现在区分 queued pause 与运行中合作边界。普通/不可合作执行器返回
  `pause_unavailable`，不会伪报 `paused`。声明 `pause_mode="cooperative"` 的插件必须先写
  checkpoint，再由执行器到达无未确认副作用的安全边界并调用 `pause_at_boundary()`；恢复从
  最新 checkpoint 开始，领域版本仍由插件校验。运行中 `cancel()` 只请求停止并返回
  `cancelling`，执行器必须在安全边界以 `update(status="cancelled")` 确认；已开始的副作用
  仍可报告真实 `completed`/`failed`，撤权后的迟到完成会被 fencing。
- 回合制游戏示例已经把业务 state 写入 checkpoint，支持在新 worker 里按 task_id 显式恢复，
  并继续保持 `state_version` stale 防护和 event-key/timeline 幂等，不自动恢复旧回合。

## P14f — F 片：F2 任务恢复、隔离与控制语义（2026-09-10）

提交 `f32a8fda`。三个独立缺陷：

1. **恢复无法二次接管**。`adopt_recovery` 用只在丢失声明时才推进的计数比较已记录
   所有者，于是“接了这一轮但还没 claim 就崩溃”的世代会把任务永远留在
   `recovery_unknown`。现在所有权记录为显式轮次 `recovery_owner_round`：真实丢失
   claim 时预订下一轮，未被 claim 的轮次只允许交接一次，持有 claim 的所有者永不
   被抢占。新增真实子进程两次重启 + 一次交接的回归。
2. **请求失败与任务终态混淆**。`task_rejection` 把 `task_generation_expired` 报成
   `complete=True`，被替换的世代会把仍在运行的任务当成已完成。现在 `complete` 只表示
   任务真的到达 `completed`/`failed`/`cancelled`，失去世代时返回
   `status="stale"`、`scope_expired=True`、`complete=False`；`cancel()` 只报
   `cancelling` + `cancel_requested`，只有插件自己确认边界才变成终态。
3. **任务作用域缺角色维度**。`create`/读/写/控制/恢复现在都要求同一
   `character_pack_id`，同一 profile+session 下换角色无法读取、写入或恢复他人任务。
