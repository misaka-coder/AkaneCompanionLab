# Care runtime 拆分

`companion_v01/care_runtime.py` 从 3055 行收敛到 178 行，保留 `CareRuntimeStore` 的静态模块组合、锁和存储路径，以及 `CareModulePort` 的启用边界和原有导入入口。配置、商品目录、状态存储、桌宠和 QQ 玩法、回合结算各有固定模块。

## 状态归属

- 身体状态按角色、会话存储；关系按角色、会话、成员存储；金币和库存按角色、用户存储。
- 启用主人私聊绑定且桌宠通过主人身份验证时，同一角色的桌宠和主人 QQ 私聊映射到 `master` 会话，共用身体状态及主人账户。
- 群聊、其他人的私聊、未验证的桌宠和不同角色仍遵循原来的隔离规则。绑定由 `owner_private_session.py` 与 `engine_services/desktop_care_pet.py` 决定，存储层不自行扩大共享范围。
- 本轮不变更状态归属、存储版本或迁移规则。

## 修复与验证

- 购买入库此前会记录事件回执，却没有在扣额度和入库前检查回执。现在重复购买返回 `duplicate`，重启后仍不重复执行；保存失败后同一请求仍可重试。
- QQ 购买、投喂和带物品供奉明确处理 `duplicate`。购买不再重复扣额度或增加库存；重复投喂不再缺少快照而报错；重复供奉不再生成“又消耗了物品”的模型互动事实。
- 移除了 3 处无用局部赋值，并纠正了购买入库注释中把“额度”写成“金币”的说明。
- `tests/test_care_inventory_transactions.py` 新增 6 项行为检查。修复前已复现重放、失败重试和 QQ 命令结果的问题，修复后通过。
- 一条旧供奉测试仍要求所有会话共享身体状态。使用拆分前的原始文件同样失败（`30 != 50`）；现已按既有会话归属校验同一会话内身体共享、成员好感独立、不同会话隔离。
