- 恢复云端 personal Bot 在 87 群识别当前图片、引用图片及合并转发的可靠性。

- 不创建每会话一个 venv；不把工作目录与 Python 环境绑定为一对一。

### 3. 本地环境盘点与最小绑定方案

1. 先盘点已知 Python 安装、项目 venv、插件指定环境和公共工具；需要扩大扫描范围时明确目录与成本。
2. 输出解释器位置、版本、关键依赖、兼容检查、当前使用者和已知占用；未知归属明确标记，不能据此删除。
3. 复用兼容环境，保持 Akane 宿主与第三方软件环境稳定；冲突时才新建环境。
4. 用户已选定非 C 盘管理根目录 `F:\AkaneRuntime`；运行环境、模型、下载缓存和临时数据分别核对实际去向。
5. 复用现有环境配置与执行入口，建立唯一明确绑定；避免再增加一套与现有配置冲突的权威来源。
6. 依赖准备先展示目标环境、来源、版本约束、预计空间（不可得时明说）及影响；批准后才执行。
7. 检测、安装、健康检查和真实插件任务必须使用同一选定解释器。

验收：环境 A 缺依赖、B 已有时，能够明确发现并验证 B，而不是误报“电脑未安装”；多个工作目录复用兼容环境；冲突不污染旧环境。系统程序如 LibreOffice/FFmpeg 按程序路径验证，不当成 Python 包处理。

### 4. 长任务状态与用户可见反馈

1. 依据第 0 步证据，确认缺口属于命令等待、进程脱离、状态续读、Job 终态通知还是桌宠展示。

3. 区分无输出但仍运行、等待用户操作、实际失败、已完成和状态未知。
4. 仅在有真实来源时展示下载量/百分比；状态反馈不依赖安装器持续输出文本。
5. 复查 PowerShell 文件属性查询的输出捕获，禁止把退出码 0 加空输出解释成文件不存在；可验证的文件大小、状态才是结论依据。

验收：覆盖静默命令、长时间下载、失败退出、超时、取消、切会话、重复触发、重启及子进程仍运行。已完成任务可回传到原会话；气泡/工具卡片与实际状态一致，不假成功、不无限显示处理中。
