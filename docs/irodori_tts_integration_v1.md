# Irodori-TTS 接入（2026-10-06）

本次接入通过现有 `tts` v1 插件服务访问官方 Irodori-TTS-Server，桌宠和 QQ 共用一份常驻模型。角色使用已注册的话者 ID，模型文件和本机部署路径仅保存在私有服务配置中。

## 表达意图与声音执行

- Irodori 的模型提示中，`utterances[].style` 是可省略的一句日语自然语言描述，通常 10～40 字，最多 80 字。描述本组台词的情绪、语气和节奏，不列举固定语气，也不要求 GPT-SoVITS 的参考音频映射。这是本项目的生成与执行约束；官方 caption 长度按 token 计算。
- 流式事件、当轮最终回复和原始记录保留完整表达意图，合成端不会将其写回为 `calm`。`style` 只作用于当前这组 `say`，不代表角色的长期状态。
- 给模型看的历史投影恢复为紧凑 JSON：非空 `say` 与自然语言 `style` 收起为 `[hidden]`，保留中文 `text`、整体与组内 `emotion`、旧 ASCII 短 `style` 标签和附加字段，已有 `memory_metadata` 对象收为 `{}`。原始输出及表达意图另存，空配音、缺失字段和沉默保持原义。显示记录版的渲染实现已撤回；冻结投影版本递增到 17，用于显式更新已有历史。稳定格式说明解释标记来源，并保留用户已修改的 `say` 描述。
- 每次完成回复时冻结一次历史 JSON，日常读取不重新渲染、不迁移。此前显式恢复旧投影并通过 MemCore 重建受影响的工具结算投影，保留原始消息、记忆标注和用户／工具载荷；模型曾输出的异常原文仍保留。后续沿用冻结历史追加。双语流式与批量配音跳过新旧占位台词；流式返回 `say_hidden` 诊断并保留原始字段。
- 双语要求与完整 JSON 示例置于稳定的客户端格式说明中。2026-10-07 增加宿主持久上下文说明：开启双语角色的会话首次准备回复时写入一次；MemCore 实际提交原始对话压缩后再写入一次。同一压缩代际重复回调或重启保持幂等，语义摘要单独压缩沿用仍可见的旧说明；普通对话和连续工具调用保持冻结历史前缀。已有临时 JSON 尾部提醒已移除。
- 快照说明 `[hidden]` 是系统为节省上下文收起过去字段原文的标记，原文另存；新回复的 `text` 写中文正文，`say` 写意思对应的完整自然日语台词，`style` 用简短日语描述当前这组台词的情绪、语气和节奏。工具沿用工具协议，最终回复使用当前客户端 JSON 示例。快照为宿主来源的 `material.runtime_context.voice_history_notice`，通过官方独立条目接口写入，模型只看到清楚的说明正文；既不伪装用户聊天，也不进入角色的自传记忆或检索索引。写入失败记录安全诊断，下一次实际开轮重试。
- Irodori 直接选择角色绑定的话者档案。合成端将有效的自由描述作为 `irodori.caption`，试用 `cfg_scale_caption=2.0`，保留 32 步、固定种子、原话者和连贯合成配置。这个强度是本项目的试用值。描述声音表达，不加载新话者或模型；具体听感仍需试听判断。
- 省略或空描述时沿用无 caption 合成。超过 80 字、旧式 ASCII 标签、`[hidden]` 与旧 `[archived]` 标记或含非法控制字符时也回到无 caption，并保留原始表达与回退原因；不截取半段表达，不填入统一的冷静语气。聊天协议既有 120 字接收上限保持不变，合成层的 80 字执行上限不写回原始记录。
- GPT-SoVITS 继续使用既有语气到参考档案的映射。塞西莉亚原有 13 个映射保留，便于切回。
- `X-Akane-Voice-Style-Requested` 与 `X-Akane-Voice-Style` 分别返回经过 URL 编码的请求描述与实际送入合成的 caption。它们记录执行条件，不证明输出声音已准确表达情绪。`X-Akane-Voice-Style-Fallback: true` 表示描述未应用，仍使用绑定的话者；`X-Akane-Voice-Style-Fallback-Reason` 保留回退原因。`tts` v1 增加可选的 `caption` 输入（最多 80 字），只接受 Irodori，旧调用形状与 GPT/Edge 路径保持兼容。

## 配置与启动

Provider ID：`provider.tts.irodori.local`，本机端点：`http://127.0.0.1:9890`。

声线档案示例：

```json
{"providerId":"provider.tts.irodori.local","enabled":true,"irodoriVoiceId":"cecilia"}
```

角色包 `voice` 示例（沿用既有安全路径检查和原子写回）：

```json
{"provider":"irodori","profile_id":"cecilia_irodori_calm"}
```

`cecilia_irodori_calm` 是档案 ID，不是模型提示中的语气枚举。Irodori 不需要新增 `speech_output.provider_styles`。双语输出继续使用 `text` 展示中文、`say` 合成日语。

安装 Irodori 官方项目和服务到相同的独立环境；在私有 JSON 配置中提供 `port` 和 `environment`，其中包括现有的本地 checkpoint、codec、voices 目录和默认声线。当前使用官方 Small INT8 权重，模型运算及 codec 为 BF16。服务预加载后真实合成一段日语，完成后才报告 ready，保留官方音频水印。

```powershell
scripts/start_irodori.ps1 -Python <Irodori环境的python.exe> -ConfigFile <私有server_config.json>
```

启动器复用已就绪服务；端口占用、启动失败和超时有明确状态，超时保留仍在准备的进程。不会自动下载模型或启动 Large。控制中心语音页可配置声线 ID、试听和绑定角色；保存成功与实际音频成功分开反馈。

## 调度与取消

桌宠沿用“播放当前段、预取下一段”的流水线。Irodori 按完整的 `utterances[].say` 连贯生成，不再套用 GPT-SoVITS 的 24 字短请求切分；同一表达内的句子合在一起，每个合成块最多 120 字。完成 `say` 字符串时，后端发出 `voice_unit_end`，桌宠开始生成该表达，无需等待整个回复或工具参数；不同表达、语气、生成阶段保持边界。旧后端或仅有最终回复时，也可在表达切换、阶段结束或最终回复时排空缓冲。停止、静音和切换角色会清掉缓冲。

QQ 对 Irodori 同样合并同一表达的句子，长表达按 120 字上限分块，每块沿用该表达的有效 caption，顺序合成后拼成完整 WAV；GPT-SoVITS 保留原来的按句合成和参考档案映射。Irodori 插件对这些有界请求关闭服务二次分句，保留 32 步、原话者文件和种子。较长的直接 API 请求继续使用服务的 80 字分组兜底。失败时不会发送半成品。

这一调整来自用户对同台词原始试听的反馈：连贯版明显更自然。执行分块不改写模型的表达意图、中文展示文本或聊天历史。

双语气泡现在按同一个 `utterances[i]` 展示整组中文 `text`，跟随日语 `say` 的实际播放。后端在 `text` 字符串闭合时发出 `speech_unit_text`，首组可在合成期间先展示；其余组等播放器启动成功后才切换。完成预取、接收最终 JSON、中文分句的阅读计时都不会提前换气泡。长 `say` 的多个音频块共用一组中文，不做逐字时间对齐。原始模型输出和历史保持不变。

`voice_unit_end` 带有展示文本与 `has_voice`：无 `say` 的动作描述在同一队列中按阅读时间展示，不生成伪造台词；合成或播放失败也保留对应文字，再继续后续表达。关闭语音后只按阅读时间展示尚未播放的文字；本轮保持文字模式，重新开启语音从下一轮恢复。停止、切换角色或会话会取消旧队列，旧请求的完成不能覆盖新气泡。流式重试、重复最终事件和仅有最终 JSON 的回复使用同一表达边界。

`scripts/irodori_server.py` 在整个 WAV 请求外增加一条全局串行通道。桌宠、QQ、预热同时请求时也只有一个推理任务，队列上限 16。等待中的断连请求被丢弃；已经开始的推理完成并回收后才允许下一条进入，避免取消后残留 GPU 工作与新请求重叠。空闲 10 秒后释放 CUDA 分配器缓存，保留常驻模型。

后端 `/tts` 将客户端断连传递给插件调用。Irodori 客户端使用可取消的异步 HTTP；取消结果不声称 GPU 工作已经停止。`/akane/status` 提供 ready、active、queued、完成与丢弃计数、错误类型和 CUDA 内存统计，不暴露权重路径。
