# 工具编排拆分记录

## 目标与兼容入口

`companion_v01/tool_orchestration_engine.py` 原为 1,834 行，混合原生协议、参数规范化、校验、审批、执行与回执。按职责逐片迁移，旧入口继续显式导出原函数，调用方无需迁移接口。

不改变桌宠、QQ 的状态归属与授权范围，不改变冻结的工具选择、原生调用 ID、模型工具别名或结果分页约定。工具结果的完整性与 continuation 仍由结果生产者负责，共享反馈层保留长结果及生产者的分页契约。

## 第一片：协议、参数与模型反馈

| 模块 | 职责 |
| --- | --- |
| `tool_orchestration/native.py` | 原生工具启用判定、白名单、选定能力的 schema |
| `tool_orchestration/normalization.py` | 调用来源、参数、冻结选择与 wire 元信息 |
| `tool_orchestration/feedback.py` | 工具预算提示、反馈内容与新生成文件回执 |

修正了原生计划对无效 handler 集合的检查顺序：以前会在判断不可用前遍历 `None` 或错误类型，现在返回 `disabled / native_tool_handlers_missing`。禁止工具调用与关闭原生模式的优先级保持不变。

迁移前 24 个相关测试模块共 367 项通过。第一片相关的 11 个模块共 230 项检查通过；新增两项测试覆盖无效集合以及禁用开关的检查优先级。AST 对照确认原有 40 个函数均保留签名，第一片只有上述启用判定发生行为变化。

## 第二片：校验与权限

- `tool_orchestration/validation.py` 负责冻结能力范围、参数校验与可恢复错误提示。
- `tool_orchestration/permissions.py` 负责可信 QQ 身份、桌面策略、高风险动作指纹和审批回执。
- 电脑操作与个人浏览器直接引用权限模块，移除对总入口的反向依赖。原有测试仅调整私有辅助函数的 mock 位置，断言保持不变。
- 移除旧 JSON 校验入口的无用预解析。普通调用只解析一次；错误 JSON 在参数边界直接返回诊断，不加载 handler。两项回归测试在修复前复现、修复后通过。

本片相关的 15 个模块共 152 项检查通过，包括测试 MCP 子进程、电脑操作传输与权限。AST 对照确认原有 40 个函数签名保留，除启用判定和预解析修复外，函数体保持一致（相对导入按实际包解析比较）。新增依赖边界检查，防止具体实现和设备层重新引用兼容总入口。

## 第三片：执行与回执

- `tool_orchestration/execution.py` 负责准入、路由、执行上下文和服务端执行；主函数由 225 行缩至 82 行，分开过期契约检查、上下文复制、长任务接入与保留/释放绑定。
- `tool_orchestration/desktop.py` 负责桌面派发、dispatch scope 恢复、截图登记与实际结果投影。派发与投影独立，主调用保留原权限检查顺序。
- `tool_orchestration/results.py` 负责模型回执、失败调用配对和策略/资源限制映射。三个执行入口的重复映射收敛到同一处，保留桌面 broker 的 data 字段与本地 broker 的专用字段契约。
- 工具已通过校验、执行器却在下一次解析中消失时，旧实现只生成 envelope 并返回空 result，旧调用入口因此丢失错误反馈。现在两种入口都得到真实的 unavailable 事件、状态更新和错误回执，不尝试派发。两项回归测试修复前复现、修复后通过。

普通工具的传输回执与内部能力结果是两个层次：能力生产者返回的部分结果或临时失败仍按既有约定反馈；命令状态、审批、策略、资源限制与 broker 派发失败的映射保持原样。取消检查仍在派发前执行，保留的实现仍在 finally 中释放，设备派发 scope 仍在 finally 中恢复。

原入口从 1,834 行缩至 63 行，仅保留显式兼容导出及既有 config patch 入口。原有 40 个函数的参数、默认值、返回类型和原生计划类均保留；AST 对照除两处准入修复和三个执行函数的拆解/重复映射外，原函数体保持一致。依赖检查覆盖入口只做导出、具体实现不导入兼容门面、设备层不反向引用总入口。
