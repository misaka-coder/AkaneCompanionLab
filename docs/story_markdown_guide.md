# 桌宠互动剧本 Markdown 创作与 AI 生成指南

本文档介绍如何使用纯 Markdown 格式编写《AkaneCompanionLab》桌宠互动剧本，以及如何将格式规范喂给大模型（DeepSeek / Claude / ChatGPT）实现**一键自动生成剧本**。

---

## 1. 剧本文件存放位置

你编写或生成的 `.md` 剧本文件只需放入以下任一目录，系统将**自动扫描并实时加载**，修改后保存即**热重载**，无需重启后端服务：

| 存放路径 | 作用域 | 示例 |
| :--- | :--- | :--- |
| **`characters/<character_id>/stories/`** | **角色专属剧本**（仅当该角色被选为当前桌宠时展示） | `characters/akane_v1/stories/rainy_day.md` |
| **`users_data/stories/`** | **全局通用剧本**（所有角色均可加载体验） | `users_data/stories/festival_outing.md` |

---

## 2. 剧本 Markdown 语法规范

一个剧本文件分为两大部分：**YAML 元数据头（Frontmatter）** 与 **剧幕节点块（Nodes）**。

### 2.1 YAML 元数据头 (Frontmatter)

必须放在文件最顶部，用两组 `---` 包裹：

```markdown
---
story_id: rainy_afternoon        # 必填：剧本唯一标识（英文、数字、下划线）
title: 雨后的美术教室             # 必填：剧本展示标题
description: 放学后的骤雨，困在美术教室里只剩下你们两人。 # 选填：剧本简介
cover_image: scenes/家/白天客厅.png # 选填：封面图片相对路径
initial_node_id: intro_1         # 选填：起始节点（默认以第一个出现的节点为准）
background: scenes/家/夜晚客厅.png # 选填：剧本全局默认背景（支持路径或名称如“夜晚客厅”，未声明时继承日常房间背景）
bgm: 吟诗作对                    # 选填：剧本全局默认背景音乐（支持路径或名称如“吟诗作对”，未声明时继承日常房间音乐）
outfit: 水手服                   # 选填：剧本全局默认服装（支持ID如“builtin-水手服”或名称“水手服”，未声明时继承日常房间服装）
---
```

> [!NOTE]
> **日常继承与还原特性**：
> - 如果剧本中未声明背景、音乐或服装，剧本将**无缝继承日常房间正在使用的装扮与音乐**；
> - 退出剧本（完成结局或返回日常）时，系统会**自动干净还原日常房间的原有状态**。

---

### 2.2 剧幕节点定义 (Nodes)

每个节点以 `## <node_id> [类型]` 开头。共有 4 种类型：

| 类型 | 说明 | 特有字段 |
| :--- | :--- | :--- |
| **`[script]`** | 普通剧情台词推进 | `下一幕: <node_id>` |
| **`[choice]`** | 分支选择肢（玩家在屏幕上点选选项） | `标题: ...`, `? 你的选择:` 列表 |
| **`[agent]`** | **自由对白节点**（玩家自由打字，由大模型实时生成角色神态与回答推进剧情） | `目标: <本幕演出的情绪与引导目标>`, `下一幕: <node_id>` |
| **`[ending]`** | 剧情终点结算 | `结局标题: ...`, `结局总结: ...` |

> [!TIP]
> 类型的标签 `[script]`, `[choice]`, `[agent]`, `[ending]` 也可以省略不写，编译器会根据节点内是否包含 `选择肢`、`目标`、`结局标题` 自动推断！

---

### 2.3 节点内常用属性对照表

支持中英文别名混写，放在正文台词之前（以冒号分隔）：

- **`角色` / `speaker`**：如 `Akane`
- **`表情` / `emotion`**：如 `normal`, `开心`, `脸红`, `卖萌`, `思考中`, `得意`, `被摸头`
- **`动作` / `motion`**：可选 `idle`（静止）, `nod`（点头）, `shake`（摇头/扭身）, `bounce`（轻跳）
- **`背景` / `background`**：如 `scenes/家/白天客厅.png` 或 `夜晚客厅`（在此幕切换背景；未指定则保持上一幕或全局设置）
- **`音乐` / `bgm` / `music`**：如 `bgm/afternoon.mp3` 或 `吟诗作对`（在此幕切换曲目；未指定则保持播放）
- **`服装` / `装扮` / `outfit`**：如 `水手服`、`睡衣` 或 `builtin-水手服`（在此幕切换立绘装扮；未指定则保持上一幕或全局设置）
- **`下一幕` / `next`**：目标节点 ID（跳转到哪个节点）

---

### 2.4 选择肢写法（Choice Block）

以 `? 你的选择:` 或 `选择肢:` 开头，每行以 `- 选项文字 -> 目标节点ID` 表示：

```markdown
## choice_1 [choice]
标题: 窗外的雨越下越大了……
角色: Akane
表情: normal

看这天色，雨一时半会儿停不了呢。我们要不要先做点什么打发时间？

? 你的选择:
- “一起画幅画吧，你来当我的模特。” -> branch_paint
- “把外套披上吧，别着凉了。” -> branch_warm
- （自由对话）笑着调侃她怎么又忘了带伞 -> agent_tease
```

---

### 2.5 自由 Agent 节点写法

大模型会结合前因后果，针对玩家打出的任何话做出符合茜茜人设的回应：

```markdown
## agent_tease [agent]
角色: Akane
表情: 思考中
动作: nod
目标: 茜茜被玩家调侃后有些脸红害羞，但心里很高兴被关心。根据玩家回复自然回应并引导至温馨结局。
下一幕: ending_warm

哼……我今天出门明明看了天气预报说是多云的嘛！你倒好，还专门笑话我……！
```

## 3. 一键丢给 AI 写的 Prompt 模板

你可以直接将以下提示词**整段复制给 ChatGPT / Claude / DeepSeek**，让 AI 帮你生成完整剧本：

````markdown
你是一个文字冒险与桌宠互动剧本作家。请根据以下 Markdown 剧本规范，为角色【茜茜】编写一个 3~5 幕、包含分支与自由对白的小剧场。

【剧本规范要求】：
1. 顶部必须包含 YAML frontmatter：
   ---
   story_id: <英文标识>
   title: <剧本中文标题>
   description: <剧本简介>
   cover_image: scenes/家/白天客厅.png
   initial_node_id: <起始节点ID>
   background: <可选：背景路径或名称，如“夜晚客厅”>
   bgm: <可选：BGM路径或名称，如“吟诗作对”>
   outfit: <可选：服装名称或ID，如“水手服”>
   ---
2. 节点使用 `## <node_id> [类型]` 声明，支持：
   - [script]: 对白推进，支持属性：`角色: Akane`, `表情: normal/开心/脸红/卖萌/得意`, `动作: idle/nod/shake/bounce`, `背景: <名称/路径>`, `音乐: <名称/路径>`, `服装: <名称/ID>`, `下一幕: <目标ID>`
   - [choice]: 分支选择，包含 `? 你的选择:`，格式为 `- 选项文本 -> 目标ID`（至少包含一个自由回应选项指向 agent 节点）
   - [agent]: 自由交互节点，必须包含 `目标: <剧情与情绪引导目标>`, `下一幕: <目标ID>`
   - [ending]: 结局节点，包含 `结局标题: <标题>`, `结局总结: <总结>`
3. 角色性格：傲娇、娇羞、温柔可爱，嘴硬心软，非常在乎玩家。
4. 确保所有 `下一幕` 和分支 `-> 目标ID` 都是真实存在的有效节点，没有悬空断链。
5. 请直接输出符合上述规范的 Markdown 文本，无需其他多余解释。
````

AI 生成后，将内容保存为 `.md` 文件（如 `rainy_day.md`），放进桌宠的 `characters/akane_v1/stories/` 文件夹，桌宠端立刻就能看到并开始演出！
