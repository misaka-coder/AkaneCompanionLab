## 1. 交付效果

主模型可以把独立工作交给单独配置的子模型。任务立即返回 ID，子代理使用独立历史和已有工具执行链，在当前选定项目里直接工作。主模型收到报告后检查真实改动、验证和整合。

请求短暂失败时保留当前进度，恢复本次模型请求；失败退出时仍交接已有报告、可核验结果和产物。后续工作能够回到原子会话，而不是从零重新派发。工具执行、状态查询、完成通知和 MemCore 继续复用现有实现。

实施顺序为：先定位队列与本地等待，再接通统一子模型和可靠交接，随后完成子会话接续、MemCore 管理、列出与删除。配置保存及设置页可以与队列排查并行；涉及同一运行循环的改动顺序执行。

主会话长期保留；子会话按任务创建并持久保存，相关返工可以接续，独立新任务默认新建。一次执行结束只释放运行资源，不删除会话，也不要求等待主模型最终交付。保留历史与一直运行进程是不同的事。

## 3. 本轮设计选择

- 主模型优先自己处理工作。子代理用于边界明确、能带来上下文、时间或成本收益的任务；等一个长命令直接用已有后台工具。
- 默认共享工作区，子代理的写入立即作用于真实文件。失败或停止不自动回滚已有改动。派发说明明确负责范围，避免同时修改同一处。
- 保留现有后台立即返回行为；依赖子代理结果时可用公共任务查询等待。第一版不再增加一套前台调用参数。
- 一份统一子模型配置供所有子代理使用，主子可以使用不同服务和思考设置；不增加逐个 agent_id 的模型设置、固定角色队伍或任务派发时自行选择凭据。保留明确的跟随主模型选项；独立配置失败时不无声回退到昂贵主模型。
- MemCore 的工具收起门槛、原始历史压缩阈值、压缩比例和摘要数量等默认复用现有配置。会话各自计量，配置不逐会话复制；有效请求预算按实际子模型窗口及输出预留适配。
- 原生工具调用优先处理。工具回合无需输出任务最终 JSON，更不需要伴侣的 emotion、text、say 等字段。
- 主模型接收简短报告、真实状态、失败原因与产物引用；不自动复制 child 全部对话、命令输出或工具历史。
- 完成通知直接携带必要报告，不强制再查一次相同结果。详细证据沿用回读入口；主模型最终回复不销毁仍在执行的子任务。
- 默认保留已结束子会话，按需列出或删除。列表不每轮注入提示词；删除会话不撤销它已经写入项目的代码或删除交付文件。
- 不新增固定十分钟任务终止、强制完成工具、文件锁审批层、递归派发或固定角色阵容。已有权限、用户停止和明确配置的预算继续有效。

## 3.1 阶段 Q：队列与长任务后的响应延迟

负责：Codex。取证基线见 [已有审计的待处理部分](tool_runtime_trace_fixes_v1.md#待处理长任务后的响应延迟与子代理接续)。这条工作不因子代理改造完成而自动算作修复。

已知证据：后续聊天打开至第一次请求构建审计约 237 秒；被动图片批次约 236 秒；一条正常聊天排队约 203 秒。同期两次压缩成功，第二次收起了长任务轮的 291 条来源记录。当前不能把等待全部归因于上游、压缩或图片下载。

1. 在既有调用边界补轻量阶段计时：入队到领取、被动内容/转发准备、附件注册与就绪等待、会话执行权等待、记忆入库与维护调度、上下文读取/投影、请求预算处理，以及服务商请求与回复阶段。复用现有 trace 和指标，日志只记录必要标识、阶段及数值，不记正文、凭据或路径内容。
2. 用可控慢附件、慢维护、忙会话和正常文本夹具分开复现；实际轨迹可读时再对照。查明等待点后做窄修复，不仅增加超时提示，也不先假设需要改队列优先级。
3. 复核 `tests.test_session_completion_batches` 中 `test_retry_waiting_head_cannot_be_overtaken_including_steer` 的已有失败。普通排队保持既有顺序；主人的有效干预应能进入正在执行的回合。先核对真实入口、身份校验与测试语义，再决定是实现缺口还是旧断言。不能为全绿把所有消息放开插队，也不能用旧断言堵住主人干预。
4. 长任务结束、被动记录维护、压缩调度和完成通知之间不能形成自己的等待循环；检查 claim、lease、重试与停止后的释放。需要等待的实际业务保留原因，不用清空队列或旧任务来掩盖问题。
5. 对照 QQ 和桌宠普通消息的本地前置开销，服务商耗时、确实需要的附件等待和同步预算修复分别记录。此前约 200～300 ms 只作已有体验参照，报告样本数量和变化；不承诺所有消息固定落在该范围。

重点入口：`companion_v01/qq_session_queue.py`、`companion_v01/qq_session_work.py`、`companion_v01/durable_session_queue.py`、`companion_v01/session_inbox.py`、现有会话协调器、`companion_v01/engine_services/turn_preparation.py`、`companion_v01/engine_services/response_budget.py` 和真实桌宠入口。与实现相应的 tests 由 Codex 维护。

验收：可解释“入队至首次请求”的耗时组成；已复现的等待点有实际修复或明确外部原因。普通消息顺序、主人干预、停止、重启恢复、完成消费与两个客户端的入口回归通过。现场复现不足时明确保留限制，不将加了计时等同于问题已解决。

1. 在现有模型服务页增加一份统一子代理配置，复用服务商、模型检测、API 测试、保存和密钥遮蔽。未配置时保留当前跟随主模型行为；用户选择独立配置后，缺失或不可用要明确反馈。配置保存与界面切片 A1a 见 [可派发的设置执行单](subagent_shared_model_settings_execution_plan_v1.md)，实际模型路线 A1b 由 Codex 接入。
2. 同服务可以明确复用主服务配置，但独立模型和思考设置不被会话模型切换覆盖；独立服务可与主服务使用不同协议和凭据。

5. 一次执行开始后固定目标；修改设置影响新执行。排队和重启恢复只保留必要的非敏感路线引用。路线不能再解析时明确结束并交接，不能偷偷换服务。密钥只由既有配置存储与客户端管理，不进 Job、提示词、报告或日志。
6. 子任务实际模型及使用量进入既有任务回执/审计。与普通聊天缓存统计分开；不为本轮增加新的统计仪表盘。
7. 模型列表、测试、保存的慢响应不能覆盖更新后的选择或表单。现有聊天、视觉及图像服务配置完整保留。

验收：主子不同模型、不同服务、不同思考设置的真实请求目标一致；切换父会话模型不改变已运行子任务。密钥不出现在公开快照和任务材料中。

### A2. 请求恢复与最终报告

重点入口：`companion_v01/subagent_engine.py`、`companion_v01/model_runtime/json_calls.py`，以及 `companion_v01/engine_services/final_response_sync.py`、`companion_v01/engine_services/final_response_failures.py` 中可复用的公共判断。

1. 抽取小范围的请求失败分类与恢复决策，主聊天保留角色最终格式，child 保留任务报告出口。不要建立第二个工具执行器或整体重写聊天主循环。
2. 短暂连接失败或服务过载，最多对当前请求补一次重试。适配器已有恢复必须计入同一策略，避免外层再叠加一轮完整重试。正常成功请求不增加等待。
3. 重试保持目标、历史、工具定义和当前请求一致；传输错误不追加“你输出格式错误”的提示。完整长请求超时、凭据错误、取消等直接保留真实原因，避免连续多分钟等待。
4. 已确认执行且落库的工具不重跑。测试失败、参数错误等业务反馈交回模型，让它正常修正；未确认的外部执行先查状态，不能当作未执行重新派发。
5. 合法原生工具调用先进入公共执行链。只有最终报告有格式问题时才给一次简短修正，保留工具能力和已有工作。仍无法取得合法报告则按未完成交接原文，不制造成功。
6. 成功、失败、取消和异常出口使用同一个结果收束入口。模型返回错误、轨迹写入失败、无最终报告以及 `finally` 的取消未确认，都不能丢掉已积累的 artifacts 和可核验进度。

验收：child 写文件、登记产物、完成测试后，下一次模型请求断开；文件写入和测试都只执行一次，报告与产物仍能交给父模型。原生工具调用没有最终 JSON 时仍正常执行。

### A3. 失败报告与消费一致性

1. 报告尽量包含已完成工作、实际验证、剩余工作和结束原因。优先复用最后有效报告及已有工具回执；没有最终模型输出时从真实记录生成简短交接，不额外调用故障服务来“写漂亮摘要”。
2. 没有证据的修改归属、测试通过或任务完成保持未知。共享工作区的整体 diff 可能包含用户、父模型和其他 child 的改动，不能全部归给某个失败子任务。
3. 最终原文及工具证据仍在 child 历史里。检查现有报告裁切与各消费入口，确保状态、原因和产物不会只在其中一条路径丢失；长材料沿用现有可回读结果机制。
4. 显式查询、活跃父回合汇集、父回合结束后的通知使用同一终态事实。实际进入有效模型响应后再确认消费；查询已经消费的结果不再自动重复通知。
5. 报告明确是子代理结果或后台事件，不能伪装为主人新指令。产物已生成与已向用户发送仍分开表示。

完成阶段 A 后先复验。当前长任务后的聊天延迟另有独立审计，不据此宣称已经修复。

## 5. 阶段 B：继续原 child 与执行中追加

### B1. 子会话身份与单次执行

1. 对外区分稳定 `agent_id` 与本次 `job_id`：前者定位原子会话，后者供既有 `exec_status` / `exec_cancel` 查询和控制本次运行。复用已有 child_session 与 Host Job 关联，不新增第二套任务状态权威。
2. `spawn_subagent` 增加可选 `agent_id`：省略时创建新 child；提供时把任务追加到原 child。启动和完成回执简短带上两个 ID，不把内部 profile、数据库路径或权限材料输出给模型。
3. 原 child 活跃时，在下一次模型请求边界接收追加指令，返回当前 job_id；空闲、已完成或失败时，新建一次 Job，使用原 child 历史。每个 child 保持一个活跃模型循环，多 child 的并行不变。
4. 旧 Job 的成功、失败、取消和已消费事实不改写。新执行有自己的终态、通知和工具调用 source_id，不能沿用固定的 `:input` / `:result` 标识。
5. 沿用 owner、父会话、角色/渠道和 actor 的现有归属判断，不通过角色文本或猜测 session 找任务。父会话切换模型或项目不会把活跃 child 悄悄搬到新目标。
6. 新任务默认新 child，相关返工明确使用原 agent_id。主模型最终回复、子模型交出报告和进程释放都不触发会话删除。保留原 MemCore 历史，无需新设强制“验收批准后归档”的状态流程。

### B2. 消息边界与失败后继续

1. 后续指令真实追加进 child 的 MemCore，保持任务、工具调用和结果配对。已经发送给服务商的请求不在中途改写；指令只影响后续决策。
2. 工具执行中收到更正，当前实际结果先按原调用记录，再与更正一起交给模型。普通追加指令不自动撤销工具；停止使用现有停止语义。
3. 指令接收与模型实际看见分别有真实回执，重复投递不重复入库。复用现有协调、消息登记和 `TaskWork`，不把整个 child 历史每轮重新扫描或重新归档。
4. 失败后继续从原历史和已确认工具结果出发。进程已丢失或后台执行不确定时先核实，不能仅凭任务 ID 就宣称命令已经恢复。
5. 后端重启保留历史和失败交接；未开始的排队 Job 沿用现有恢复。已开始而中断的任务不从第一步自动重做副作用，父模型可以显式接续。
6. 新执行使用当前子模型配置，并按已有规范轨迹适配协议。不同服务商的原生 continuation/reasoning 凭据不能直接混用；必要时进行一次合法历史重投影。

验收：成功后追加任务、写代码后失败再继续、活跃时更正、用户停止后明确继续、后端重启后的接续，都保留原工作与真实状态。测试 source_id 不碰撞、重复请求不多起一次执行。

### B3. 提示与缓存

共享说明只需表达：独立上下文、共享项目直接修改、任务 ID、报告回传及后续任务。子提示不包含伴侣人设、父聊天全文和面向用户的语音 JSON。

- `agent_id`、新指令与任务结果进入尾部记录，不每轮修改父会话稳定前缀。
- 工具链内冻结本次目标和已经组装的静态说明，按既有追加规则处理工具结果与背景完成；不重复注入全量目录。
- 有效重试不替换前面历史。继续同一 child 正常追加，压缩和工具卡片仍走其自己的 MemCore。
- 不承诺不同服务商相同的命中率。先验证实际 prompt/schema 稳定与本地耗时，再用生产统计确认；不把子请求混进主人聊天图表制造数值变化。

### B4. MemCore 工具卡片、压缩与长执行预算

负责：Codex，与子循环及接续一同实施。独立历史不意味着独立设置页，也不意味着主聊天的所有调度已自动继承。

1. 每个 child 的原始任务消息、工具配对、报告和摘要仍进入自己的 MemCore。原文、工具 ID 与回读能力保留；不把全部轨迹拷贝进父会话。
2. 工具紧凑投影和 LLM 摘要分别处理。按当前 `compact_arguments_after_terminal` 等已选策略，本次子回合结束后由代码收起符合门槛的结果和参数，不每个工具回合改写前面的历史；它不需要等待父模型交付。失败交接的回合也要以真实失败结束；不能伪装成功，也不能假定仅 abort 就已有成功回合的 settlement。
3. 子回合结束后复用 `compact_due_background`，由该子会话自己的用量决定是否压缩。未达门槛不生成摘要，报告不等待 LLM 摘要返回。各 child 按 namespace 复用已有调度与合并，不一起重新扫描或压缩所有子会话。
4. 子模型配置不单独复制 MemCore 阈值和摘要滑动规则。请求预算纳入该模型窗口、静态提示、工具定义、已有历史与输出预留；只在确有必要时调整有效预算。摘要模型沿用已有选择规则：明确配置的摘要路线优先，未配置时正确接到本次子模型路线，不能误用昂贵父模型或丢掉摘要提示。
5. 下一次模型请求边界检查预算，并优先复用已结束历史的压缩与上下文重建。正常工具追加保持前缀稳定，压缩失败保留真实原因与原文，不循环重试故障服务或默默删除当前任务信息。
6. 必须处理单次长执行本身超过预算的情形。当前 child 整次执行是一个 open turn，普通压缩会保护它；仅补一个压缩调用不足以解决。核实 MemCore 的公开回合/投影接口，采用同任务内安全分段或必要的最小 SDK 补充：在完整调用与结果已配对的边界整理历史，保留任务目标、最新进度、未完成项、后台任务 ID 和产物引用。agent_id 与运行中的 Job 不变，关闭记忆片段不等于宣布整个任务完成，不增加模型必须调用的完成工具。
7. 对未确认的后台结果、当前待返回的调用、服务商 continuation 和压缩期间新增指令保留正确关联。新投影只用于后续请求，不中途改写已发送请求。若需要更改 MemCore，修改其源码并按既有依赖流程更新，不直接改 `.venv` 安装文件。

验收：未达门槛无需 LLM 摘要；子报告先回传而摘要可后台完成；接续可用已有卡片/摘要并回读原文；小窗口子模型与单次超长工具轨迹确实可持续推进。只验证任务结束后压缩，不能声称长执行预算已接齐。

### B5. 按需列出和删除子会话

负责：Codex，在 B1 的持久身份接通后完成。沿用 Host Jobs 与 child_session 关联，从同一个管理入口提供 `list`、`delete`；按 ID 状态查询/停止沿用现有工具，接续沿用 `spawn_subagent(agent_id=...)`。

1. 列表按 agent_id 聚合，默认返回活跃和最近结束的子任务，旧任务支持分页。内容仅包含 agent_id、当前/最近 job_id、名称、项目标识、真实状态、更新时间和短报告；用存储条件查询，不加载全部对话。列表不每轮注入系统提示，不另建与 Jobs 竞争的任务状态表。
2. 依据已有发起会话、角色和真实任务所有者定位，复用主人私聊/桌宠的已认证身份关系；不能通过一个任意 ID 读写其它用户或群的子会话。不是取消当前授权范围，而是沿用已有归属。
3. 支持单个或多个 agent_id 按需删除。已结束且结果已交接后可清理；仍运行的先通过现有停止入口结束，未交接结果保留并返回简短原因。不新增每个 child 的寿命设置、结束自动删除或单独审批流程。
4. 通过 MemCore 已有 `MemorySystem.forget_namespace` 等公开入口删除该 child 的历史、摘要、投影和对应索引。宿主补窄范围的资源释放，避免该 child 的压缩/索引任务在删除后重新写入；不关闭其它会话或整个 MemCore。索引清理失败按实际 `partial` 结果报告。
5. 保留父会话已有报告、项目代码、交付文件和必要 Job 终态回执；通过已有任务关联保留已删除事实。旧 ID 查询明确“已删除”，接续不能偷偷新建同 ID 空会话。重复删除可辨识，批量逐项报告实际结果，不把部分失败包装成全部成功。

验收：分页及多次执行聚合准确；停止与删除的竞态、重启后旧 ID、索引清理部分失败和跨所有者访问均有对应行为。正常列举不产生模型请求，删除不影响主记忆、其它 child 或已交付代码与文件。

### 8.1 实现入口与维护边界

- `subagent_engine.py` 是准入与控制入口；`subagent_execution.py` 只协调本次循环，实际工具仍走 `execute_tool_batch`、既有 broker 和 Host Jobs。
- `subagent_models.py` 固定本次目标与非敏感设置；所有子代理读取同一份 `BotSettingsView.subagent`。独立客户端在宿主复用，关闭时随 worker/记忆服务排空释放，密钥不进入 Job。
- `subagent_recovery.py` 负责当前请求的有限恢复，和最终格式修正分开；主聊天 JSON 适配器只补充恢复尝试数及可选请求超时，不另写主循环。
- `host_job_runtime/subagents.py` 在现有 Job 表中保存稳定子身份、补充指令及删除标记。`spawn_subagent(task, agent_id=...)` 提供接续/干预；`manage_subagents(action=list|delete)` 按需管理；状态和停止仍用 `exec_status` / `exec_cancel`。
- `subagent_memory.py` 与 `memcore_integration/subagents.py` 处理独立历史、共享配置、预算分段及定向删除。使用 MemCore 公共接口，未修改已安装 SDK。子记忆工具只读自己的任务历史。
- 一次执行使用固定项目；已结束 child 的新执行可使用当前选择的项目。活跃 child 不会随父会话切换项目而移动。长任务 claim 定期续租，没有新增固定时长终止。
- 工具轮保持当前 slice 的完整调用/返回；安全边界关闭 slice 后先终态收起，再在达到预算时压缩。最终报告不等后台摘要。缺少可靠子模型窗口元数据时采用现有共享宿主预算，扣除该子模型输出预留，不虚构服务商容量；共享显式窗口仍由现有配置管理。
