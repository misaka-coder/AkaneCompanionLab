# 插件系统归属与边界 V1

状态：设计约定，2026-09-09 起草，供评审。本文回答“什么属于宿主本体、什么可以开放给
插件、插件不能碰什么”。目标、切片与验收仍以
[优化方案](plugin_system_optimization_v2.md)和[实施记录](plugin_system_v2_progress.md)
为准；本文只补两者都没有的**归属判据**，不新增接口承诺。

## 1. 一句话原则

**扩展点归宿主，实现可归插件；开放“效果与策略”，保留“实现与权威”。**

外部可以声明“我要什么、我允许什么、我要改变什么”，不能重造工具注册表、执行器、
记忆库、会话与投递链。宿主只对四件事严格：**身份、授权、一致性、生命周期**；
其余（业务内容、字段命名、结果大小、单次业务语义）不设启发式限制。

## 2. 判据

一条问题即可判断归属：

> 把这块实现换成别人的，用户会不会觉得“这不是我的 Akane 了”？

- 会 → **宿主本体**，不提供替换位，只提供声明位。
- 不会 → **能力**，应当开放：第三方可以和第一方走同一条注册、配置、调用、展示路径。

补充两条推论：

1. 宿主已经自己实现的能力（生图、转写、分轨、TTS、被戳反应）**不因“能用”而属于本体**；
   它们是能力，长期应迁成插件并由插件替换，旧实现当片删除。
2. 同一能力出现在多个入口时（模型工具 / 插件程序调用 / 事件回调），**只有一份执行
   权威**，其他入口都是它的适配，不允许各自维护业务实现。

## 3. 归属表

“可替换”指部署者能否用第三方实现替换该能力；“插件可声明”指作者通过公开 SDK 能控制
的范围；“插件不得”是红线。

| 子系统 | 宿主定义 | 宿主持有状态 | 可替换 | 插件可声明 | 插件不得 |
| --- | --- | --- | --- | --- | --- |
| 角色与人格 | 角色包契约、人格字段、立绘与展示规则 | 角色身份、当前角色、角色资源 | 是（角色包） | 贡献提示词块、技能、QQ 命令、展示 | 冒充其他角色/会话，改写他人角色包 |
| 记忆与上下文（MemCore） | 记忆结构、上下文组装、预算、留存语义 | 全部记忆数据与上下文权威 | **否** | 用公开动词参与（见第 4 节） | 直接读写记忆库、构造内部标识、伪造历史 |
| 会话与投递 | 会话队列、回合控制、渠道投递、回执 | 队列、回合、投递与回执状态 | 否 | 请求回合、查询真实状态、声明交付意图 | 自行发消息、伪造完成/已送达 |
| 授权与安全 | 权限命名、审批、作用域签发、撤销 | 授权记录与作用域 | 否 | 声明所需权限、声明连接需求 | 扩大自身授权、自报身份、绕过审批 |
| 工具系统 | 注册表、schema 校验、准入、执行、发现 | 工具目录与执行权威 | 否 | 注册工具、声明输入/输出 schema、执行特性、后续处理、效果与可见渠道 | 重造注册表/执行器，改他人工具定义 |
| 事件 | 事件契约、作用域、分发与回执、保留策略 | 分发状态与订阅绑定 | 否 | 发布事件、订阅事件、声明合并/串行语义 | 冒充来源、向未授权会话投递、假定持久化 |
| 服务与 provider | 服务契约、版本、依赖图、调用快照 | 服务目录与选择结果 | 是（provider 实现） | 提供服务、声明依赖、查询可用实现 | 绕过依赖图或部署选择自行直连 |
| 执行策略 | 策略阶段与顺序、失败语义 | 生效策略与诊断 | 是（策略实现） | 注册 before/wrap/transform/present/observe | 改程序权威值以外的展示、在失败时伪造成功 |
| 展示与 UI | 卡片契约、客户端渲染、媒体链 | 界面状态 | 否 | 声明配置表单、状态、卡片与操作按钮 | 直接调后端/Tauri、自带渲染实现 |
| 渠道 | 渠道协议、身份解析、发送实现 | 连接与发送权威 | 是（渠道动作实现） | 订阅入站事件、请求已授权动作 | 直连 OneBot 等外部接口、伪造发送成功 |
| 连接与配置 | 配置 schema、存储与投影、私密标记 | 凭据与配置权威 | 否 | 声明连接 schema、读取已授权值 | 读取未授权凭据、回显私密值 |
| 安装与依赖 | 暂存/发布/激活/回滚/卸载、依赖供应 | 制品、版本与 last-good | 否 | 声明依赖与权限、请求安装 | 自行安装依赖、写宿主配置模拟安装 |

## 4. MemCore：不设替换位，只开动词

MemCore 是宿主本体，**不提供替换接口**。插件与记忆的关系只有四个动词，全部由宿主
翻译成内部实现，作者不需要理解 MemCore：

| 作者意图 | 公开动词 | 宿主内部效果 |
| --- | --- | --- |
| 发生了一件事 | `ctx.events.emit()` / `@plugin.on()` | 只投递给订阅者；不写聊天、不唤醒模型 |
| 当前状态变了 | `ctx.observe(key, data)` | 进入下一次决策的观察输入；不产生新对话 |
| 需要角色处理 | `ctx.request_turn(reason, data)` | 进入正常会话队列；排队/合并/拒绝都有真实回执 |
| 想留下共同经历 | `ctx.timeline.append(event)`（P14b-1 已公开） | 走既有留存路径；不隐式唤醒模型 |

四者互斥且可预期：写 `emit` 就绝不进记忆，写 `observe` 只影响下一次决策输入。**“要不要
进 MemCore”不是作者的选择题**，而是所选动词的确定结果。工具调用与结果的配对、批次
聚合、取消后的收尾同样由宿主保证，作者只声明执行语义。

未来若开放“记忆策略”，形态是**宿主调用插件提供的策略**（召回排序、摘要方式、记忆源），
而不是插件操作记忆库。该形态尚未实现，不在当前 SDK 承诺内。

## 5. 红线与执行方式

红线不靠自觉，按可验证方式落地：

| 红线 | 落地方式 |
| --- | --- |
| 插件只用公开 SDK | 已由独立 SDK 与隔离 worker 保证；新增能力必须有“宿主不可 import”的真实安装验收 |
| 不直接读写记忆 | 只暴露动词；任何直连入口按缺陷处理 |
| 不自报身份 | 已由宿主签发来源与作用域保证；payload 自报无效 |
| 不绕过授权 | 安装授权与每次调用授权分开；策略 allow 不替代审批 |
| 宿主不再新增业务启发式限制 | 代码审查 + 回归：字段名/内容/通用小上限类规则不得新增 |
| 不留两套权威 | 每片必须同时删除被替换的旧实现；迁移窗口单独登记，有删除目标版本 |

## 6. 迁移清单（谁还留在宿主里）

| 项 | 现状 | 决定 |
| --- | --- | --- |
| 图像生成 | 已迁为插件（P5d），宿主保留模型服务连接适配 | 保持；继续清理遗留分支 |
| 被戳反应（含硬币/冷却业务） | 宿主业务逻辑，硬编码在 care 运行时 | **搬**：宿主留事件接收、动作执行与资源约束，业务策略迁成第一方插件 |
| QQ 动作（`onebot_action`） | 模型工具完整，插件无公开动作入口 | **留工具、开执行层**：插件用公开动作端口，与模型工具共用同一执行器 |
| 工具系统 | 宿主权威 | **留**；只继续收口 V1 与 SDK 两套写法 |
| 事件系统 | 已公开自定义事件、入站消息及 poke；旧投递模型已由 P14c 删除 | 按实际渠道缺口补类型化事件，不重复开放 poke |
| TTS / ASR / 模型服务 | 宿主固定名实现，仅图像迁移 | **开放**：分别接入公开服务契约，做真实替换验收 |
| 定时/签到等第一方插件 | timer、gentle-checkin、poke-streak 已由 P14b-3…5 迁至公开 SDK | 保持公开事件、观察与回合语义，不恢复 V1 端口 |
