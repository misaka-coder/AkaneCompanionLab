# 工具前后台执行与结果统一追加执行单

日期：2026-10-07。状态：第一阶段已实现并完成本地行为验证，尚未提交、重启或进行线上验收；第二阶段仅完成执行单，尚未实施。

第十一节是本轮讨论确定的最新执行单。第一至十节保留第一阶段的方案、实现与验收记录；涉及工具覆盖范围、前台等待、明确后台和最终回复等待时，以第十一节为准。第一阶段的通过记录不代表第二阶段已实现或已验证。

目标是在模型每次请求之前，统一收集当前任务已经完成、尚未交付的后台结果，与本批工具回应一起追加。模型通常无需逐个查询才能获知结果；主动查询仍用于等待关键任务、检查进度和读取详细输出。QQ、桌宠与子代理复用现有任务、权限、记忆和交付基座。

## 一 设计方向

1. 模型可以同轮提交多个工具调用。实际并发沿用现有资源限制、只读并行与副作用顺序，不能把提交数量等同于无限并发。
2. 支持后台续跑的工具可以先返回运行状态与任务凭据，让模型继续处理独立工作。
3. 每次请求模型前，收集属于当前任务的就绪结果，一次追加；不为每个完成结果分别启动模型回合。
4. 查询与自动追加共享终态回执的消费凭据。查询已经交付终态回执，就抑制后续的自动完成通知；查询到运行中不消耗未来的完成结果。正文续读独立于通知去重。
5. 自动追加应携带足够决策的结果。小结果直接附上，长结果保留必要输出和回读凭据，避免只有“完成了，请查询”的通知，也避免倾倒完整长日志。
6. 当前任务结束后，真正需要模型续接的后台完成事件仍可唤醒；静默、内部消费和直接交付策略继续有效。
7. 已发出的模型请求不被中途修改。执行完成后先登记，等下一个请求边界追加，不为通知打断正在生成的回复。

整批共享等待窗口默认 8 秒，通过环境变量 `AKANE_TOOL_BATCH_WAIT_SECONDS` 配置，范围 0–10 秒。命令初始页等待取 `initial_wait_seconds` 与整批剩余预算中的较小值；随后批次仍可在剩余窗口内收集完成结果。等待窗口控制前台等多久，任务执行超时控制任务能运行多久，两者独立。

## 三 与主流实现的关系

dsh 会把完成通知注入忙碌代理的下一步，空闲代理则可被唤醒；通知通常引导模型再调用 job_output 读取输出。我们的设计采用同样的请求边界收集方向，并自动附带适量实际结果。[dsh 完成通知说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/jobs/tool-jobs/README.md)

Claude Code 的本地 2.1.88 标注快照中，后台命令通知包含任务 ID、原工具调用 ID、状态、摘要和输出文件路径，符合优先级的通知可以进入当前工具循环。它是已发布程序的标注快照，不代表当前所有版本或任务类型；详细输出仍有工具读取入口。[Claude Code 工具说明](https://code.claude.com/docs/en/tools-reference)

Codex 检查到的 Shell 路径通过 exec_command 与 write_stdin 继续执行和读取输出；命令结束事件更新原命令的执行状态。不能据此把界面完成事件等同于自动给模型追加完整结果。[Codex 工具说明](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)

整批最多等待几秒是宿主调度选择，不是统一行业标准。是否改善体验，需要比较任务总耗时、模型请求次数和重复交付，不能只比较后台能力或等待秒数。

## 四 目标调用过程

假设独立调用 A、B、C 同时开始，A 用时 2 秒，B 用时 6 秒，C 用时 20 秒，整批前台等待上限为 8 秒。

```text
模型调用 A、B、C
  ↓
8 秒内收齐 A、B；C 仍在运行
  ↓
返回 A 的结果、B 的结果、C 的运行状态与任务 ID
  ↓
模型继续处理独立工作，并调用 D
  ↓
若 C 已完成，下次请求前一并追加 D 的回应和 C 的完成结果
  ↓
模型继续调用工具或完成交付
```

若 C 此时还未完成，只返回本次已有事实；之后到达的结果进入后续边界。若模型通过查询已拿到 C 的终态回执，自动完成通知跳过 C；结果正文有续页时仍可继续读取。

### 原生工具配对

每个原生调用都必须得到一份对应回应。后台工具的“已受理或运行中加任务 ID”就是该次调用的真实回应，不能把未完成调用空着就请求模型继续。Claude 对并行调用要求在下一条结果消息中配齐各调用的回应。[原生并行工具规则](https://platform.claude.com/docs/en/agents-and-tools/tool-use/parallel-tool-use)

后台操作随后完成时，以宿主任务事件追加，并关联原任务；不第二次伪造相同调用 ID 的原生结果，也不插回旧历史或改写已冻结的运行状态。事件来源应明确为工具任务，不能渲染成用户新说的话。

### 等待与并发

- 窗口是适用批次的共同最长等待预算。全部提前完成立即返回，不等满 8 秒，也不按工具数量累加 8 秒。
- 并发队列尚未开始的任务只能报告已排队；未真正受理的调用不能凭空生成运行状态或任务 ID。
- 普通同步工具保持正常返回。缺少后台生命周期的工具不能仅靠超时切断调用后继续执行；新增适配须明确所有权、取消、结果保存和回读。
- 涉及依赖或共享资源的后续动作不能因前一步返回运行中就认定前一步已完成。等待真实结果后再解除相应顺序约束。
- 无独立工作可做时，允许等待相关任务完成；不每隔 8 秒凭空请求模型，也不要求模型反复查询状态。

## 五 统一结果收集与消费

### 请求边界

在普通与流式路径共同的请求准备处，收集当前任务已经就绪且未交付的终态结果。子代理沿用所属 child 的入口，父代理只接收其正常任务报告，避免把 child 内部工具结果重复送到父会话。

已就绪结果不额外等待其他慢任务，亦不增加通知防抖倒计时。一次收集可以包含多个结果；收集结束后新到达的结果留到下个边界。数量或上下文预算不足时保留剩余项，后续继续领取，不能静默丢弃。

收集只读取所属活跃任务的待交付项与新完成事件，优先使用既有索引和批量入口；不每轮扫描全库、重建全部历史或读取所有结果全文。等待只发生在真实任务仍需完成时，不为收集、合并或展示再加固定延迟。

结果必须绑定实例、会话、角色、任务来源与原始调用，保持原授权和交付上下文。群里不同成员、不同任务以及 QQ 与桌宠之间不能仅凭会话相近就合并。模型侧只暴露需要的公共凭据，不注入内部路径、凭据或授权存储细节。

### 查询与自动追加的竞争

查询终态和自动追加竞争同一份终态事实。统一凭据应让两条路径在正常执行中只把该事实自动交付一次，并处理查询前、通知入队后及同时完成等竞争窗口。

查询到运行中只记录观察，不消耗终态。模型主动再次查询或回读详细日志仍合法；去重针对自动重复通知，不拦截合法查询。

任务已经完成不代表结果正文已经读完。交付一页终态结果后可以消费完成通知，但不能清除其续读入口或把正文标为完整；后续页的读取位置复用原工具的游标，不另建通知或全文副本。

已经进入通知队列但尚未处理的已消费结果，应通过原队列的结算或跳过机制抑制。不能直接删除原始任务事实、取消真实任务，也不能把已领取且可能发生交付的通知当作未执行输入处理。

复用 HostJobStore、SessionInboxStore 和现有事件 ID、领取与回执机制。TaskWork 只保留活跃任务引用，不另建业务任务表或维护第二份执行状态。

### 请求失败与重启

收集不等于模型已收到。冻结请求时固定本批结果和身份；同一请求的安全重试复用原批事实，不重新执行工具或吸收新结果来改变旧请求。

模型输入交付、任务完成和用户收到消息分别记录。网络失败、停止和重启的未知结果保留原因；已经可能产生外部副作用的回合沿用现有未知结果保护，不承诺跨崩溃严格只执行一次。

旧任务缺少来源关联时，不猜测归属或批量改写数据库；保留明确的旧路径，确保新任务使用完整关联。

## 六 模型与用户收到的内容

自动结果应包含公共任务 ID、对应工具、真实终态，以及足以判断下一步的内容：成功结果、必要 stdout 或 stderr、失败原因和现有产物句柄。只引用任务原本具有的资源权限，不通过追加扩大权限。

沿用工具已经清晰表达结果的格式，每项正文只展示一份，不同时追加 JSON 正文、同义文字说明和另一个包装副本。原生结果与兼容反馈按实际调用路径择一进入模型；自动事件不重复注入已查询交付的事实。内部 diagnostics 只保留必要诊断，不整份转成提示词。

### 当次返回与续读

工具轮期间的展示预算与回合结束后的 MemCore 历史卡片是两层机制。短结果直接返回，长结果保留适量正文和真实可用的回读入口；同步返回与后台自动追加沿用同一展示规则，不额外请求模型先写摘要。已有分页结果由生产方控制，公共出口不再硬切一次。

| 结果类型 | 当次展示与续读方式 |
| --- | --- |
| 修改商品、发送文件等操作回执 | 完整保留真实状态、实际变化、必要 ID 和产物句柄。 |
| 搜索、列表与结构化数据 | 按完整条目组成有限页，保留导航与续页凭据；不把裁断的 JSON 宣称为完整结构化结果。 |
| 论文、网页、文件正文 | 优先按原工具支持的章节、段落或页返回，明确已展示范围与剩余内容。 |
| 命令日志 | 保留退出状态、适量日志与错误上下文，剩余正文通过命令游标或已保存材料读取。 |
| 未提供分页的长结果 | 复用现有材料存储保存原始结果，返回明确标注的预览和读取入口，不靠猜字段删掉业务数据。 |

复用 ToolFollowupEnvelope 的 complete、continuation 和 diagnostics 表达正文是否完整及下一步读取参数，执行终态仍由原任务状态表示，不要求聊天模型增加新的最终输出字段。分页或预览必须明确不完整，并保留对应工具可执行的续读参数；材料正文的读取沿原读取工具返回的 cursor 继续。

续读入口优先使用既有公开任务 ID、材料句柄与短游标，只展示下一次调用必需的参数，字段名与工具参数一致，值可直接复制使用。不给模型多组同义 ID、内部关联字段或需要自行拼接的凭据；不为缩短而截断已有 ID。若确有过长凭据，再在原存储中登记短句柄映射，由宿主恢复原凭据并校验归属，不另建凭据库或依赖模型推导。

模型在当前工具轮可以继续读取同一次执行保存的结果，直到证据足够或正文读完。信息已经足够时不强制读完；续读不重新执行原动作，也不伪造原调用 ID 的第二份原生结果。正文完整性与终态通知消费保持独立。

### 原文保留与 MemCore 回读

MemCore 按 ID 展开的是实际入库的完整记录。入库正文是全文，就能展开全文；入库正文是预览加材料句柄，则展开后仍需沿句柄读原材料。不能把“完整记录”与“工具产生的全部数据”混为一谈，也不能指望历史卡片恢复入库前已丢失的内容。

长结果复用既有材料或产物存储保留原文，工具记录保留实际展示内容与回读凭据，不为了统一而把同一全文重复复制到另一套结果数据库。优先复用已保存材料或随输出增量写入，避免完成边界反复读写、编码和序列化整份数据；结果展示生成后供各消费者复用，宿主内部复用不等于向模型重复注入。本机命令日志的增量保存和原游标回读已经接通；任务所属会话、权限和材料生命周期沿用原机制。

保存失败、材料过期或旧日志已丢失时，保留真实执行状态并说明正文缺失原因，不提供不可用的续读承诺，不因缺少全文自动重跑已经发生副作用的动作。

### 整批预算与缓存

单份长结果先沿用原工具预算，自动追加另控制整批正文量。状态、错误和回读凭据不能因正文裁剪丢失；本批原生调用必须配齐回应，后台完成项若整项无法纳入则保留待交付，不能先消费再省略。已经交付终态和预览的长结果无需为每一页正文再次自动唤醒模型，详细读取由模型按需发起。

单页沿用生产方原预算，自动完成结果每次模型请求最多收集 16 项、128 KiB UTF-8 正文。放不下的整项保留待交付，不预先确认消费；收尾处与请求准备处不会重复领取两批。未分页的单份超长结果复用现有材料保存和 16,000 字符预览，失败则明确不完整且不提供假句柄。这些限制分别使用字节和字符，不等同于 token 数。

保持当前原生 action 和 observation 的配对、来源检索与 MemCore 生命周期。自动完成事件进入所属任务的现有记忆入口，长记录的收起和回读沿用已有机制，不在工具轮中提前重写冻结历史。

普通工具轮的 system、工具定义、已发布历史和动态上下文快照保持稳定，只在尾部追加新事实。不要每轮加入整份任务目录或重复状态说明。

固定用法放在稳定的工具说明中，只简短说明自动补入、按需续读与交付前处理相关任务。单份结果只附真实状态、正文完整性和必要续读参数，不每轮重复整套规则，不针对某个命令或此次故障追加专项提示。

拿到完成结果不必立即向用户发消息。模型按原任务决定继续工作、集中交付或保持静默；文件发送、QQ 分句、桌宠表现和 text、say 等输出协议继续走现有链路。

## 七 任务收尾与后台续接

模型尝试结束当前任务时，宿主再检查已就绪结果，避免没有下一批工具调用导致结果漏收。仍影响交付的未完成任务可以等待或继续处理；长期服务和明确留在后台的任务不能让当前回合无限等待。

活跃任务的完成结果优先由当前循环消费。当前循环结束后，按原 completion_mode 和 memory_mode 决定记录、直接交付或模型续接；静默任务不被改成角色主动发言。

闲置会话的完成事件复用现有持久化聚合：领取当时已就绪、连续且上下文兼容的项，不增加额外等待，不跨越用户输入和其他隔离边界。不同时间完成可能形成多批，不保证任意任务组合永远只需一轮。

停止、角色切换和授权变化继续走现有边界。失效的旧任务不能覆盖新选择或借新回合的权限执行；未确认取消保留未确认状态。重启不会重做工具副作用。

| 原文保存失败或材料过期 | 回执保留执行事实与正文缺失原因，不伪造可用句柄，不自动重做副作用。 |

## 十一 通用前台等待与后台执行补充执行单

状态：代码已实现，完成受管执行与完整结果接回的本地验证；上游缓存和实际客户端体验仍需上线流量验收。

目标：普通业务工具统一进入受管执行链路。工具实现可以是同步函数，模型侧默认前台等待；等待窗口内完成就返回实际结果，未完成就返回原任务 ID 并继续后台运行。模型明确选择后台时，受理后立即返回 ID。覆盖范围不再仅由 `execution_class=long_task` 决定，也不只改命令工具。

### 11.1 最新调用语义

| 调用情况 | 返回行为 | 后续行为 |
| --- | --- | --- |
| 普通业务工具，省略 `background` 或设为 `false` | 最多等本批前台预算；提前完成直接返回真实结果，不必向模型展示任务 ID。 | 已直接交付的终态不再自动追加。 |
| 本批前台预算到期，工具仍未完成 | 返回真实 `queued` 或 `running` 状态、原任务的公共 ID 和必要的已有输出。 | 原任务继续执行，完成后走现有结果追加与续接链路。 |
| 明确 `background=true` | 受理成功后立即返回公共任务 ID 和实际状态，不进入前台等待窗口。 | 不阻塞本批结果返回或最终回复。 |
| 工具已有独立任务生命周期，如命令执行、子代理提交 | 复用原任务和控制入口；`spawn_subagent` 保留其已经声明的立即受理语义。 | 不再包一层任务或生成第二组同义 ID；需要报告时按需查询或等待。 |
| 查询、等待、输入与取消等任务控制操作 | 直接操作原任务；显式等待沿用控制工具自己的参数和上限。 | 不把控制操作再次包装成需要查询的新后台任务。 |
| 已就绪的后台结果 | 下次请求模型前直接收集，无额外等待。 | 与本次工具回应合并追加，已查询交付的终态不重复通知。 |

- 保留 `AKANE_TOOL_BATCH_WAIT_SECONDS`，默认 8 秒、范围 0–10 秒。它是前台结果等待预算，等待到期不取消任务。Shell 默认不设执行期限，`timeout_seconds` 省略或 `0` 表示不限时，正数期限到期仍沿用原执行器的确认终止和结算规则；普通工具、网络和设备通信超时保持各自契约。
- 从本批开始派发时建立一次单调时钟截止时间，普通前台调用的执行及并发排队共用该预算；不按工具数累加，也不在执行器和批收集器之间重复等待。权限确认等尚未受理的阶段保持真实状态，不以任务 ID 假装已经执行。
- 全部前台项提前完成立即返回；全批明确后台时受理完成即可继续；混合批次只等待前台项。之前已经转入后台的任务，不因为下一批工具调用而重新获得一份隐式等待预算。
- 任务从开始就受管。前台转后台只是交还控制权，同一个任务、同一次业务执行、同一公共 ID 继续运行，不在第 8 秒重新执行工具。
- 每个原生调用必须配齐一份真实回应。随后完成以宿主任务事件追加，不复用原调用 ID 伪造第二份原生结果，不插回旧历史。
- 等待到期不表示写操作完成，不解除未完成操作的依赖或共享资源约束。继续沿用现有只读并行、资源限额和副作用顺序；查询和取消不能被慢任务堵住。

示例：A 明确后台，需 30 秒；B 默认前台，需 2 秒。约 2 秒后一起返回 A 的任务 ID 和 B 的真实结果，A 不额外拖出 8 秒。若 A、B 都默认前台，则预算到期时返回 B 的结果和 A 的原任务 ID。A 完成后在下一请求边界追加结果。

### 11.2 主流参考与扩展边界

主要参考 dsh 的任务管理和命令执行结构：启用任务管理后，命令从启动时就是任务；前台在期限内完成直接返回结果，到期仍在运行则返回同一个任务 ID；明确后台立即返回。Claude Code 的命令执行也支持明确后台和前台等待到期转后台。[dsh 命令执行](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/shell/tool-bash/README.md#foreground-commands-as-jobs)、[Claude 命令执行](https://code.claude.com/docs/en/tools-reference#foreground-commands-that-move-to-the-background)

这些资料证明的是对应命令链路，并不证明所有普通工具天然采用相同行为。dsh 的其它工具仍需接入通用任务管理接口。本项目将同一机制推广到普通业务工具，并采用整批共享前台预算，这是自己的通用化扩展。[dsh 工具接入](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/adding-a-tool.md#long-running-work)

dsh 已有忙碌代理下一步接收完成通知、闲置代理按策略续接的机制。我们保留第一阶段已实现的请求边界收集、适量实际结果追加和查询去重，不退回到每个通知都要求模型再查询一次。[dsh 完成通知](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/jobs/tool-jobs/README.md#completion-notices)

| [命令调用](../companion_v01/tool_handlers/execution_runtime/run.py)、[本机执行器](../companion_v01/local_execution_runtime/executor.py)、[等待参数](../companion_v01/execution_specs.py) | `background=true` 排除了后续等待，但初始执行仍会经过默认等待；初始等待归一化最小值为 1 秒。 | 明确后台真正跳过初始等待，不以传入 0 又被归一化成 1 秒的方式实现；默认前台与共享预算衔接。 |

| [模型收尾](../companion_v01/engine_services/turn_rounds.py)、[活跃结果](../companion_v01/host_completion_work.py)、[子任务](../companion_v01/host_subagent_jobs.py) | 正常收尾和工具预算耗尽路径仍可能无期限等待相关任务；子任务提交也可能被批等待器额外等待。 | 转入后台后不再隐式强制等待。只收集就绪结果，需要结果时由模型明确查询或等待。 |

- [x] 由宿主接入层统一提供可选 `background`，默认前台。调度参数在业务校验和调用前正确提取，不随意透传给插件或 MCP；模型工具定义、宿主校验和实际行为一致。先检查同名业务字段冲突，不静默覆盖原参数。

- [x] 保留普通写入、发送等动作的调用顺序，不再因前置调用返回后台 ID 就推定后续调用均依赖它。独立命令可同批并发；需要前一步结果或会相互影响的操作由模型分轮提交，实际资源校验照常执行。

### 11.5 必须验收的行为

| 场景 | 验收要求 |
| --- | --- |
| 原来标为 `sync` 的普通工具快速完成 | 正常返回完整实际结果，提前结束等待，没有多余任务通知。 |
| 同一普通工具慢于前台预算 | 在预算到期后交还控制权；ID 可查询，执行次数为 1，最终结果正常追加。 |
| 同一工具显式后台 | 返回耗时只包含必要受理，不等待工具完成、初始 1 秒或 8 秒窗口。 |
| A 后台 30 秒，B 前台 2 秒 | 约 B 完成时继续模型，同时带 A 的 ID 和 B 的结果；A 不额外阻塞。 |
| 多个默认前台任务分别需 2、6、20 秒 | 共享预算内收齐前两项，第三项返回原任务 ID；所有调用回应配齐，未完成项不取消。 |
| 前一批已经转后台，后一批只有一个快工具 | 不重新等待前一批；已完成则顺手追加，未完成不影响快工具返回。 |
| 快慢任务及未启动的并发排队项 | 排队与运行状态真实，预算不按工具数累加，后续仍可启动和完成。 |
| 默认前台刚在窗口边界完成 | 要么直接交付终态，要么先交还再追加；不丢失、不重复，也不产生第二个任务。 |
| 图片、文件、角色或工作区状态更新、分页结果转后台 | 接回与正常直接返回相同的必要业务效果和可读内容，权限与客户端归属不变。 |
| 查到运行中、查到终态，以及多页回读 | 运行中不消费未来终态；终态已交付不重复通知；续页仍能读取。控制操作不生成嵌套任务。 |
| 后台任务之后还有独立调用 | 后续调用正常执行，不因前置任务未完成而拒绝；真正依赖的操作分轮提交，资源校验仍保留。 |
| 模型已准备最终回复，任务尚未完成 | 不再由宿主强制等完；进度回复可及时交付，完成后按原策略续接。 |
| 工具预算耗尽但有未完成任务 | 不进入无期限等待，不按秒数重开模型请求，未消费结果可正常后续交付。 |
| 受理失败、执行超时、用户停止、授权变化或重启 | 原因和状态真实，未确认停止不报已取消，副作用不自动重做，旧状态不覆盖新选择。 |
| 连续工具轮及请求重试 | 已发布前缀和冻结输入保持稳定；一次配置或工具定义变更可重建，不能每轮改变定义。 |

实现阶段执行 `git diff --check`、相关 Python 编译和必要行为回归；触及桌宠交互再运行对应 build 和浏览器验收。真实 QQ、桌宠和上游缓存需单独记录，离线通过不能代替线上验证。缓存目标继续守住至少 95%，同时记录提示 token、命中 token、模型请求次数及上游口径，避免把首轮重建或供应商变化归因于调度本身。

完成标准：覆盖表中的普通业务工具都接通真实链路，三个调用分支与完整结果接回通过；性能、配对、消费去重和客户端交付可核验。明确记录任何未覆盖入口、无法取消的执行或外部服务限制；未完成项不能记作已经统一。是否提交和重启按后续用户指令执行。

| 子代理与控制 | 提交不增加第二层任务。`exec_status`、`exec_cancel` 支持原 job_id，并校验会话、角色、渠道、操作者和 child 范围；控制请求直接执行，显式等待最多 60 秒，提前完成则提前返回。 |
| 完整结果 | 原正文与分页、状态更新、文件事件、原始对话及私有图片输入保存在同一任务记录。活跃和闲置续接恢复这些字段；图片只进入 provider 图像输入，MemCore 保存来源信息，文字提示中不包含像素。 |

主循环正常收尾和预算耗尽均只收集已就绪结果，不再无限 join。流式进度可以及时交付；已经发出的消息不会被迟到结果替换，剩余完成事实交还原闲置路由。子代理也移除隐式最终等待：需要结果时显式查询；若提前结束 child，则按既有作用域关闭规则请求取消未完成工作，未确认停止返回失败，不把它转交父会话执行。

宿主统一增加可选 `background`。业务字段同名时改用 `host_background`；该名字再冲突时继续加 `host_` 前缀，不覆盖原契约。规则只注入稳定区一次，工具轮不重复加长尾部。直接拿到终态后解除待办引用；迟到完成以事件追加，原生调用只配一个结果。重启丢失普通调用的原执行绑定时返回 `original_execution_context_lost_no_replay`，不重建上下文后重跑。

完成收集只读取活跃就绪引用与轻量消费凭据，直接利用已结算的完整结果；没有全库扫描或重复全文读取。有效模型响应后，同批消费凭据与完成状态在一个事务中保存，失败整体回滚，正文分页不受影响。日志分别记录受理、业务执行、前台等待和结果投影耗时。

本地测量：30 次轻量调用的直接执行中位数 0.131 毫秒，受管执行中位数 43.537 毫秒、P95 48.969 毫秒；没有固定 8 秒延迟。34 个消费回执逐项落库曾耗时约 677 毫秒，合并事务后约 15 毫秒。12 个完成项共 61,118 字节，收集耗时 8.854 毫秒，结果全文重读 0 次。数字仅测宿主，不能据此推算网络、模型或真实客户端的总耗时。前缀稳定测试使用真实 MemCore 原生投影；实际命中率至少 95% 的目标仍要依据线上供应商计量核验。

验收入口新增 `test_tool_foreground_execution`，并扩展 `test_tool_completion_boundary`、`test_subagent_engine` 及原生/兼容 schema 测试，覆盖非流式和流式、共享预算、完整结果、私有图片、分页、依赖屏障、排队取消、重复 ID、原绑定丢失和消费事务回滚。未修改前端；本轮无需前端构建。

### 11.7 命令期限与交付规则（2026-10-08）

命令默认持续运行到完成或取消。统一命令 schema、兼容参数入口、执行契约与本机执行器的默认期限为 `0`，移除 600 秒上限；正数是调用者明确要求的终止期限，非法期限在启动前拒绝。前台和显式后台使用同一个期限契约，交还控制权不重启命令，也不取消任务。

模型说明只在既有稳定区表达一次：交付依赖结果时继续查询或等待，进度不是完成；用户明确要求后台运行或先回复时可结束本轮。最终回复不增加字段，宿主不隐式等待全部任务，完成通知与 MemCore 工具历史结算继续沿用既有机制。

本地验证使用真实子进程并仅推进执行监视器的时钟，覆盖超过 600 秒仍运行、前台和后台的默认期限、显式 `0`、显式长期限、短期限确认终止、原 ID 与输出续读；另测非法期限不启动进程及完整工具受理后的参数传递。时钟推进不代表实际持续执行了十分钟；模型是否持续等待交付仍需真实会话验证。

工具说明同步清理：公共调度规则留在稳定区，受理回执统一只返回 `job_id`、状态和重复提交标记，不再重复附加“无需轮询”等规则。状态查询明确等待窗口不终止任务；取消说明同时覆盖命令与普通工具。子任务提示明确共享前台窗口、立即后台和等待所需结果，其结束会取消未完成工作的原有边界保留。
