# 插件活动代次拆分与失败边界验收

## 职责与入口

原 `companion_v01/plugin_active_generation.py` 的 1,140 行实现已迁到 `active_generation_runtime/`。原文件保留 69 行兼容入口，历史类、导入绑定和 `__all__` 继续可用。

| 模块 | 行数 | 职责 |
|---|---:|---|
| `snapshot.py` | 227 | 完整候选快照、声明验证、只读索引、能力与 QQ 命令归属 |
| `bindings.py` | 202 | 调用冻结、作用域继承、服务绑定、worker 引用与授权状态 |
| `lifecycle.py` | 337 | 串行发布与关闭、候选准备与回滚、授权撤销、旧 worker 排空和清理状态 |
| `dispatch.py` | 186 | 能力、事件、Hook 与 QQ 命令在真实调用链上的转发 |
| `runtime.py` | 279 | 单一活动指针与共享状态、能力绑定、稳定的 Bot 调用桥接 |

这些职责模块继续使用同一个运行时、锁、授权表和 worker 生命周期表。候选准备中的临时集合只在发布前使用；成功后统一接入原生命周期表。没有新增服务容器或持久化状态副本。

能力绑定和三个桥接类与运行时留在同一模块，使原有类型注解能继续被 `typing.get_type_hints()` 解析；作用域创建能力绑定时用一个局部导入避免循环。没有按单个方法继续拆文件。

## 调用与清理约定

同一轮调用冻结其已见插件版本，新增插件可按原规则加入；子作用域继承父作用域的版本引用。普通升级先公开新快照，再等待旧调用和旧作用域释放，最后停止旧 worker。移除插件、能力撤销与停止运行时仍使对应授权失效，Host 任务撤销继续经过既有回调。

事件队列、Hook 和 QQ 命令沿用原 broker 及真实调用端口。发布之后的事件协调失败继续保留已公开候选的所有权，并报告 `plugin_event_reconcile_failed`。发布和关闭的取消仍经过 SDK 的 `drain()`，完成已开始的内部清理后再返回；当内部操作本身失败时，保留该失败异常。

worker 和服务作用域的清理未确认成功时，生命周期记录与安装目录引用继续保留。既有已结束 retirement 的失败记录保留原有行为；本轮没有增加后台清理重试调度器。准备回滚留下的未清理候选会在下一次成功发布或停止时进入正常 retirement，确认清理成功后移除对应失败记录。

## 复现与修复

1. 已在 retirement 中的候选原来会先撤销当前代次的 Host 任务，再拒绝发布。现在先完成状态与生命周期校验。
2. 候选的服务初始化原来发生在能力授权撤销、生命周期表修改之后；初始化失败时，旧快照虽未替换，旧能力已不能调用，外层运行时甚至会在获取旧绑定时抛出 `KeyError`。现在先准备所有候选服务作用域，并复核候选是否仍运行，再进入原有授权撤销与发布步骤。
3. 批量初始化失败或主动取消时，新开的作用域原来不会回滚。现在反向关闭已尝试打开的作用域，包括发生部分初始化后抛出异常的那一个；原有服务作用域保持原引用。回滚关闭失败会保留所有权和稳定失败代码，不覆盖原始准备异常，也不允许把该未清理候选重新发布。
4. 服务作用域关闭异常原来被吞掉，清理仍报告完成并移除生命周期记录。现在报告 `plugin_service_scope_close_failed`，保留未确认关闭的记录。
5. worker 仅返回 `ok: true` 原来就会被视为已清理。现在同时要求返回 `status: stopped` 且 worker 不再运行，否则报告 `plugin_generation_stop_incomplete`。原有停止失败原因仍优先保留。

新增 `tests/test_plugin_active_generation_boundaries.py` 的 14 项检查，覆盖初始化失败/取消、批量回滚、失败后的重试、准备期间退出、回滚关闭异常、慢回滚被取消、串行发布、服务清理失败、停止结果误报、重复发布、父子作用域引用及外层运行时失败后仍调用旧版本。用拆分前原始源码运行这 14 项，12 项失败，另 2 项保护重复发布和父子作用域的既有行为；最终全部通过。
