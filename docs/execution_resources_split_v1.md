## 所有权与调用链

`ExecutionResourceBridge` 采用静态 mixin 组合。所有方法访问同一桥接实例、同一份 `_bindings`、原有状态锁和登记锁，没有第二份资源存储、运行时方法注入或实现模块反向导入入口。

运行控制归属与资源会话 scope 继续分别保存。QQ 群成员的运行控制权限和群会话的附件/产物归属不变；生成文件继续由既有服务登记成真实 `gen_*` 句柄。原始附件、生成文件存储和持久项目目录的归属规则保留。

输入暂存和持久项目快照共用 `_pending_run_ids`，使用原状态锁原子预留运行 ID。锁只保护准入及状态发布，不包住文件复制或快照读取；不同运行 ID 可以继续独立暂存。失败后在 `finally` 中释放预留，允许同一 ID 重试，尚未发布的预留不会显示成可用资源绑定。

正常完成后的输出登记仍由执行接线层的权威终态触发，重复登记复用同一产物句柄。取消、超时和失败继续走既有失败收尾。持久项目绑定不拥有项目目录，任何登记或快照失败都不删除项目；临时清理只作用于工作区内由运行创建的 `.akane_exec_runs/<run_id>`。

## 同轮复现与修复

1. 原逻辑只检查已发布的绑定。同一 ID 的两个请求可能同时通过检查，覆盖绑定或互删暂存文件。现在输入暂存和项目快照共用原子准入，重复请求返回 `duplicate_execution_run_id`，保留首个请求的材料及输出声明。
2. 原逻辑按路径字符串判重，`out.txt` 与 `./out.txt`、中间点目录及 Windows 大小写别名可能覆盖前一个输入。现在按解析后的目标路径判重，并拒绝把 `.` 当作输入文件目标；现有工作目录 `.` 协议保留。
3. 原逻辑可以接管已存在的运行目录，清理 helper 也未验证目录归属。现在只创建新目录，拒绝目录连接/符号链接重定向，递归清理前验证直接父目录、运行 ID 和解析后的位置，保留已有文件及工作区外目录。当前 Windows 环境的真实目录连接检查通过。
4. 原逻辑按创建时间清理所有一小时前的绑定，可能删除仍在运行或暂时无法确认终态的材料。现在仅淘汰已收尾的旧回执；未确认结束的运行保留，后续确认完成仍能登记原文件。未收尾绑定不会仅凭年龄自动清理，需由既有执行收尾调用关闭，或随桥接实例生命周期结束。
5. 输入文件在检查/读取间消失、授权项目目录被删除、项目快照失败，以及输出在匹配/变更判断间消失，原先可能直接抛出文件系统异常。现在输入/项目准备返回稳定拒绝原因，失败准备释放准入；消失的输出不登记，不制造产物成功，结果保持幂等。

新增 `tests/test_execution_resource_boundaries.py` 的 18 项检查使用真实临时附件、生成文件服务、项目目录和可控制的线程同步。覆盖同一 ID 的并发暂存/快照、不同 ID 的慢请求、失败重试、等价路径、已有目录、目录连接、长运行、旧回执清理，以及输入/输出/授权目录消失。首批 14 项在修复前复现 12 个失败方法，修复后全部通过；补充的授权目录删除检查也先复现原始异常，再确认结构化拒绝。
