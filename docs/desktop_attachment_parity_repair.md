## 当前轮附件后端切片

- 桌面本地导入图片不再启动旧视觉摘要观察器；图片仍通过共享 Inbox 落盘和记事件。
- 普通同步/流式聊天接收 `current_attachment_ids`，只解析当前身份、会话、角色的
  精确 ID。路径、模糊 latest、其他角色或会话的 ID 不可绑定到当前轮。
- 原图准备复用共享 `prepare_native_image_inputs`；旧 QQ 方法只保留薄适配。
  文件材料标签进入当前用户尾部上下文，原图进入实际多模态输入，附件 ID 写入消息元数据。
- 本轮 `inspect_attachment(latest)` 优先遵循明确绑定，不被更新的工作台材料抢走。
- 视觉不可用保留材料绑定并给出未载入提示，不伪称看过图片；音频标签不代表转写或播放。

验证覆盖真实导入/Inbox 到同步与流式主链路、作用域拒绝、材料工具、原图路由，
以及同一模型下变更附件只改变 provider 消息尾部、不改变稳定前缀与缓存键。
这证明请求结构保持前缀，并不代表远端 provider 实际命中 KV 缓存。

## 待发送区与追加消息切片

- 立绘拖入、控制中心添加/拖入/粘贴共用主窗口的 scoped 附件草稿和上传队列。
  卡片返回真实附件 ID；上传中不能先发出缺附件的消息。上传失败、重复操作和
  切身份/会话/角色/后端有明确处理，不把旧草稿恢复到新作用域。
- 音频默认作为材料待发送，只有点击播放才启动音乐；重复导入复用同角色的相同
  内容，按 SHA-256 比较，不仅比较名字和大小。接收失败不返回假成功。
- 正常消息和忙碌中的追加都携带附件 ID；宿主在安全边界重新解析其作用域，
  记录引用并向后续模型轮次提供原始图片。持久队列仍保存引用，不保存图片副本。
- 控制中心忙碌时同时展示追加与停止；实时刷新保留输入焦点和选区，作用域切换
  清空旧草稿；聊天滚动恢复使用即时定位，避免平滑滚动被下一次刷新重置。
- 桌宠附件卡片加入原生点击区域，避免按钮看得见却点穿到后面的窗口。
