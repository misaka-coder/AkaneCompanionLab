# 系统笔记参考样本索引

这个文件夹保存用户已经认可的高质量系统笔记样本。

写新笔记时，不要机械模仿长度、标题或语气。要阅读样本，理解它们为什么能让用户学懂。

## 系统笔记的不可变标准

一篇好的系统笔记必须让用户读完后形成一个相对完整的知识模块，而不是只知道几个概念名。

它应该尽量做到：

- 有完整的学习路线和模块大图。
- 把概念、例子、代码、项目场景连接起来。
- 主动解释用户可能卡住的地方。
- 告诉用户第一遍需要掌握到什么程度。
- 能复习、能跟练、能迁移到项目。
- 读完后用户可以少依赖零散教程，遇到问题再查资料或问 AI 就能继续推进。

不同主题可以有不同组织形式和语言风格，但“系统”这一点不能丢。

## 阅读建议

正式写笔记前，按任务类型读取 2-4 篇样本。

读样本时重点观察：

- 开头如何建立学习动机。
- 如何先给全局地图，再逐层展开。
- 代码和解释如何穿插。
- 哪些地方提前提醒“第一遍不用全懂”。
- 如何把项目中的真实位置和通用知识连接起来。
- 如何让用户读完产生“我好像真的掌握了一个模块”的感觉。
