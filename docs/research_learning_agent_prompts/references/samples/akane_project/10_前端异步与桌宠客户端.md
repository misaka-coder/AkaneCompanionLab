# 前端异步与桌宠客户端

> 前几篇我们一直站在后端视角。  
> 这一篇开始站到“客户端”这一侧：用户点发送之后，Akane 是怎样一点点说话、变表情、播放语音、打开文件、感知桌面的。

这一篇和 `04_HTTP_JSON与流式响应.md` 有重叠，但重点不同：

```text
04 HTTP / JSON / 流式响应：
重点是通信协议本身。
比如 StreamingResponse、NDJSON、请求体、响应体。

10 前端异步与桌宠客户端：
重点是客户端如何消费这些协议。
比如 fetch、ReadableStream、TextDecoder、AbortController、
事件分发、UI 状态、TTS 队列、口型同步、桌宠本地能力。
```

Akane 当前项目里有三类客户端代码：

```text
web/app.js
网页预览客户端。
用浏览器 fetch 请求后端，直接展示对话、背景、立绘、语音。

desktop_pet/
Electron 桌宠客户端。
有 preload IPC 桥接，可以访问本地窗口、文件、桌面上下文。

desktop_pet_next/
Tauri 桌宠客户端。
更接近产品化桌宠：窗口、设置、工作区、文件交付、音乐队列、屏幕感知。
```

它们背后的核心链路是同一个：

```text
用户输入
-> 客户端 POST /think
-> 后端 StreamingResponse 返回 NDJSON 事件
-> 客户端逐行解析事件
-> 根据事件更新 UI / 表情 / 气泡 / TTS / 文件 / activity
-> 收到 final 或 final_ui 后渲染最终回复
```

## 一、这一篇学什么

学习路线：

```text
JavaScript 异步基础
-> Promise / async / await
-> fetch 普通 JSON 请求
-> AbortController 超时与中断
-> ReadableStream 流式读取
-> NDJSON 一行一事件
-> Akane /think 前端链路
-> 事件驱动 UI
-> TTS 队列与音频播放
-> Live2D 口型同步
-> 桌宠 client_mode / capabilities
-> 桌面上下文与屏幕感知
-> activity 播放控制
-> 文件交付与工作区
-> 前端合同测试
```

先给结论：

```text
前端异步不是“代码写得花”。
它解决的是：多个慢事情同时发生时，界面仍然不乱。
```

在 Akane 里，“慢事情”很多：

```text
LLM 生成回复慢
RAG 检索可能慢
TTS 合成语音慢
音频播放有时长
Live2D 加载资源慢
桌面截图需要权限
文件生成可能在后台慢慢完成
```

所以前端必须会处理：

```text
请求正在进行
请求失败
请求被取消
已经收到一部分文字
最终 payload 还没到
TTS 队列还没播完
文件生成好了但还没交付
用户又发了下一句话
```

这就是这篇笔记的核心。

## 二、前端异步到底在解决什么

JavaScript 在浏览器里通常是单线程执行 UI 逻辑。

如果一个操作会耗时，比如请求后端：

```js
const response = fetch("/think");
```

它不能把整个页面卡住。  
所以浏览器把这个任务交出去，等它完成后再回来继续执行。

这就是异步。

可以先记一个非常重要的模型：

```text
同步代码：
立刻执行，执行完才往下走。

异步代码：
先发起任务，未来某个时刻再回来处理结果。
```

浏览器里常见异步来源：

```text
setTimeout
fetch 网络请求
用户点击事件
音频播放事件 ended / error
ReadableStream 流式读取
requestAnimationFrame 动画帧
文件拖拽
桌面 IPC / Tauri invoke
```

---

## 三、Promise 是异步结果的容器

Promise 可以理解为：

```text
一个现在还没拿到，但未来会拿到的结果。
```

它有三个状态：

```text
pending    进行中
fulfilled  成功
rejected   失败
```

浏览器控制台可运行：

```js
const task = new Promise((resolve) => {
  setTimeout(() => {
    resolve("后端返回结果");
  }, 1000);
});

console.log("1. 发起任务");

task.then((result) => {
  console.log("3. 拿到结果：", result);
});

console.log("2. 同步代码继续执行");
```

输出顺序大概是：

```text
1. 发起任务
2. 同步代码继续执行
3. 拿到结果：后端返回结果
```

这说明：

```text
Promise 不会阻塞当前代码。
```

## 四、async / await：让异步代码写起来像同步

Promise 直接 `.then()` 可以用，但多层任务会变得很绕。

所以现代前端更常用：

```js
async function main() {
  const result = await task;
  console.log(result);
}
```

`async` 的意思是：

```text
这个函数内部可以 await。
这个函数本身会返回 Promise。
```

`await` 的意思是：

```text
暂停当前 async 函数，等 Promise 完成。
注意：不是暂停整个浏览器页面。
```

浏览器控制台可运行：

```js
function wait(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

async function demo() {
  console.log("开始");
  await wait(800);
  console.log("800ms 后继续");
}

demo();
console.log("demo 已经发起，但页面没有卡住");
```

这就是 Akane 前端大量函数写成 `async function` 的原因。

比如 `web/app.js` 里：

```js
async function sendMessage(message) {
  // 发请求、读流、更新 UI、处理错误
}
```

如果不用 `async / await`，这条链路会非常难读。

## 五、事件循环：为什么 await 不会卡死页面

可以把浏览器想成有一个任务队列：

```text
同步代码先执行
遇到异步任务就挂起
等异步任务完成后，把回调放回队列
浏览器空了再继续执行
```

浏览器控制台可运行：

```js
console.log("A 同步");

setTimeout(() => {
  console.log("D setTimeout");
}, 0);

Promise.resolve().then(() => {
  console.log("C Promise then");
});

console.log("B 同步");
```

常见输出：

```text
A 同步
B 同步
C Promise then
D setTimeout
```

先不用纠结宏任务、微任务的细节。  
目前你只要抓住这个：

```text
前端异步不是多线程魔法。
它是把未来完成的任务排回事件队列。
```

这对 Akane 很关键，因为：

```text
用户输入、网络流、TTS、动画、按钮点击都在事件队列里交错发生。
```

写前端客户端，本质是在管理这些事件的顺序。

## 六、fetch：前端请求后端的核心 API

普通 JSON 请求通常长这样：

```js
async function requestJson(url, options = {}) {
  const response = await fetch(url, options);
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }
  return response.json();
}
```

Akane 的 `web/app.js` 里也有类似的 helper：

```js
async function requestJson(url, options = {}) {
  const response = await fetch(url, options);
  if (!response.ok) {
    const message = `HTTP ${response.status}`;
    throw new Error(message);
  }
  return response.json();
}
```

普通 POST JSON 请求：

```js
async function postJson(url, payload) {
  const response = await fetch(url, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(payload),
  });

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  return response.json();
}

postJson("/think_once", {
  user_id: "demo_session",
  real_user_id: "master",
  message: "伙伴，今天学什么？",
}).then(console.log);
```

这里有三个关键点：

```text
method: "POST"
表示发送数据给后端。

headers: {"Content-Type": "application/json"}
告诉后端请求体是 JSON。

body: JSON.stringify(payload)
把 JS 对象转成 JSON 字符串。
```

后端 FastAPI 才能这样读取：

```python
payload = await request.json()
```

## 七、response.ok 不等于业务成功

`response.ok` 只表示 HTTP 状态码是 2xx。

比如：

```text
200 OK       response.ok 是 true
400 Bad     response.ok 是 false
500 Error   response.ok 是 false
```

但是业务上可能返回：

```json
{
  "ok": false,
  "error": "invalid_payload",
  "message": "Payload must be a JSON object"
}
```

所以前端通常要分两层判断：

```js
async function requestBusinessJson(url, options) {
  const response = await fetch(url, options);

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  const payload = await response.json();
  if (payload.ok === false) {
    throw new Error(payload.message || payload.error || "业务失败");
  }

  return payload;
}
```

Akane 的桌宠健康检查、工作区、附件上传、诊断接口都属于这种“普通 JSON 请求”。  
而 `/think` 是特殊的，因为它不是一次性 JSON，而是流式 NDJSON。

## 八、AbortController：请求超时和主动取消

一个请求可能一直不回来。  
前端不能无限等下去，所以要用 `AbortController`。

基本写法：

```js
async function fetchWithTimeout(url, options = {}, timeoutMs = 10_000) {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => {
    controller.abort();
  }, timeoutMs);

  try {
    const response = await fetch(url, {
      ...options,
      signal: controller.signal,
    });
    return response;
  } finally {
    clearTimeout(timeoutId);
  }
}
```

调用：

```js
try {
  const response = await fetchWithTimeout("/health", {}, 5000);
  console.log(await response.json());
} catch (error) {
  if (error.name === "AbortError") {
    console.log("请求超时，被前端取消");
  } else {
    console.log("请求失败", error);
  }
}
```

Akane 的 `web/app.js` 里发送 `/think` 时也用了这个模式：

```js
const controller = new AbortController();
timeoutId = setTimeout(() => controller.abort(), THINK_REQUEST_TIMEOUT_MS);

const response = await fetch(`/think?t=${Date.now()}`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  cache: "no-store",
  signal: controller.signal,
  body: JSON.stringify(payload),
});
```

注意一个细节：

```text
fetch 的 Promise 通常在收到响应头后就 resolve。
如果是流式响应，后续 body 还要继续读。
```

所以超时策略有两层：

```text
请求发起阶段：
AbortController 负责不要一直等响应头。

流读取阶段：
靠 stream_error / stream_end / turnToken / 用户中断来收尾。
```

这就是为什么 Akane 前端还会维护：

```js
const streamState = {
  started: false,
  ended: false,
  streamErrored: false,
  streamErrorMessage: "",
  hadPartialSpeech: false,
};
```

请求不是“发出去了就完了”。  
前端还要记住这条流现在走到哪里。

## 九、为什么 /think 不能只用 response.json()

普通接口是：

```text
请求一次
等待后端全部处理完
返回一个 JSON
```

但 LLM 回复可能很慢。  
如果前端一直等最终结果，用户看到的就是：

```text
点发送
卡住很久
突然出现完整回复
```

体验很差。

Akane 需要：

```text
先显示“思考中”
模型一边生成，一边显示文字片段
中途可以先变表情
文件生成事件可以提前到达
最后再应用最终 payload
```

所以后端返回 NDJSON：

```text
{"type":"stream_start","contract_version":"desktop_pet.v0.1"}
{"type":"turn_start","speaker":"Akane"}
{"type":"ui","emotion":"开心"}
{"type":"speech_chunk","text":"主人，"}
{"type":"speech_chunk","text":"我在哦。"}
{"type":"final_ui","payload":{"emotion":"开心","speech":"主人，我在哦。"}}
{"type":"stream_end","status":"ok"}
```

NDJSON 的意思是：

```text
Newline Delimited JSON
一行一个 JSON 对象。
```

不能用：

```js
await response.json()
```

因为 `response.json()` 会等整个响应结束。  
流式 UI 要边到边处理，所以要读 `response.body`。

## 十、ReadableStream：前端怎样一块一块读响应

Akane `web/app.js` 里有一个核心函数：

```js
async function consumeNdjsonStream(response, onEvent) {
  if (!response.body) {
    throw new Error("浏览器不支持流式响应");
  }

  const reader = response.body.getReader();
  const decoder = new TextDecoder("utf-8");
  let buffer = "";

  while (true) {
    const { value, done } = await reader.read();
    if (done) {
      buffer += decoder.decode();
      break;
    }

    buffer += decoder.decode(value, { stream: true });

    while (true) {
      const newlineIndex = buffer.indexOf("\n");
      if (newlineIndex < 0) break;

      const line = buffer.slice(0, newlineIndex).trim();
      buffer = buffer.slice(newlineIndex + 1);
      if (!line) continue;

      let payload = null;
      try {
        payload = JSON.parse(line);
      } catch {
        continue;
      }
      await onEvent(payload);
    }
  }

  const tail = buffer.trim();
  if (tail) {
    const payload = JSON.parse(tail);
    await onEvent(payload);
  }
}
```

这段是本篇最重要的代码之一。

拆开看：

```js
const reader = response.body.getReader();
```

拿到响应体的读取器。

```js
const decoder = new TextDecoder("utf-8");
```

网络读到的是字节，需要转成字符串。

```js
buffer += decoder.decode(value, { stream: true });
```

把当前 chunk 解码后拼到缓冲区。

```js
const newlineIndex = buffer.indexOf("\n");
```

寻找换行符。  
因为 NDJSON 是一行一个事件。

```js
const line = buffer.slice(0, newlineIndex).trim();
buffer = buffer.slice(newlineIndex + 1);
```

取出一整行，剩下的继续留在 buffer。

为什么需要 buffer？

因为网络 chunk 不保证刚好按一行切。

可能实际收到：

```text
chunk 1: {"type":"speech_chunk","text":"主
chunk 2: 人"}\n{"type":"final_ui","payload":
chunk 3: {...}}\n
```

所以前端不能假设一个 chunk 就是一个 JSON。  
必须缓冲到换行符出现。

## 十一、可运行练习：模拟 NDJSON 流

这段代码可以在现代浏览器控制台运行。

```js
async function* readNdjsonEvents(response) {
  const reader = response.body.getReader();
  const decoder = new TextDecoder("utf-8");
  let buffer = "";

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split("\n");
    buffer = lines.pop() || "";

    for (const line of lines) {
      const trimmed = line.trim();
      if (!trimmed) continue;
      yield JSON.parse(trimmed);
    }
  }

  buffer += decoder.decode();
  const tail = buffer.trim();
  if (tail) {
    yield JSON.parse(tail);
  }
}

function makeFakeNdjsonResponse() {
  const encoder = new TextEncoder();
  const chunks = [
    '{"type":"stream_start"}\n{"type":"speech_chunk","text":"主',
    '人，"}\n{"type":"speech_chunk","text":"我在哦。"}\n',
    '{"type":"final_ui","payload":{"speech":"主人，我在哦。"}}\n',
  ];

  const stream = new ReadableStream({
    async start(controller) {
      for (const chunk of chunks) {
        await new Promise((resolve) => setTimeout(resolve, 500));
        controller.enqueue(encoder.encode(chunk));
      }
      controller.close();
    },
  });

  return new Response(stream);
}

async function demo() {
  const response = makeFakeNdjsonResponse();
  for await (const event of readNdjsonEvents(response)) {
    console.log("收到事件：", event);
  }
}

demo();
```

你会看到事件不是一次性出现，而是隔一段时间一个个出现。

这就是 Akane 流式回复的前端基础。

## 十二、Akane /think 后端流式事件从哪里来

后端在 `companion_v01/routes/think.py` 里返回：

```python
return StreamingResponse(
    _stream(),
    media_type="application/x-ndjson",
    headers={
        "Cache-Control": "no-store",
        "X-Akane-Contract": DESKTOP_PET_CONTRACT_VERSION,
        "X-Accel-Buffering": "no",
    },
)
```

核心生成器逻辑是：

```python
yield json.dumps({
    "type": "stream_start",
    "contract_version": DESKTOP_PET_CONTRACT_VERSION,
}, ensure_ascii=False) + "\n"

for event in engine.process_turn_stream(payload):
    yield json.dumps(event, ensure_ascii=False) + "\n"

yield json.dumps({
    "type": "stream_end",
    "contract_version": DESKTOP_PET_CONTRACT_VERSION,
    "status": "ok" if ok else "error",
    "partial": partial,
}, ensure_ascii=False) + "\n"
```

所以前端读到的每一行，其实都是后端 `yield` 出来的一个事件。

如果中间出错，后端会发：

```json
{
  "type": "stream_error",
  "contract_version": "desktop_pet.v0.1",
  "error": "think_stream_failed",
  "message": "stream failed: ...",
  "retryable": true,
  "partial": {
    "emotion": "开心",
    "speech": "已经生成的一部分内容",
    "event_count": 7
  }
}
```

这个设计很重要：

```text
即使最终失败，前端仍然可能拿到 partial，展示已经生成的部分。
```

这就是“流式系统”的韧性。

## 十三、web/app.js 的 sendMessage 主线

网页预览的主入口在 `web/app.js`：

```js
async function sendMessage(message) {
  const trimmed = String(message || "").trim();
  if (!trimmed || state.sending) return false;

  unlockAudio();
  await stopVoicePlayback();
  await fetchManifest();

  const streamState = {
    started: false,
    ended: false,
    endStatus: "",
    streamErrored: false,
    streamErrorMessage: "",
    hadPartialSpeech: false,
  };

  setSendingState(true);
  resetStreamedDialogueText();
  setStatus("thinking");
  dialogueTextEl.classList.add("is-pending");
  dialogueTextEl.textContent = THINKING_TEXT;

  try {
    const controller = new AbortController();
    timeoutId = setTimeout(() => controller.abort(), THINK_REQUEST_TIMEOUT_MS);

    const response = await fetch(`/think?t=${Date.now()}`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      cache: "no-store",
      signal: controller.signal,
      body: JSON.stringify({
        user_id: expectedSessionId,
        real_user_id: expectedProfileUserId,
        message: trimmed,
        client_mode: "scene_static",
        client_capabilities: [
          "speech_segments",
          "background",
          "bgm",
          "static_sprite",
          "audio_playback",
          "tts",
          "choices",
          "tool_actions",
        ],
        current_visual: state.currentVisual,
      }),
    });

    await consumeNdjsonStream(response, async (event) => {
      const maybeFinalPayload = await handleThinkStreamEvent(event, streamState);
      // final payload 到达后应用到 UI
    });
  } catch (error) {
    // 超时、网络错误、流错误、恢复逻辑
  } finally {
    setSendingState(false);
  }
}
```

这段可以拆成 7 步：

```text
1. 清洗用户输入
2. 防止重复发送
3. 停止上一轮语音
4. 设置 UI 为 thinking
5. POST /think
6. 消费 NDJSON 流
7. 收尾或错误恢复
```

这就是一个典型的前端异步业务函数。

## 十四、事件分发：handleThinkStreamEvent

读到一行 JSON 后，前端不能只打印。  
它要根据 `type` 做不同动作。

Akane 的网页预览使用：

```js
async function handleThinkStreamEvent(event, streamState = null) {
  const eventType = String(event?.type || "").trim().toLowerCase();
  if (!eventType) return null;

  if (eventType === "stream_start") {
    streamState.started = true;
    return null;
  }

  if (eventType === "turn_start") {
    speakerTagEl.textContent = String(event?.speaker || DEFAULT_SPEAKER).trim();
    resetStreamedDialogueText();
    return null;
  }

  if (eventType === "ui") {
    await applyStreamEmotion(event?.emotion);
    return null;
  }

  if (eventType === "speech_chunk") {
    const text = String(event?.text || "");
    appendStreamedDialogueText(text);
    appendSpeechForTts(text);
    return null;
  }

  if (eventType === "final_ui") {
    return event?.payload || null;
  }

  if (eventType === "final") {
    return event?.payload || null;
  }

  if (eventType === "stream_error" || eventType === "error") {
    streamState.streamErrored = true;
    streamState.streamErrorMessage = String(event?.message || "stream failed");
    return null;
  }

  if (eventType === "stream_end") {
    streamState.ended = true;
    streamState.endStatus = String(event?.status || "");
    return null;
  }

  return null;
}
```

这种写法叫：

```text
事件驱动 UI。
```

不是前端主动问后端：

```text
现在该变表情了吗？
现在该说话了吗？
现在文件好了没？
```

而是后端推事件，前端按事件更新。

## 十五、Akane 常见流式事件表

可以把 `/think` 事件按功能分组。

```text
stream_start
流开始。前端可以记录 contract_version。

turn_start
一轮回复开始。前端显示 thinking，清空旧文字。

ui
轻量 UI 更新，比如 emotion。

speech_chunk
增量文本片段。网页预览会边到边显示。

speech_segment
分段文本。桌宠 next 会优先展示第一个片段，让气泡更快出现。

npc_turn
多角色或 NPC 发言。

final_ui
给 UI 用的最终 payload。通常可以立即应用。

final
最终业务 payload。可用于 debug、存档或兜底。

stream_error / error
流中途失败。可能带 partial。

stream_end
流结束。可能 status=ok，也可能 status=error。
```

工具和工作区相关事件：

```text
reminder_set
提醒设置完成。

reminder_list
提醒列表。

reminder_cancelled
提醒取消。

inventory_snapshot
礼物/物品快照。

gift_updated
礼物状态变化。

作品状态变化。

persona_state
人设卡状态变化。

file_ready
普通文件准备完成。

generated_file_ready
生成文件准备完成。

task_worker_delegated
后台任务已委派。
```

桌宠动作相关：

```text
activity
模型希望桌宠执行的轻量动作请求。
比如 play / pause / resume / stop / next / previous。
```

注意：

```text
activity 是执行请求，不是执行成功回执。
```

这个点在 Akane 的测试里被反复保护。

## 十六、final_ui 和 final 的区别

你可以先简单理解：

```text
final_ui：
前端 UI 优先使用的最终展示 payload。

final：
完整最终结果，可能更偏业务记录、调试、兼容。
```

在 `web/app.js` 里，两者都会返回 payload：

```js
if (eventType === "final") {
  return event?.payload || null;
}

if (eventType === "final_ui") {
  // 同时收尾 TTS
  return event?.payload || null;
}
```

在桌宠客户端里，也会这样处理：

```js
if (type === "final" || type === "final_ui") {
  const payload = event?.payload || event;
  renderPayload(payload);
}
```

为什么需要两个？

因为不同客户端需要不同节奏：

```text
网页预览：
可以先根据 final_ui 刷 UI，再用 final 做 debug。

桌宠：
通常 final_ui / final 都能渲染，但要避免重复渲染。

后端：
可以逐步演进协议，不让老客户端一下子坏掉。
```

这就是协议兼容性。

## 十七、UI 状态机：不要让界面乱跳

发送消息时，界面至少有这些状态：

```text
idle       空闲
thinking   已发送，等待后端开始
streaming  正在接收 speech_chunk
final      最终结果已应用
error      出错
```

桌宠 next 还会有：

```text
offline
replying
music-playing
music-paused
```

最小状态机可以这样写：

```js
const uiState = {
  mode: "idle",
  text: "",
  error: "",
};

function reduceUiState(state, event) {
  const type = String(event?.type || "");

  if (type === "send") {
    return { mode: "thinking", text: "……", error: "" };
  }

  if (type === "speech_chunk") {
    return {
      ...state,
      mode: "streaming",
      text: state.text === "……" ? event.text : state.text + event.text,
    };
  }

  if (type === "final_ui" || type === "final") {
    return {
      mode: "final",
      text: event.payload?.speech || state.text,
      error: "",
    };
  }

  if (type === "error" || type === "stream_error") {
    return {
      ...state,
      mode: "error",
      error: event.message || "请求失败",
    };
  }

  return state;
}

let current = uiState;
current = reduceUiState(current, { type: "send" });
current = reduceUiState(current, { type: "speech_chunk", text: "主人，" });
current = reduceUiState(current, { type: "speech_chunk", text: "我在哦。" });
current = reduceUiState(current, {
  type: "final_ui",
  payload: { speech: "主人，我在哦。" },
});

console.log(current);
```

Akane 没有把 UI 状态机抽成一个纯 reducer，但实际逻辑是类似的：

```js
setSendingState(true);
setStatus("thinking");
appendStreamedDialogueText(text);
setStatus("final");
setStatus("error");
```

学习重点不是某个函数名，而是这种思维：

```text
每个事件只能让 UI 从合法状态转到另一个合法状态。
```

## 十八、为什么要防止重复发送

`sendMessage` 开头有：

```js
if (!trimmed || state.sending) return false;
```

这是非常重要的工程细节。

如果不防重复，用户连续点两下发送：

```text
请求 A 发出
请求 B 发出
A 先返回 speech_chunk
B 再返回 final
A 又返回 final
UI 被两个回复交叉污染
```

前端会乱。

所以要么：

```text
发送中禁用按钮
```

要么：

```text
每一轮请求有 turnToken，旧请求回来也不允许更新 UI。
```

桌宠 next 用了类似概念：

```js
let activeTurnToken = 0;

function isTurnActive(turnToken) {
  return turnToken === activeTurnToken;
}
```

流式 UI 的基本原则：

```text
只有当前轮次的事件可以更新当前 UI。
```

## 十九、TTS 队列：文字和语音为什么要分段

Akane 网页端语音逻辑在 `web/modules/audio.js`。

大致流程：

```text
收到 speech_chunk
-> 拼到 ttsTextBuffer
-> 遇到句号、问号、感叹号等切一段
-> 每段请求 /tts
-> 得到 audio blob
-> URL.createObjectURL
-> 放入播放队列
-> 按顺序播放
-> 播完 revokeObjectURL
```

为什么不等完整回复再 TTS？

```text
等完整回复再合成：
语音开始慢。

边生成边分段合成：
第一句出来后就可以开始播。
```

Akane 的分段逻辑类似：

```js
function findTtsSplitIndex(text) {
  const punctuation = new Set(["。", "！", "？", "!", "?", "；", ";"]);

  for (let index = 0; index < text.length; index += 1) {
    const char = text[index];
    if (punctuation.has(char)) {
      return index + 1;
    }
  }

  return -1;
}
```

简化版 TTS 队列：

```js
class SimpleTtsQueue {
  constructor(audioEl) {
    this.audioEl = audioEl;
    this.queue = [];
    this.playing = false;
    this.token = 0;
  }

  enqueue(text) {
    const normalized = String(text || "").trim();
    if (!normalized) return;
    this.queue.push(normalized);
    void this.pump();
  }

  stop() {
    this.token += 1;
    this.queue = [];
    this.audioEl.pause();
    this.audioEl.removeAttribute("src");
  }

  async pump() {
    if (this.playing) return;
    this.playing = true;
    const token = this.token;

    try {
      while (this.queue.length && token === this.token) {
        const text = this.queue.shift();
        await this.playText(text, token);
      }
    } finally {
      this.playing = false;
    }
  }

  async playText(text, token) {
    const response = await fetch("/tts", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ text }),
    });

    if (!response.ok) {
      throw new Error(`TTS HTTP ${response.status}`);
    }

    const blob = await response.blob();
    if (token !== this.token) return;

    const url = URL.createObjectURL(blob);
    try {
      this.audioEl.src = url;
      await this.audioEl.play();
      await new Promise((resolve) => {
        this.audioEl.addEventListener("ended", resolve, { once: true });
        this.audioEl.addEventListener("error", resolve, { once: true });
      });
    } finally {
      URL.revokeObjectURL(url);
    }
  }
}
```

这里的 `token` 很重要：

```text
如果用户中途发新消息，旧队列必须失效。
```

否则上一轮的语音可能会继续播放。

## 二十、浏览器音频限制：为什么要 unlockAudio

现代浏览器通常不允许页面自动播放声音。  
必须用户先有一次点击、按键等交互。

所以 Akane 发送消息时会调用：

```js
unlockAudio();
```

它的意义是：

```text
用户已经主动点击发送，可以认为音频播放被允许。
```

这类问题不是 Akane 特有，而是浏览器安全策略。

常见现象：

```text
第一次打开页面，BGM 播不了。
点一下页面后，BGM 才能播。
```

所以前端音频代码通常要准备：

```text
play() 可能失败
失败后提示“等待交互”
用户交互后重试
```

Akane 的 `playBgmWithFade()` 就是这个思路：

```js
try {
  await bgmPlayerEl.play();
  await fadeAudioTo(BASE_BGM_VOLUME);
} catch (error) {
  bgmPillEl.textContent = "... 等待交互";
}
```

## 二十一、BGM ducking：语音播放时压低背景音乐

Akane 在播放语音时会把 BGM 音量压低：

```text
语音开始
-> BGM 从正常音量淡到较低音量
-> 语音播放
-> 语音结束
-> BGM 恢复正常音量
```

这叫 ducking。

简化代码：

```js
async function fadeAudioTo(audioEl, targetVolume) {
  const current = audioEl.volume;
  const steps = 8;

  for (let step = 1; step <= steps; step += 1) {
    audioEl.volume = current + ((targetVolume - current) * step) / steps;
    await new Promise((resolve) => setTimeout(resolve, 40));
  }
}

async function playVoiceWithDucking({ bgmEl, voiceEl, voiceUrl }) {
  await fadeAudioTo(bgmEl, 0.22);
  voiceEl.src = voiceUrl;
  await voiceEl.play();

  await new Promise((resolve) => {
    voiceEl.addEventListener("ended", resolve, { once: true });
    voiceEl.addEventListener("error", resolve, { once: true });
  });

  await fadeAudioTo(bgmEl, 0.58);
}
```

这属于体验工程。  
虽然不是算法核心，但它决定桌宠是否“像一个活的客户端”。

## 二十二、Live2D 口型同步：声音如何变成嘴巴开合

Akane 的口型同步在 `web/modules/lip-sync.js`。

核心思路：

```text
HTMLAudioElement 播放语音
-> Web Audio API 创建音频图
-> AnalyserNode 读取波形数据
-> 计算 RMS 音量
-> 映射到 0 到 1 的 mouth 值
-> avatarController.setMouth(value)
-> Live2D 参数 ParamMouthOpenY 改变
```

简化版：

```js
function rms(samples) {
  let sumSquares = 0;
  for (const sample of samples) {
    const centered = (sample - 128) / 128;
    sumSquares += centered * centered;
  }
  return Math.sqrt(sumSquares / samples.length);
}

function mapVolumeToMouth(volume) {
  const noiseFloor = 0.012;
  const gain = 8.2;
  const raw = Math.max(0, Math.min(1, (volume - noiseFloor) * gain));
  return Math.pow(raw, 0.72);
}
```

Akane 里对应代码：

```js
state.analyser.getByteTimeDomainData(state.samples);
const target = mapVolumeToMouth(readRmsVolume());
state.smoothMouth = state.smoothMouth * 0.64 + target * 0.36;
avatarController.setMouth(clamp(state.smoothMouth, 0, 0.95));
```

这里有两个细节：

```text
1. 要平滑 mouth 值
否则嘴巴会抖得很厉害。

2. 要有 fallback
如果 Web Audio API 不可用，就用随机嘴型模拟说话。
```

Akane 的 fallback 是：

```js
void avatarController.startTalking();
```

也就是不用真实音量分析，直接让嘴巴周期性动起来。

## 二十三、AvatarController：静态立绘和 Live2D 的边界

`web/modules/avatar.js` 负责角色渲染。

它支持两类模式：

```text
静态立绘。

Live2D 模型。
```

## 二十五、client_mode：同一个后端适配不同客户端

Akane 后端不是只服务一个 UI。

## 二十六、capabilities：客户端明确告诉后端自己会什么

`client_mode` 说明客户端类型。  
`client_capabilities` 说明客户端当前具体支持什么。

比如桌宠 next：

```js
const BASE_CAPABILITIES = ["speech_segments", "tts", "file_drop", "tool_actions"];
const AUDIO_PLAYBACK_CAPABILITY = "audio_playback";

function buildClientCapabilities() {
  const capabilities = [...BASE_CAPABILITIES, AUDIO_PLAYBACK_CAPABILITY];
  if (state.desktopContextEnabled) capabilities.push("desktop_context");
  if (state.screenVisionEnabled && state.screenVisionMode === "summary") {
    capabilities.push("screen_vision");
  }
  return capabilities;
}
```

这很像硬件驱动或浏览器特性检测：

```text
我支持 TTS，你可以给我 speech_segments。
我支持 audio_playback，你可以给我 activity 播放控制。
我支持 desktop_context，你可以在 prompt 里使用桌面上下文。
我不支持 screen_vision，你就不要假设我能看屏幕。
```

为什么不用后端自己猜？

因为同一个 `desktop_pet` 模式下，用户可能关闭了某些能力：

```text
关闭桌面上下文
关闭屏幕感知
关闭语音播放
使用旧客户端
```

能力必须显式传。

Akane 测试里有一个非常关键的约束：

```text
如果前端显式传 capabilities，但不含 audio_playback，
后端不应该自动补上 audio_playback。
```

原因是：

```text
旧客户端或禁用音频的客户端可能无法执行 activity。
后端不应该让模型输出它执行不了的动作。
```

## 二十七、output adapter：不同客户端拿到不同字段

否则每个客户端都要自己处理一堆无关字段。

## 二十八、桌宠 BackendClient：把后端包装成可用 SDK

Electron 桌宠里有：

```text

```

这个文件本质是桌宠前端的后端 SDK。

```text

解析 NDJSON
轮询提醒
拉取资源清单
上传音频
获取工作区
```

`sendMessage` 是一个 async generator：

```js
async *sendMessage({
  profileUserId,
  sessionId,
  message,
  clientMode,
  capabilities,
  currentVisual,
  desktopContext,
  currentActivity,
}) {
  const response = await fetch(`${this.baseUrl}/think?t=${Date.now()}`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    cache: "no-store",

      message,
      client_mode: clientMode,
      client_capabilities: capabilities,
      current_visual: currentVisual || {},
      desktop_context: desktopContext || null,
      desktop_activity: currentActivity || null,
    }),
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder("utf-8");
  // 逐行 yield JSON.parse(line)
}
```

注意这个写法：

```js
for await (const event of client.sendMessage(...)) {
  // 一个事件一个事件处理
}
```

这比回调更清晰：

```text
BackendClient 负责“怎么读流”。
业务层负责“读到事件后怎么显示”。
```

## 二十九、async generator 是什么

普通 async function 返回一个 Promise。

```js
async function getOneValue() {
  return 1;
}
```

async generator 可以返回一串异步值。

```js
async function* countSlowly() {
  yield 1;
  await new Promise((resolve) => setTimeout(resolve, 500));
  yield 2;
  await new Promise((resolve) => setTimeout(resolve, 500));
  yield 3;
}

async function demo() {
  for await (const value of countSlowly()) {
    console.log(value);
  }
}

demo();
```

`/think` 流非常适合 async generator：

```text
一个请求
很多事件
事件之间有等待
前端按顺序处理
```

所以桌宠客户端写成：

```js
const gen = client.sendMessage({...});
await processStream(gen);
```

这种结构很漂亮，值得学。

## 三十、桌宠 processStream：最终 payload 决定正式展示

Electron 桌宠的 `processStream` 有一个重要策略：

```text
speech_chunk 只保存成 partialSpeech。
真正正式展示由 final / final_ui 决定。
```

简化逻辑：

```js
async function processStream(gen) {
  let finalPayload = null;
  let partialSpeech = "";

  for await (const event of gen) {
    const type = String(event?.type || "").trim().toLowerCase();

    if (type === "turn_start") {
      showThinking();
    } else if (type === "ui") {
      applyEmotion(event);
    } else if (type === "speech_chunk") {
      partialSpeech += String(event?.text || "");
    } else if (type === "final" || type === "final_ui") {
      finalPayload = event.payload;
      renderAuthoritativePayload(finalPayload);
    } else if (type === "stream_error") {
      renderTerminalFallback({
        speech: event.partial?.speech || partialSpeech,
      });
    }
  }
}
```

为什么网页端可以边到边显示，桌宠却更谨慎？

因为桌宠气泡空间更小，而且 TTS、表情、动作都要配合最终分段。

如果边到边显示所有 chunk，可能会出现：

```text
中途文本显示了
最终 speech_segments 又来了
气泡重复
TTS 播两遍
```

所以桌宠更偏：

```text
partial 用于失败兜底。
final payload 才是权威展示。
```

这是很重要的客户端策略差异。

## 三十一、PresentationController：桌宠展示层





也就是说：

```text

前端就按分段展示和播放。
```

## 三十二、TtsPlayer：桌宠语音播放队列

Electron 桌宠有独立的：

```text
desktop_pet/renderer/services/TtsPlayer.js
```

核心职责：

```text
接收文本或 segments
逐段请求 /tts
拿到 blob
audioEl 播放
播完下一段
stop 时取消请求、清空队列、释放 URL
```

这和网页端 `audio.js` 是同类思想，只是封装成了类。

关键代码结构：

```js
class TtsPlayer {
  speakSegments(segments) {
    const items = segments.map((item) => this._normalizeText(item)).filter(Boolean);
    if (!items.length || !this._enabled) return;

    this.stop();
    this._queue.push(...items);
    void this._pumpQueue();
  }

  async _pumpQueue() {
    if (this._pumpActive || !this._enabled) return;
    this._pumpActive = true;

    try {
      while (this._enabled && this._queue.length > 0) {
        const text = this._queue.shift();
        await this._playText(text);
      }
    } finally {
      this._pumpActive = false;
    }
  }
}
```

这是典型队列模式。

你以后做任何“按顺序执行的异步任务”，都可以套这个思路：

```text
queue 存任务
pump 负责消费
active 防止多个 pump 并发
token 防止旧任务污染新任务
stop 负责中断和清理
```

## 三十三、activity：桌宠动作协议

Akane 的桌宠不只是显示文字。  
模型还可以请求桌宠做轻量动作。

比如：

```json
{
  "activity": {
    "action": "play",
    "target": "current",
    "source_id": "workspace:attachment:audio_001"
  }
}
```

支持的动作大致是：

```text
play
pause
resume
stop
next
previous
```

注意这句话：

```text
activity 是给桌宠执行的请求，不是执行成功回执。
```

也就是说模型输出：

```json
{"activity":{"action":"play","target":"current"}}
```

不代表音乐已经播放成功。  
只是告诉客户端：

```text
请你尝试播放当前音频。
```

客户端执行时还可能失败：

```text
没有当前音频
文件不存在
系统禁止播放
格式不可播放
用户关了音频能力
```

所以客户端要执行并反馈 UI。

Electron 里是：

```js
activityRuntime.applyAction(payload.activity)
```

Tauri next 里是：

```js
applyPayloadActivity(payload)
```

后端和测试会保护：

```text
只有 desktop_pet 且有 audio_playback capability 时，activity 才应该保留。
web / QQ 不应该收到 activity。
```

## 三十四、ActivityRuntime：本地音频播放动作执行器

Electron 桌宠的：

```text
desktop_pet/renderer/services/ActivityRuntime.js
```

负责管理当前音频活动：

```text
当前播放对象
播放状态 ready / running / paused / stopped
进度
时长
附件 handle
生成文件 handle
timeline 状态
```

核心动作：

```js
async applyAction(actionPayload) {
  const action = this._normalizeAction(actionPayload);
  if (!action || this._isDuplicateAction(action)) return false;

  if (action.action === "play") {
    await this._play(action);
    return true;
  }
  if (action.action === "pause") {
    this._pause({ nextStatus: "paused" });
    return true;
  }
  if (action.action === "resume") {
    await this._resume();
    return true;
  }
  if (action.action === "stop") {
    this._stop();
    return true;
  }
}
```

这个类不是简单调用 `audio.play()`。  
它还要做：

```text
去重
解析 target
确认音频源可用
等待播放真的有进度
失败提示
同步 activity state
给音乐 timeline 做准备
```

前端客户端越接近产品，越需要这种“执行器类”。

## 三十五、桌面上下文：让模型知道用户当前环境

```js
async function collectDesktopContextForTurn() {
  if (!state.desktopContextEnabled) return null;

  let foreground = null;
  if (isTauriRuntime) {
```

## 三十七、文件交付：模型生成文件后客户端怎么处理

Tool Calling 之后，后端可能生成文件。

前端会收到：

```text
file_ready
generated_file_ready
```

桌宠 next 有：

```js
function applyPayloadFileDeliveries(payload) {
  const events = Array.isArray(payload?.tool_events) ? payload.tool_events : [];
  for (const event of events) {
    const type = String(event?.type || "").trim().toLowerCase();
    if (type === "file_ready" || type === "generated_file_ready") {
      void handleDesktopFileDeliveryEvent(event);
    }
  }
}
```

文件交付事件可能带：

```json
{
  "type": "generated_file_ready",
  "send_to_user": true,
  "delivery_action": "open",
  "generated_file": {
    "generated_handle": "gen_001",
    "output_title": "复习计划",
    "absolute_path": "F:/..."
  }
}
```

客户端根据 `delivery_action` 做动作：

```text
open
打开文件。

reveal
打开文件所在文件夹。

save_desktop
导出到桌面 Akane Outputs。

copy_path
复制文件路径。
```

对应 Tauri 命令：

```js
await tauriCall("open_local_file", { path: filePath });
await tauriCall("show_item_in_folder", { path: filePath });
await tauriCall("export_file_to_desktop", { path: filePath, fileName });
```

这就是桌宠客户端的本地能力价值。

网页只能下载或显示链接；桌宠可以直接帮你打开本地结果。

## 三十八、文件交付为什么要去重

流式事件可能在两个地方出现：

```text
1. 作为独立事件 file_ready / generated_file_ready
2. 出现在 final payload 的 tool_events 里
```

如果前端不去重，可能会：

```text
打开同一个文件两次
重复弹气泡
重复刷新工作区
```

所以桌宠 next 维护了：

```js
const desktopFileDeliveryHandled = new Set();
```

然后生成 key：

```js
function desktopFileDeliveryEventKey(event, fileRef, action) {
  const id = String(
    fileRef.path ||
      event?.file?.source_id ||
      event?.generated_file?.generated_id ||
      fileRef.handle ||
      ""
  ).trim();
  return id ? `${String(event?.type || "")}:${action || "workspace"}:${id}` : "";
}
```

这是前端工程里很常见的模式：

```text
事件可能重复到达，
客户端必须保证副作用只执行一次。
```

打开文件、播放音频、扣库存、提交表单都属于副作用。  
副作用一定要小心去重。

## 四十一、Tauri fetch 和浏览器 fetch 的差异

桌宠 next 里有：

```js
import { fetch as tauriFetch } from "@tauri-apps/plugin-http";

function backendFetch(input, init) {
  if (isTauriRuntime) {
    return tauriFetch(input, init);
  }
  return window.fetch(input, init);
}
```

为什么 Tauri 要用 plugin-http？

因为桌面应用里的网络请求可能涉及：

```text
CORS
本地后端访问
系统代理
桌面权限
打包环境差异
```

用 Tauri 插件可以更稳定地从桌面壳发请求。

但上层业务不应该到处判断：

```js
if (isTauriRuntime) ...
```

所以封装成：

```js
backendFetch(...)
```

这就是适配层思维：

```text
底层环境不同，上层调用一致。
```

## 四十五、错误处理：流式客户端不能只 catch 一次

普通请求错误：

```text
fetch 失败
HTTP 非 2xx
JSON parse 失败
```

流式请求错误更多：

```text
响应头成功，但中途断流
某一行 JSON 损坏
后端 yield stream_error
后端没有 final
用户中途取消
旧 turnToken 回来
TTS 请求失败
音频播放失败
Live2D 加载失败
本地文件打不开
```

所以 Akane 前端有多层兜底：

```text
readNdjsonEvents
跳过 malformed line。

stream_error
记录 partial，显示已有 speech。

stream_end
如果有 partial，尝试终端兜底展示。

sendMessage catch
恢复输入框、停止语音、显示错误文案。

syncCurrentSessionAfterTurn
如果已经生成了部分内容，尝试同步后端最新 session。

TTS catch
显示语音播放失败，但不影响文本展示。
```

这是工程上非常重要的点：

```text
文本回复失败，不应该拖死整个桌宠。
TTS 失败，不应该让文字消失。
文件打开失败，不应该让工作区结果丢失。
```

一个成熟客户端要分级失败。

```html
        padding: 8px 14px;
      }
    </style>
  </head>
  <body>
    <div id="status">idle</div>
    <div id="bubble"></div>
    <form id="form">
      <input id="input" autocomplete="off" placeholder="对 Akane 说点什么" />
      <button id="send" type="submit">发送</button>
    </form>

    <script>
      const statusEl = document.querySelector("#status");
      const bubbleEl = document.querySelector("#bubble");
      const formEl = document.querySelector("#form");
      const inputEl = document.querySelector("#input");
      const sendEl = document.querySelector("#send");

      let sending = false;

      async function* readNdjsonEvents(response) {
        const reader = response.body.getReader();
        const decoder = new TextDecoder("utf-8");
        let buffer = "";

        while (true) {
          const { value, done } = await reader.read();
          if (done) break;

          buffer += decoder.decode(value, { stream: true });
          const lines = buffer.split("\n");
          buffer = lines.pop() || "";

          for (const line of lines) {
            const trimmed = line.trim();
            if (!trimmed) continue;
            try {
              yield JSON.parse(trimmed);
            } catch {
              // 跳过损坏行
            }
          }
        }

        buffer += decoder.decode();
        const tail = buffer.trim();
        if (tail) {
          yield JSON.parse(tail);
        }
      }

      function applyEvent(event) {
        const type = String(event?.type || "").toLowerCase();

        if (type === "stream_start") {
          statusEl.textContent = "stream_start";
        } else if (type === "turn_start") {
          statusEl.textContent = "thinking";
          bubbleEl.textContent = "……";
        } else if (type === "ui") {
          statusEl.textContent = `emotion: ${event.emotion || ""}`;
        } else if (type === "speech_chunk") {
          if (bubbleEl.textContent === "……") bubbleEl.textContent = "";
          bubbleEl.textContent += event.text || "";
          statusEl.textContent = "streaming";
        } else if (type === "final" || type === "final_ui") {
          const speech = event.payload?.speech || "";
          if (speech) bubbleEl.textContent = speech;
          statusEl.textContent = "final";
        } else if (type === "stream_error" || type === "error") {
          statusEl.textContent = `error: ${event.message || "failed"}`;
          if (event.partial?.speech) bubbleEl.textContent = event.partial.speech;
        } else if (type === "stream_end") {
          statusEl.textContent = `end: ${event.status || ""}`;
        }
      }

      async function sendMessage(message) {
        if (sending) return;
        sending = true;
        sendEl.disabled = true;
        bubbleEl.textContent = "……";
        statusEl.textContent = "sending";

        try {
          const response = await fetch(`/think?t=${Date.now()}`, {
            method: "POST",
            headers: { "Content-Type": "application/json" },
            cache: "no-store",
            body: JSON.stringify({
              user_id: "mini_client_session",
              real_user_id: "master",
              message,
              client_mode: "scene_static",
              client_capabilities: ["speech_segments", "choices", "tool_actions"],
            }),
          });

          if (!response.ok) {
            throw new Error(`HTTP ${response.status}`);
          }

          for await (const event of readNdjsonEvents(response)) {
            applyEvent(event);
          }
        } catch (error) {
          statusEl.textContent = `failed: ${error.message || error}`;
        } finally {
          sending = false;
          sendEl.disabled = false;
        }
      }

      formEl.addEventListener("submit", (event) => {
        event.preventDefault();
        const text = inputEl.value.trim();
        if (!text) return;
        inputEl.value = "";
        void sendMessage(text);
      });
    </script>
  </body>
</html>
```

这段代码覆盖了本篇最核心的能力：

```text
fetch POST JSON
读取 NDJSON
事件分发
UI 状态
防重复发送
错误处理
```

如果你能看懂这份 mini client，再去看 `web/app.js` 就不会完全无从下手。

## 五十一、最后用一句话总结

前端异步与桌宠客户端的核心不是“会写页面”。

它真正训练的是：

```text
当后端、模型、语音、文件、桌面环境都在异步变化时，
客户端如何用稳定的协议和状态管理，把这些变化组织成自然的用户体验。
```

Akane 的桌宠客户端值得学。  
它不是简单套壳页面，而是一个很完整的 AI 产品客户端样本。
