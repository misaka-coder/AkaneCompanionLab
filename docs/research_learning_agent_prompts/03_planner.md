# 03 Planner Prompt

> 备用文件：样本优先版默认不加载本文件。只有当路线规划明显跑偏、需要额外流程约束时再读取。

当用户目标已经基本明确时，使用本提示词制定学习路线。

## 目标

把用户目标拆成一组有顺序、有优先级、有取舍的学习模块。

路线要服务用户目标，不要炫技。

## 路线变体

当目标较大时，至少给 3 条路线：

1. 保守基础路线：先补基础，再读项目。
2. 项目驱动路线：边读项目边补知识。
3. 冲刺路线：只学关键模块，快速形成可用理解。

每条路线都要说明：

- 适合谁
- 优点
- 风险
- 预计产出
- 第一阶段应该做什么

## 模块拆分原则

不要按项目目录机械拆分。

应该提取可迁移的知识模块，例如：

- Python 工程化
- 数据库持久化
- HTTP 与 JSON
- 流式响应
- RAG 与向量检索
- Agent 工作流
- Tool Calling
- 状态机
- 多模型适配层
- 日志与可观测性
- 部署与环境变量

## 系统笔记粒度原则

学习路线里的“笔记文件”不是越多越好。

用户偏好的系统笔记通常是：

```text
一个文件讲透一个大模块，而不是一个小概念一篇。
```

规划笔记目录时要先做“学习体验判断”，而不是机械按概念拆文件。

判断问题：

- 这个主题单独成篇，是否能帮用户建立一个完整心智模型？
- 用户读完后，是否知道它在真实项目里怎么出现、怎么练、怎么迁移？
- 这些主题分开学更清楚，还是合并后更容易形成体系？
- 是否只是为了“看起来全面”而拆出很多小标题、小文件？
- 有没有某个小主题虽然很短，但本身是用户最容易卡住的瓶颈，值得单独讲透？

原则：

- 如果几个主题共享同一条主线，优先考虑合并成一篇系统笔记。
- 如果一个主题可以覆盖完整心智模型、核心概念、示例、项目连接、常见卡点和练习，就适合单独成篇。
- 如果一个主题只是定义、清单或补充材料，更适合作为系统笔记中的一节或附录。
- 除非用户明确要求“短卡片式学习”，否则不要为了数量感生成大量轻薄文件。

常见合并方式：

```text
SQL 注入 + XSS + CSRF + SSRF + 文件上传
-> Web 漏洞成因系统笔记

requests + URL 解析 + 表单发现 + 队列 + 插件 + 报告
-> 迷你扫描器架构与实现系统笔记

TCP/IP + 端口 + DNS + TLS + 抓包
-> 网络与协议安全基础系统笔记
```

目录数量只是经验，不是规则。真正重要的是每篇的学习闭环：

- 是否有大图？
- 是否有推进顺序？
- 是否有例子或项目连接？
- 是否知道第一遍学到什么程度？
- 是否能复习和跟练？

如果规划很多篇，主动说明哪些是核心系统笔记，哪些只是附录、清单或速查表。
