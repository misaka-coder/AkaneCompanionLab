# 06 Knowledge Mapping Prompt

> 备用文件：样本优先版默认不加载本文件。知识模块拆分优先参考用户高质量样本的组织方式。

当项目结构已经初步清楚，需要把项目内容转成学习模块时，使用本提示词。

## 目标

从项目中提取可迁移的通用知识模块，而不是照搬项目目录。

## 提取标准

一个模块值得写成系统笔记，通常满足至少一个条件：

- 经典基础知识
- 工程中高频使用
- 时代前沿方向
- 对用户专业成长有帮助
- 能显著提升项目理解能力
- 能迁移到其他项目

低价值、过细、只需知道存在的内容，不应该占用大量笔记篇幅。

## 模块粒度判断

知识模块提取后，要再做一次合并判断。

不要把每个概念都单独写成笔记。系统笔记应该覆盖一个“完整学习模块”，而不是一个术语、一个漏洞、一个工具按钮或一个小函数。

如果一个候选模块只能自然写出：

```text
定义
几条列表
一个很短的示例
检查清单
```

它更像知识卡片，不一定适合单独成为系统笔记。可以把它合并到更大的系统模块里，或者作为附录/速查表。

系统笔记通常应该能自然容纳：

- 模块大图和学习路线
- 核心概念逐层拆解
- 多个最小可运行示例
- 项目或真实资料连接
- 常见卡点和误区
- 必学/略读/暂时不用学
- 练习和掌握检查
- 能迁移到其他项目的总结

篇幅不是目标，只是信号。短笔记可以很好，前提是它完成了清晰的学习闭环；长笔记也可能失败，如果只是堆内容。判断时优先看：用户读完是否真的理解了模块，是否知道下一步怎么练，是否能把知识迁移到项目里。

## 合并优先级

优先合并这些小主题：

- 同一套底层模型下的多个概念
- 同一条工程流程上的多个步骤
- 同一类问题的多个变体
- 同一个项目最终会连续实现的多个模块

例如：

```text
不要拆成：
08_SQL注入.md
09_XSS.md
10_CSRF.md
11_SSRF.md
12_文件上传.md

更适合合成：
04_Web漏洞成因系统笔记_SQLi_XSS_CSRF_SSRF_文件上传.md
```

```text
不要拆成：
requests基础.md
URL解析.md
表单爬取.md
队列去重.md
XSS插件.md
SQLi插件.md
报告输出.md

更适合合成：
07_迷你Web安全扫描器架构与插件系统.md
```

但不要为了合并而合并。如果某个小主题本身是关键瓶颈，例如“认证状态为什么会丢”“Attention 里张量形状为什么变来变去”，也可以单独成篇讲透。

## 输出内容

每个知识模块要包含：

- 模块名称
- 为什么要学
- 用户需要学到什么程度
- 项目中的对应代码或资料
- 必学内容
- 略读内容
- 暂时不用学的内容
- 迁移价值
- 推荐笔记标题
- 预计深度：系统笔记 / 知识卡片 / 附录
- 是否建议与其他模块合并

## 输出模板

```text
知识模块 1：
名称：
为什么重要：
项目对应位置：
必学：
略读：
暂时不用学：
迁移价值：
推荐笔记：
预计深度：
是否合并：

知识模块 2：
...

推荐阅读顺序：

反碎片化合并结果：

第一篇建议：
```

## 重要提醒

不要平均用力。

如果一个模块很重要，要明确告诉用户“这个值得深学”。

如果一个模块只是工程胶水，要明确告诉用户“知道它存在即可”。
