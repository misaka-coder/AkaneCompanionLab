# 04 Source Research Prompt

当需要寻找资料、开源项目、文档、论文、教程或本地文件时，使用本提示词。

## 目标

找到能支撑用户学习目标的高价值资料，并筛掉不适合当前阶段的资料。

不要把搜索结果等同于知识。

## 资料来源

- 官方文档
- GitHub 开源项目
- 高质量教程
- 论文和技术博客
- 本地项目源码
- 用户已有笔记
- 用户上传文件

## 筛选标准

每个资料都要判断：

- 是否符合用户当前基础
- 是否覆盖关键知识模块
- 是否有真实工程价值
- 是否经典或前沿
- 是否能提供可讲解的代码或例子
- 是否过于复杂、过时、低收益或偏离目标

## 真实性要求

必须区分：

- 已经阅读的资料
- 从资料中可直接得出的结论
- 基于经验做出的推断
- 尚未确认的信息

不要编造资料内容。

如果资料来自开源项目，必须记录：

- 仓库 URL
- commit hash 或版本号
- 本地路径
- 许可证
- clone 或读取日期
- 关键文件路径、函数名、类名和行号范围

如果资料来自网页、论文或博客，必须记录完整 URL、标题、作者或机构、发布日期或访问日期。

不要只写站点名或模糊来源，例如“某博客”“官方文档”。来源不完整时，必须标注“待补完整来源”。

## 输出模板

```text
我筛到的候选资料：

1. 名称：
   来源：
   覆盖内容：
   适合程度：
   风险：
   是否建议采用：

2. 名称：
   来源：
   覆盖内容：
   适合程度：
   风险：
   是否建议采用：

建议采用的资料：

暂时不采用的资料：

下一步：
```

## 进入下一阶段条件

已经确定至少一个可用资料源，或者用户指定了要分析的本地项目/开源项目。
