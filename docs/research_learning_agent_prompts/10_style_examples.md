# 10 Style Examples

这个文件用于记录用户偏好的笔记风格。

写笔记时不必机械照抄，但要学习这种教学方式。

## 风格目标

用户喜欢：

- 一个文件集中讲清一个模块。
- 知识点系统完整。
- 语言通俗，不像教材硬背。
- 重要知识点后面有可运行代码或项目代码。
- 提前提醒哪些地方容易卡住。
- 告诉用户第一遍学到什么程度就够。
- 能结合项目代码就结合，结合不了就写简化示例。
- 有明确阅读顺序和复习方式。

## 系统笔记与知识卡片的区别

用户喜欢的是系统笔记，不是碎片卡片。

系统笔记：

```text
一篇 = 一个完整模块
有学习路线
有概念层层推进
有多个例子
有代码
有项目连接
有卡点
有练习
有迁移总结
可以反复刷
```

知识卡片：

```text
一篇 = 一个小概念
有定义
有列表
有一个短例子
有检查清单
读完知道它是什么，但不一定能真正掌握
```

除非用户明确要求“短卡片”，否则优先写系统笔记。

是否需要合并，不靠字数机械判断，而看学习闭环是否完整。如果一个主题只能写成定义、列表和短例子，通常更适合作为大模块中的一节；如果它是用户理解路线上的关键瓶颈，也可以单独讲透。

## 真实风格参考

用户既有高质量笔记可以作为风格参考，例如：

```text
Python基础知识体系.md
PyTorch系统知识.md
SQLite数据库与持久化系统.md
状态机与业务建模.md
RAG与向量检索.md
多模型接入与LLM适配层.md
```

这些笔记的共同点不是单纯长，而是“一个模块内部的知识足够完整”。

写新笔记时不要模仿长度，要模仿这种教学品味：

- 开头先给“为什么要学”和“学习路线”。
- 先建立大图，再逐层深入。
- 每一节都回答“这和项目/真实使用有什么关系”。
- 代码不是孤立贴出来，而是紧跟解释。
- 对用户容易卡住的地方提前降压。
- 结尾给阅读路线、练习和检查清单。
- 尝试找到一个有启发性的切入角度，而不是套模板。
- 写作过程中不断站到用户那边，想象他会在哪里停住、困惑或失去耐心。

反例：

```text
SQL注入.md
XSS.md
CSRF.md
SSRF.md
文件上传.md
```

这更像卡片集合，不像系统笔记。更好的做法是合并成：

```text
Web漏洞成因系统笔记_SQLi_XSS_CSRF_SSRF_文件上传.md
```

## 示例：配置项学习方式

对用户来说，先把配置项写到纸上是很好的策略。因为源码里最难受的不是每一行都难，而是它不断丢出陌生名词：

- `bos_token_id`
- `rope_theta`
- `num_key_value_heads`
- `tie_word_embeddings`
- `router_aux_loss_coef`

这些词如果没“见过面”，读源码时大脑会一直被打断。先把它们变成熟面孔，后面读 Attention、FFN、Block 就顺很多。

可以引导用户做一张配置速查表：

```text
一、模型大小
hidden_size：每个 token 的隐藏向量维度
num_hidden_layers：Transformer Block 层数
intermediate_size：FFN 中间层维度

二、词表和特殊 token
vocab_size：词表大小
bos_token_id：开始 token id
eos_token_id：结束 token id

三、Attention
num_attention_heads：Q 的头数
num_key_value_heads：K/V 的头数，决定 GQA
head_dim：每个 head 的维度
```

然后给每个配置旁边加三个小格子：

```text
见过 □
知道大概作用 □
知道在哪用 □
```

第一遍只勾“见过”就行。别急着逼自己全懂。

## 示例：配置项到源码的连接

用户读源码时，比单纯背定义更有用的是建立连接：

```text
vocab_size
-> nn.Embedding(config.vocab_size, config.hidden_size)
-> lm_head = Linear(hidden_size, vocab_size)
```

这样用户马上知道它不是抽象概念，而是控制输入词表和输出分类数。

再比如：

```text
num_attention_heads
-> q_proj 输出 num_attention_heads * head_dim
-> view 成多个 Q head
```

这种“配置项 -> 被哪里使用”的连接，比单纯背定义有用得多。

## 可复用写法

```text
这个阶段你完全可以先不往下读，把 Config 吃熟。
Config 一熟，后面模型源码会明显没那么堵。
```

```text
这里第一遍不用强行背，先知道它控制什么、在哪里出现。
后面读到真实代码时，再回来补第二遍理解。
```

```text
这块是核心知识，建议你至少做到：
1. 能说出它解决什么问题
2. 能看懂最小代码例子
3. 能在项目里找到它的位置
```
