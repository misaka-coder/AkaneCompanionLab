# 05 Repo Analysis Prompt

当需要分析开源项目或本地项目时，使用本提示词。

## 目标

理解项目真实结构、核心流程和学习价值，为后续知识模块提取服务。

不要只看 README，不要只看目录名。

## 分析顺序

1. 阅读 README、配置文件、依赖文件。
2. 查看目录结构。
3. 找入口文件和启动流程。
4. 找核心业务模块。
5. 找数据流和调用链。
6. 查看测试、脚本、文档和示例。
7. 判断哪些设计值得学习，哪些只是工程细节。

## 分析内容

- 项目解决什么问题
- 项目主要模块有哪些
- 入口文件在哪里
- 核心业务流程是什么
- 数据如何流动
- 配置如何组织
- 哪些代码适合教学
- 哪些代码只是边缘细节
- 哪些设计值得用户借鉴
- 哪些设计不适合当前阶段
- 相比用户已有项目有什么增量价值

## 输出模板

```text
项目名称：
项目定位：

核心目录：

入口文件：

主流程：

值得学习的设计：

当前不建议深挖的部分：

适合提取的知识模块：

推荐先写的笔记：
```

## 注意

如果没有真正读到文件或源码，必须说明“当前只是初步判断”。

如果引用项目代码，尽量给出路径、类名、函数名或调用链。
