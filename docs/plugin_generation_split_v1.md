# plugin_generation 进程边界拆分 v1

`companion_v01/plugin_generation.py` 从 1274 行调整为 87 行兼容入口。6 个实现模块按完整职责划分；沿用原来的工作进程、回调路由、编解码、产物存储和技能导出实现。

原 `__all__` 的 6 项公开导出、69 个历史模块绑定，以及原方法的签名和装饰器继续保留。纯搬迁阶段，55 个原方法及 10 个原辅助函数（含 `main`）的 AST 一致；收尾仅有 5 个原方法因异常路径修复而改变，原辅助函数仍一致。

## 真实调用链与兼容性

`BotRuntimeFactory` 装配 `PluginGenerationRuntime`，候选构建器通过原入口创建进程；工作进程仍由 `plugin_generation_worker` 创建 `PluginHost`，候选发布及旧版本保留继续由既有换代运行时负责。

工具与事件调用继续使用 `GenerationHostCallbackRouter` 的授权和资源作用域。取消信号仍等待工作进程的真实终态，再处理依赖结果与产物交接；原产物安全校验、清理和权限校验保持原调用链。QQ 组合代理继续让宿主命令优先。

历史 `python -m companion_v01.plugin_generation` worker 入口仍转发到 `plugin_generation_worker.main`。QQ 组合代理和进程类放在同一个实现模块，公开构造与工厂签名的类型注解可通过 `typing.get_type_hints` 正常解析。

## 异常路径修复

- JSON 序列化或 UTF-8 编码失败时，在登记等待项、设置停止状态和写管道前拒绝请求。非 JSON、循环值、非有限数及不可编码字符都有明确错误，失败请求不再留下等待项。
- 输入管道已经关闭时，返回既有不可用原因并移除本次等待项；不重新执行可能已经开始的请求。
- 可关联的宿主回调结果无法编码时，使用原回调标识返回 `callback_result_invalid`，使插件收到失败原因；不回显原结果、不重发通知。
- 读取线程构造或启动失败时，终止已创建的子进程并关闭管道，返回既有不可用原因；收尾不再尝试等待未启动的线程。
- 调用作用域初始化失败或取消时，释放已经登记的回调授权。作用域清理抛错或取消时仍结清调用计数，同时保留清理异常，避免停止流程等待一个已经结束的调用。

拆分过程中补充了公开类型注解的反射检查，将 QQ 组合代理与进程类保留在同一模块，避免跨模块前向引用在运行时解析失败。
