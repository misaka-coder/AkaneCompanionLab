# 插件一等公民与宿主统一交互链路 V1

状态：设计已确定；后台插件的 Agent-event RPC 已由宿主统一路由到 QQ 与桌宠的正常 Agent 回合。

日期：2026-09-04

## 1. 核心决定

插件可以隔离运行，但不能拥有一套与 Akane 不同的用户交互语义。

安装插件后：

```text
本轮可用能力 = Akane Core 能力 + 当前实例启用的插件贡献
```

插件贡献的工具、事件、提示块、Skill、Hook 和后台服务都通过宿主公开契约进入同一个
运行时。插件不直接取得 Engine、MemCore、QQ Gateway 或数据库对象；宿主通过受控接口提供
等价的能力和真实结果。

“隔离”只表示进程、权限、存储和协议边界，不表示角色、人设、记忆、模型回合或表现层另起
一套实现。

插件包的安装、实例启用和贡献适用渠道是三个不同概念：

- 同一实例只安装并激活一份插件，不为 QQ 和桌宠分别安装；
- 是否启用由实例选择决定，不由某个聊天窗口临时复制一套运行时；
- 每项贡献用 `visible_in` 声明真实适用面。通用工具可同时声明 `desktop/qq`，QQ 指令只属于
  QQ，读取屏幕等本地能力只属于桌宠；
- 市场和控制中心后续只展示同一插件卡片，并根据实际贡献生成渠道徽标，不伪造全渠道支持。

## 2. 三种明确语义

插件产生的内容必须属于以下一种语义，不能混用：

### 2.1 `internal`

只供插件内部处理。不会进入模型当前回合，不写 MemCore，也不会产生用户可见消息。

### 2.2 `current_turn` / `timeline`

插件报告一个已经发生的外部事实。插件可以声明它只参与本轮，或写入当前会话时间线。

宿主负责：

- 解析目标会话；
- 恢复 `profile_user_id`、`session_id`、`character_pack_id` 和记忆域；
- 按宿主规则写入 MemCore；
- 在需要时启动一次普通 Agent 回合；
- 将事件和模型回复放入正常的上下文与渲染流程。

插件只表达业务语义，不能直接操作 MemCore，也不能自己拼装角色身份。

### 2.3 固定通知

插件已经拥有确定的机器文本，只需要可靠投递时，才使用通知端口。

固定通知不是角色回复：

- 不启动模型；
- 不继承角色人设；
- 不写入助手对话，除非另有明确的时间线记录；
- 不得声称经过了 JSON、emotion、TTS 或角色渲染。

通知端口保留的原因是支持后台任务完成、系统状态变化等不需要模型参与的发送场景。

## 3. 统一模型回合

所有“希望当前角色做出回应”的来源都必须进入同一个 Agent 主入口：

```text
用户消息 / 插件事件 / 桌宠事件 / 外部事件
        ↓
目标会话解析
        ↓
正常上下文构建（角色、MemCore、工具、Skill、当前事件）
        ↓
正常模型回合
        ↓
结构化输出解析
        ↓
QQ / 桌宠 / Web 等统一表现层
```

Agent-event 请求可将事件持久性声明为 `timeline`（默认）或
`current_turn`。两者都走同一模型与表现层；区别只在宿主是否把外部事实写入
当前会话的用户时间线。

`event` 中的结构化事实是持久化与幂等身份；`message` 是本次模型回合的处理说明。
插件升级可以改进处理说明而不改变同一事件的身份；若复用幂等键却改变事件事实，宿主仍按
冲突拒绝。不要把提示语、展示前后缀或客户端排版写进事件身份。

模型输出在到达表现层之前必须保持结构化。插件事件不能把模型结果提前压成纯文本，再交给
通知端口发送；否则会丢失 `emotion`、`speech`、贴纸、TTS、引用和客户端能力适配。

事件持久性与回复展示是两个正交选择。默认回复继续使用客户端的普通实时/分段策略；确实
需要完整公告版式的事件可以请求 `text_delivery=single_message`，并提供有界的
`text_prefix/text_suffix`。宿主仍先完成同一个结构化 Agent 回合，只在 QQ 投递边缘把
`speech` 与前后缀合成一条消息；静默回复不发送空壳。这不是固定通知，也不创建第二套推理链。

## 4. 会话引用

后台插件创建延迟任务时，使用宿主提供的会话引用，而不是自行保存裸 QQ 用户号或角色名：

```text
conversation_ref
  -> session_id
  -> profile_user_id
  -> character_pack_id
  -> client/channel mode
  -> MemCore namespace
```

任务到期后，宿主根据会话引用恢复完整上下文。引用失效或上下文无法解析时，返回
`event_context_unresolved`，不得静默回退到全局默认人设。

会话引用同时包含来源渠道。宿主先验证引用，再交给该渠道的普通回合适配器；QQ 事件进入
现有 QQ 发送与结构化渲染，桌宠事件进入现有桌宠输出契约，并通过已连接的桌面卫星通道把
同一个 frame 交给气泡、表情、动作与 TTS。桌宠不在线时在启动模型前返回明确失败，不把
回复误送到 QQ 或另一实例。

如需从一个会话向另一个会话投递固定通知，插件必须明确使用固定通知语义；它不能把跨会话
通知伪装成原角色的上下文回复。

## 5. MemCore 规则

插件可以选择事件的持久性意图，但宿主是唯一写入者：

| 插件意图 | 当前回合 | 时间线 | 摘要/检索 |
| --- | --- | --- | --- |
| `internal` | 否 | 否 | 否 |
| `current_turn` | 是 | 否 | 否 |
| `timeline` | 是（如请求 Agent 回合） | 是 | 按 MemCore 正常策略 |

插件不负责决定摘要格式、向量索引或压缩代次。宿主按已有 MemCore 策略处理；`timeline` 只
表示“这个事实应进入时间线”，不表示必须永久进入所有检索结果。

模型因插件事件生成的助手回复，只要走正常 Agent 主入口，就按普通助手回复写入同一会话的
MemCore 时间线。

## 6. 现有接口的收敛

保留：

- `PluginEventResult.delivery` 的 `internal/current_turn/timeline` 语义；
- 隔离 worker、代次、权限和反向 RPC；
- `NotificationPort`，但仅用于固定通知；

已清理：

- 独立的插件推理端口及其权限、worker RPC、缓存指标和测试；
- “插件先生成纯文本，再调用固定通知端口发送”的组合；
- 任何在主动回合中跳过角色、MemCore、输出解析或客户端渲染的特殊分支；
- 文档和 Skill 中把主动推理端口描述成插件角色回复主链的说法。

插件需要角色分析或回复时统一提交 Agent event；纯插件内部计算由插件自身完成，不再由宿主
公开第二个模型入口。

## 7. 全局不变量

1. 安装插件不会创建第二个 Akane。
2. 插件工具和内置工具使用同一个工具执行与结果反馈链。
3. 插件事件和用户消息使用同一个上下文构建与模型回合链。
4. 需要角色回应的结果永远经过同一个结构化输出和表现层。
5. 插件可声明事件是否进入时间线，宿主是唯一实际写入者。
6. 缺少目标上下文时显式失败，不回退到默认角色继续发送。
7. 固定通知不伪装成角色回复。
8. worker 隔离只改变调用方式，不改变用户可见语义。

## 8. 实施顺序

1. 为后台插件补充宿主拥有的会话引用和事件提交入口。（已完成 QQ/桌宠签发与验证、能力与命令上下文、隔离 RPC）
2. 将需要角色回应的定时器、订阅和外部事件迁移到普通 Agent 主入口。（QQ、桌宠、`akane.timer` 与 `gentle-checkin` 样例已接通；事件使用 `turn_kind=plugin_event`）
3. 保留固定通知端口，删除“推理结果转纯文本再通知”的用户回复用法。（公开样例与私有金融插件均已迁移到 Agent-event）
4. 统一结构化结果、MemCore 记录和客户端渲染验收。（QQ 与桌宠 Agent-event 已复用普通表现层；单消息公告使用同一投递边缘的展示策略）
5. 删除不再有调用者的旧插件推理适配代码及其测试。（已完成）

本轮不新增第二套事件总线、第二套记忆系统或新的提示词目录。目标是减少分支和权威实现，
而不是增加一个更复杂的插件框架。

`akane.timer` 的参考实现以真实 wheel 在隔离 generation 内运行后台服务，并通过反向 RPC
提交 Agent 事件。宿主覆盖插件自报的事件来源、限制事件尺寸，并按插件域与幂等键合并并发
重试。插件只保存宿主签发的会话引用，不再保存或猜测 QQ 投递地址与角色。

## 9. 必须通过的验收

- 定时器从 QQ 群聊创建后，到期仍使用创建时的角色、会话和 MemCore 域；
- 同一事件可选择只进当前回合、进入时间线或仅内部处理；
- 插件事件触发的模型回复仍能生成正常 JSON，并由 QQ/桌宠表现层处理 emotion、speech、
  TTS 和贴纸；
- 固定通知不启动模型，模型也不把它当成历史助手回复；
- 上下文解析失败时明确返回错误，不出现默认人设发送；
- 插件停用后，工具、事件、后台任务和提示贡献全部消失；
- 连续普通工具轮的 system/tool 前缀和 MemCore 性能不回归。
