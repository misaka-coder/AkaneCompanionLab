# 对话回合主流程拆分 v1

## 目标与边界

`companion_v01/engine.py` 的 `_run_turn_core()` 原有 1116 行，将输入准备、模型和工具循环、记忆收尾放在一个生成器内。拆分按阶段进行，保留同步和流式共享的唯一主流程。

不改变公开入口、生成器的延迟执行、工具批次预算、协议重试计数、请求内固定的用户刺激、原生协议续接、语音预提交归属和流关闭时的 MemCore 回收。

## 切片 1：结果收尾

- `engine_services/turn_completion.py` 负责回复整理、记忆元数据、助手消息持久化、MemCore 完成或中止、压缩调度及最终事件。
- 移动原有 33 条顶层收尾语句，语法树核对一致；同步和流式入口仍调用同一收尾生成器。
- 保留 `final_ui` 在添加 `trace_id` / `_debug` 之前发送的顺序。
- `engine.py` 从 2159 行降到 1961 行。

## 验证

切片 1：264 项相关测试通过，包括回合契约、MemCore、工具批次与续接、多模态、插件、私有会话和插件代际冻结。Python 编译、新增模块 Ruff 检查及 `git diff --check` 通过。

切片 2：输入准备抽取后相同测试集扩展到 266 项并全部通过；保留的模型生成与工具循环共 21 条顶层语句，语法树与拆分前一致。

切片 3：23 个模块共 502 项测试通过。覆盖上述行为及生产语音运行时、播放上下文、桌宠当前附件、QQ 身份与群关注、响应上下文、原生工具协议、工具暴露、关怀归属、记忆交付和当前工作区的操作投影策略。Python 编译、本次拆分模块和回合测试的 Ruff 检查、`git diff --check` 通过。

测试期间并行新增的操作投影配置测试已补跑，当前该模块 17 项全部通过。

真实桌宠、QQ、语音设备与外部模型服务未在本轮启动验收。

## 切片 2：输入准备

- `turn_contracts.py` 明确划分身份、请求、持久化策略、可更新的提示状态、记忆状态和兼容诊断字段。
- `turn_preparation.py` 校验输入、确认服务域和私有会话、调用媒体和用户记录准备、打开正确的 MemCore 回合并冻结当前刺激的来源。
- `turn_media.py` 准备附件、原生图片和桌面画面，选择对应模型目标。
- `turn_input_memory.py` 准备普通、临时、插件或语音预提交记录及兼容诊断字段。
- 收尾从 40 个上下文参数收敛为阶段对象与实际工具证据；合并重复的参与者身份规范化，移除无用局部别名。
- `engine.py` 降到 1655 行。
- 新增两项真实主流程边界测试：未启动的流没有输入或模型副作用；模型生成中关闭流会关闭底层生成器并中止已打开的记忆回合。

- 执行完成后需要继续处理的停止或追加输入仍回到同一决策边界；协议重试不消耗实际工具批次预算。
- 结果收尾进一步分为回复整理、记忆提交、调试信息及最终事件，`final_ui` 仍先于调试计算和 `final`。
- 各个回合使用独立的可变证据列表、字典和预算；没有共享的默认容器、动态方法注入或局部变量字典传递。
- 新增同步/流式参数一致性、交错会话证据隔离、无效决策不消耗工具预算三项行为测试。
- `_run_turn_core()` 与 `_generate_round()` 签名保持原样；其余 18 个引擎方法的语法树保持一致。
- 最终 `engine.py` 为 **981 行**；`_run_turn_core()` 从 **1116 行降到 28 行**，只串联准备、轮次和收尾。

### 保持的执行边界

创建未启动的流不会做输入准备或写入记忆。关闭嵌套生成器会关闭底层提供方流，外层原有 MemCore 守卫负责回收未结束的回合。语音预提交继续由语音外层拥有；普通、临时、插件和 QQ 关注输入保留各自的持久化规则。

本轮并行出现的 MemCore 配置、投影和依赖版本改动保留在工作区，相关联动测试已覆盖；拆分提交只包含本轮的回合阶段文件、引擎、回合契约测试和本记录。

## 桌宠消息等待与超时修正（2026-10-07）

主线桌宠经 `pet/chat.js`、`desktop-conversation-transport.js` 向 `/think` 发送流式请求。
聊天模型客户端的传输超时为 120 秒；前端整体请求上限为 5 分钟，二者作用不同。
此前流失败后可以继续尝试非流式请求及无缓存请求；每次都可能重新等待模型超时，期间缺少可见的恢复状态。
原生桌宠还漏传了 `AbortSignal`，前端计时器和停止操作无法中断该 HTTP 请求。

- 后端取得请求回执后先发送 `stream_start`，再等待插件发布和会话锁，表示消息已送达，不表示模型已开始生成。
- `routes/think_stream.py` 每次只推进一个引擎步骤；步骤阻塞时每 5 秒发送 `turn_progress`。断开时先撤销模型消费，等待当前步骤结束，再在同一个 Context 中关闭生成器。
- 模型达到传输超时后返回 `provider_timeout`，停止非流式及无缓存恢复；明确提示消息已收到、模型响应超时。快速连接错误等仍保留原有有界恢复，并在恢复调用前发送重试状态。
- 原生与浏览器请求均使用取消信号；等待授权、显式歌词准备或画面打包时也可取消。停止消费时释放 NDJSON reader，取消后的旧输入不会迟到补发。
- 桌宠气泡区分正在发送、后端已收到、等待模型和正在重试；这些是本地工作状态，不进入模型台词或 TTS。

验证：185 项后端相关检查、6 项前端取消/等待检查、真实入口浏览器 smoke、发送延迟 smoke、前端构建、语法与 lint 检查通过。
后端全套相关检查另有 1 项既存 QQ 戳一戳断言失败，修改前已复现；该项与本次消息传输修改无关。
浏览器使用隔离 HTTP 流验证接收、等待、重试气泡及切换会话，不向真实 QQ 会话或模型提供方发送测试消息。
本次没有拿到用户发生卡顿时的请求日志，因此上述修正针对已确认的链路缺陷，不将它们断言为每次偶发卡顿的唯一原因。
当前桌宠使用内嵌前端资源的发布程序；生效需要重新构建并重启桌宠，以及重启后端。本次验证没有替换正在运行的发布程序。
