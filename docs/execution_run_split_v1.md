## 状态与调用链

本地提供方、执行工具、资源交接和宿主作业继续通过原入口使用相同类型。提供方负责真实进程生命周期；内核负责运行状态及结果边界，没有新增第二份进程或作业状态。

`ExecutionRunStore` 在 `store.py` 初始化唯一的 `_runs` 和 `RLock`。`output.py` 的三个存储方法通过静态 `RunOutputMixin` 组合，继续在原调用方持有的锁内处理同一份运行记录。`get` 仍返回既有记录对象，分页与本地执行器读到的状态一致。没有运行时方法注入、实现模块反向导入入口或新增状态副本。

终态先在锁内提交，再在锁外通知观察者。一个运行只产生一次提供方确认的终态事件；观察者失败保留已提交的状态。取消意图与确认终止仍分开，宿主作业的持久化记录继续承担重启后的恢复职责。

## 保留的行为约定

- 所有运行的读写和取消继续检查用户、会话、提供方三个归属字段。
- 输出仍按 stdout/stderr 捕获顺序累计绝对字节偏移，分页遵守现有字节和行数预算，不切断 UTF-8 字符。输出裁剪后游标仍单调推进。
- 初段和续页都使用同一记录，`runlog:` 引用和游标必须绑定当前运行。现有日志恢复和资源交接调用链保留。
- `exec_status` 的有界等待继续查询同一游标，直到终态或等待截止；进度输出不会提前结束等待。等待逻辑与结果校验现在各有一个明确位置。
- 退出码为零、无输出、仍在运行、超时和取消等反馈保留原有标记。脱敏继续保留可复用的命令、路径和输出证据。
- 只有提供方确认终止后才报告取消或超时；不能确认终止时继续返回 `execution_unknown`。

## 同轮修复

1. 首段和状态查询会在提供方调用结束后直接转换时间戳。无法转换的值会抛出 `ValueError`、`TypeError` 或 `OverflowError`；非有限值可能进入不能严格 JSON 序列化的回执。现在两处共用时间戳校验，返回 `invalid_execution_timestamps` 或 `invalid_status_timestamps` 的结构化未知结果。有限数值、数值字符串、负值归零和零值转空的现有行为保留。
2. `exec_run` 原先只校验结果 ID 格式，即使宿主指定了一个 ID，也可能接纳提供方返回的另一个运行的输出。现在检查返回 ID 与宿主指定 ID，一旦不一致就返回 `execution_run_id_mismatch`，只保留请求的 ID，不暴露另一运行的输出、退出码、游标或日志引用。提供方自主分配 ID，以及未启动命令而返回无 ID 的不可用状态，仍正常工作。
3. 统一 schema 已允许首段返回 `execution_unknown`，原映射却将它改写成 `invalid_execution_status`，丢掉“终止未确认”等真实原因。现在复用 schema 的状态集合，校验运行 ID 和分页证据后保留脱敏原因及已知输出，仍返回错误而不宣称成功终止。无原因时明确使用 `termination_unconfirmed`。查询和取消的状态集合也复用既有定义，消除重复维护。

新增 `tests/test_execution_run_boundaries.py` 的 13 项用例覆盖上述错误、两个时间字段、非有限值、归属不匹配、匹配 ID、自主分配 ID、不可用状态，以及未知状态仍须校验分页证据。修复前 8 个用例复现失败或异常，修复后 13 项全部通过。

## 包装命令与子进程退出码

`exec_run` 的退出码描述启动的外层命令。Python 的 `subprocess.run()` 默认不因
子进程非零退出而抛异常，外层仍可返回 0；工具保留子进程输出，外层成功不等于测试通过。
包装测试或构建时，用 `check=True` 或 `sys.exit(result.returncode)` 传递失败，
并核对输出中的验收结果。允许失败的探测或重试仍由包装程序处理。

真实本地执行回归覆盖：忽略子进程退出码时外层为 0；传递退出码时为 7；
`check=True` 抛出异常时外层失败。状态映射保留相应退出码和子进程输出。
