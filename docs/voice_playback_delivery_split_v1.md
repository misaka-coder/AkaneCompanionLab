## 回执与关闭

音频发送确认仍只推进通道发送状态，播放入队、开始和终态由客户端回执确认。重复的已确认回执返回重复，内容变化返回冲突；不凭发送成功制造“已播放”。停止控制与自然播放终态沿用原 VoiceCore 观察语义。

同一音频的回执在进入 Host 前先在原状态锁内占位。控制回执同时占据控制 ID 和目标音频 ID，避免停止控制与自然完成回执并发改写同一记录。正在处理的请求返回 `voice_playback_ack_in_progress`，标记可重试；已有回执尚未成功时不会返回重复确认。Host 调用在状态锁外执行，结束后释放占位，避免把通道状态锁带进 Host 的串行锁。受控跨线程测试验证这一点。

关闭先停止新交付、出队和发送确认，再逐项提交剩余控制与音频的失败/中断观察。提交失败保留原因和可重试性，已完成的记录不重复提交；再次关闭只补做未完成项，并保留首次关闭原因。Host 异常转为稳定的提交失败，真实 `journal_result.retryable` 也传递到返回结果。只有所有记录都完成收尾，后续关闭才返回重复。

关闭与回执处理重叠时，正在处理的目标暂不被关闭流程改写；关闭返回可重试状态。回执完成并释放占位后再补做关闭收尾，防止旧入队或开始结果把终态重新变成活动状态。关闭后的新活动等待立即结束。事件循环恰好在检查之后关闭时，活动通知正常结束，不向调用链抛出循环关闭异常。

## 请求身份与恢复兼容

交付登记同时核对命令、交付 ID 和语音单元，控制登记也核对控制 ID，碰撞不覆盖旧记录。活跃通道要求快照的会话和代次与拥有者一致；语音单元所属响应、代次、顺序及音频引用必须匹配命令。控制目标也核对已登记音频的响应与代次。执行器核对登记通道的归属，防止将别的会话或旧代次接到当前请求。

无客户端的旧命令恢复保留原失败收尾机制，不自动重播音频。此路径继续兼容不含会话身份字段的历史局部快照，仅用于产生原 `voice_playback_runtime_restarted` 失败观察；活跃播放仍要求完整身份。如果快照显式提供了不匹配的身份，则返回失败。无通道时也验证必要的响应上下文，损坏数据不会在构造失败观察时抛出裸类型异常。

非对象回执、非法 UTF-8 幂等键、非法控制音量返回结构化失败。超大整数音量先比较有效范围，再转换为浮点值，避免溢出。现有 TTS 的确定性音频引用、来源、Host receipt 与未知结果恢复策略保持不变，符合 `plugin_tts_service_execution_plan_20260911.md` 的交付和重启约束。
