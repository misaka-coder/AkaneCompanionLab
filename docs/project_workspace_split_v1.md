## 所有权与调用链

引擎服务工厂继续建立一个 `ProjectWorkspaceService`。桌宠路由、项目管理工具、文件读写工具和执行目录解析都通过原入口调用该服务。模块采用静态 mixin 组合，共享同一实例、同一个 `MemoryStore` 和同一把 `RLock`，没有为不同模块创建独立的权限状态或锁。

项目归属继续由现有 `scope_for` 和主人私聊归一化决定；QQ 用户目录、群会话选择和桌宠选择沿用现有规则。已注册项目先校验归属和项目状态；直接执行目录复用执行提供方已经授权的目录。界面仍通过既有后端路由访问。

读取、写入和补丁共同使用 `paths.py` 的目录边界。分页游标和工具参数投影仍由既有处理器负责，底层读取预算、结果指纹和文件变化检查保留。

## 保留的行为约定

- 项目关闭只解除当前选择；归档只改变登记状态，保留实际文件。
- 外部目录绑定沿用保护目录校验，公开项目记录继续隐藏真实宿主路径。
- 单文件写入保留写入模式和预期 SHA-256 校验，使用临时文件、flush、fsync 和替换完成更新。
- 多文件补丁在同一把锁内先验证全部变更，验证完成后才提交。提交失败仍恢复已修改文件；回滚失败同时保留原失败原因和无法恢复的路径。
- 补丁保留新增、更新、删除、移动、UTF-8 校验、原有换行方式、唯一上下文与锚点规则。传统带行号 unified diff 仍返回原格式反馈。
- 原入口的 `regex_engine` 引用仍指向实际搜索使用的模块，既有正则超时测试能够拦截真实调用。

## 同轮修复

1. `.`、`./`、`.\` 作为文件写入路径或补丁目标时，原实现会因空路径分段抛出 `IndexError`；现在返回 `invalid_relative_path`。目录列表使用 `.` 的正常行为保留。
2. 同一份补丁使用 `a.txt`、`./a.txt`、反斜杠写法或 Windows 大小写别名重复操作同一个文件时，原来的原始字符串检查会漏过。准备阶段现在比较安全解析后的路径，覆盖移动操作的来源和目标，在写入前返回 `duplicate_patch_target`。不同文件的正常混合操作保留。

新增 `tests/test_project_workspace_boundaries.py` 的 11 项用例先复现失败，再验证明确拒绝、未写入、原内容保留和正常路径仍成功。注册项目与直接执行根目录共用这些检查。
