## 并行调用与中途反馈的判断口径

模型协议支持多调用、宿主能够并发执行、模型本轮实际选用并行，是三个不同的问题。本次实际轨迹全部单调用；普通调用转后台也不等同于模型显式选择异步。

中途反馈还需要逐层区分：供应商返回了哪些文字、解析器保留了哪些文字、当前客户端路径是否即时投递。不能仅凭最终界面或最终记忆投影断言是模型能力问题。

### 本轮追加核对：当前输出格式的非流式解析缺口

修复前，`model_runtime/provider_execution.py::_native_preface_text_from_content` 对有效 JSON 只读取 `speech`。当前桌宠回复采用 `utterances[].text`，原生工具调用分支未在此提取这个结构。

修复前直接调用生产解析函数复现：

| 输入中的进度文字 | 非流式提取 | 流式提取 |
| --- | --- | --- |
| 普通文本，含句末标点 | 保留 | 流结束后由普通文本回退提取 |
| 当前 `utterances[].text` | 空 | 保留 |
| 旧 `speech` | 保留 | 保留 |

流式对比使用 `_TopLevelJSONStreamTap`；普通文本的结果来自工具轮结束后的 `_native_preface_text_from_content` 回退，不是 JSON 流解析器即时识别。上述复现不访问供应商、不修改生产数据。

该问题与后台队列只投递最终 frame 是两个独立缺口。即使供应商输出了合法的当前格式进度文字，非流式解析也可能丢弃；即使解析保留了文字，后台路径仍缺少即时展示通路。当前审计任务的 166 条冻结助手工具消息均无 content，不能据此倒推供应商原响应完全没有文字。

此处现已复用 `project_speech_units` 提取当前格式的显示文字，普通文字和旧 `speech` 路径保持支持。小样本结果见文末；没有新增模型字段。

### 与主流实现对照

- 当前请求在非 Anthropic 原生工具模式下发送 `parallel_tool_calls: true`，没有把聊天工具轮强制设为 JSON response format。
- `tool_batch.py` 并发执行相邻的可并发调用，按模型调用顺序收集结果；有序工具构成边界。读取类与明确声明可并发的工具可加入批次，不能把“一个工具消息里有多个调用”直接等同于所有操作都会同时执行。
- 本地 dsh 的 `packages/core/agent-loop/src/tool-calls.ts` 同样采用可并发组、有序工具边界与按调用顺序提交结果；实现细节有差异，基本调度方式一致。其助手输出流在执行工具前持续发布，未依赖一份包含完整最终回复字段的 JSON 才能展示文字。
- 官方 Gemini 文档说明支持同一轮调用多个独立函数：[Function calling](https://ai.google.dev/gemini-api/docs/function-calling)。Claude 文档也使用一轮多个工具调用与对应的成组结果：[Parallel tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/parallel-tool-use)，助手正文和工具块可共存：[Handle tool calls](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)。

协议支持不保证每个模型、反代与长会话都会主动选用中途反馈及多调用。此项初次审计时未做反代隔离请求；随后完成的对照见文末，仍不足以断言所有转换无损或所有长会话都会主动汇报。
