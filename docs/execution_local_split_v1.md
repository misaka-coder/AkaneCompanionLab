## 所有权与调用链

引擎服务工厂继续建立一个 `TrustedLocalExecutor`。执行工具、宿主作业、子任务和项目文件工具通过原入口调用。模块采用静态 mixin 组合，共享同一实例、同一个 `ExecutionRunStore`、同一把 `RLock` 和同一份进程、输入通道、日志及失败状态。

所有状态在 `executor.py` 初始化。`output.py` 的内存记录和日志写入继续在同一把锁内完成，字节游标保持同一顺序。进程监视线程继续通过实例方法调用读取和终止操作，原有子类覆写仍有效，没有运行时方法注入或实现模块反向导入入口。

## 保留的行为约定

- Windows 默认使用已经向模型披露的 PowerShell，优先 PowerShell 7、兼容 Windows PowerShell；显式 `cmd.exe` 调用仍可用。POSIX 继续使用 `/bin/sh`。
- 执行以宿主用户权限运行。相对目录保持在执行根或授权挂载内，绝对目录沿用宿主权限和目录存在检查。
- 默认继承经过凭据/内部变量过滤的宿主环境，显式允许列表和宿主配置的凭据引用保留。稳定提示不触发工具版本探测，也不暴露实际目录或凭据值。
- 普通命令使用空 stdin，交互命令使用既有 `InputChannel`，输入失败和顺序冲突仍返回可观察状态。
- 初段等待到期可返回 `running`，后续查询继续读取同一运行记录。取消和超时只有确认终止后才报告相应终态，重试耗尽返回 `execution_unknown`。
- 增量 UTF-8 解码、跨块凭据脱敏、输出分页、日志重载和原有读取预算保留。输出捕获或日志持久化失败继续保留原因。
- 运行日志仅在真正打开并写入时暴露 `runlog:` 引用；保留清理继续避开活动日志。

## 同轮修复

1. 编码项目的两项既有 Shell 冒烟失败来自旧测试命令：`cmd` 风格分隔符和参数引号与当前 PowerShell 默认值不一致。真实执行对照验证了旧命令失败、正确命令返回预期退出码并创建文件。测试现在复用既有 `_python_command`，复合命令使用 PowerShell 分隔符和显式失败传播，13 项编码项目检查全部通过；生产 Shell 行为保留。
2. 运行 ID 重复或容量不足时，原登记失败分支会无条件关闭并删除同名日志，即使本次没有成功创建它，可能破坏原任务的记录。现在只有本次创建的日志才会被失败清理；日志创建和运行登记在同一把锁内完成，避免两个请求对同一个 ID 的登记与日志归属交错。

新增 `tests/test_execution_local_boundaries.py` 的 5 项用例：活动任务继续输出、已完成任务日志保留、未由本次创建的日志保留、本次新建日志正常清理，以及并发登记只接纳一个请求。修复前其中 4 项复现失败，修复后 5 项全部通过。测试使用真实临时日志和运行记录；活动任务用真实进程及交互 stdin，竞争登记用受控线程顺序验证。
