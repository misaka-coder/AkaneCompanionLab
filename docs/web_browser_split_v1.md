# 浏览器与网页搜索处理器拆分

稳定入口是 `companion_v01/tool_handlers/web_browser.py`，工具目录和运行时继续从这里导入四个处理器。构造参数、方法签名、工具类型及类常量保持兼容；实现模块放在 `web_browser_runtime/`，不反向导入入口。

入口由 3078 行缩到 180 行，只保留构造器、类常量和工具规格。`web_browser_runtime/__init__.py` 组合职责；25 个实现模块最大 274 行。修改时先按下面的责任表找到实现，再从原工具入口回看调用链。

## 第一片：输入、授权与工具边界

| 模块 | 职责 |
|---|---|
| `common.py` | 共用 URL 校验、私网识别、整数范围和文字裁剪 |
| `public_pages.py` | 公开网页打开请求，仍通过执行器代理授权与执行 |
| `music_search.py` | 音乐搜索页面请求，不能把请求打开说成已播放 |
| `browser_inputs.py` | 托管/个人浏览器参数、批次、原文输入与错误说明 |
| `browser_authorization.py` | 控制动作和接受对话框之前的权限决策 |
| `browser_lifecycle.py` | 能力状态、会话执行器、提示与关闭 |
| `browser_feedback.py` | 失败事实、动作执行状态与恢复建议 |

修复的输入边界：畸形 IPv6、无效端口、地址中换行正常返回无效参数；超过 1600 字符的 URL 不再被截成另一个地址；网页提取拒绝 URL 中的用户名、密码和密钥查询。托管浏览器仍按原有显式开关决定是否接受私网；公开网页打开和联网提取不接受私网。

## 第二片：执行、观察与快照

| 模块 | 职责 |
|---|---|
| `browser_execution.py` | 先授权，再准备参数/上传资源，只执行一次，适配原有注入执行器 |
| `browser_artifacts.py` | 截图文件分配、登记、模型图像输入和失败清理 |
| `browser_result.py` | 页面状态、截图说明、续读提示与模型结果 |
| `browser_events.py` | 公开事件，只输出发送所需句柄与元数据 |
| `browser_snapshots.py` | 用户/会话绑定的不可变快照续读，不重放动作 |

原来的 377 行 `execute` 拆成 38 行的流程入口与具体步骤。字典形式的执行结果现在保留 `step_results`；异常计数/尺寸返回真实失败，控制动作状态记为未知并要求先观察，不能自动重放。截图执行失败或登记失败都会删除本轮临时输出，不发文件就绪事件。

## 第三片：搜索提供者、状态与分页

| 模块 | 职责 |
|---|---|
| `search_inputs.py` | 搜索/批次/提取/域名参数与提供者参数映射 |
| `search_execution.py` | 续页还原、启用检查、提供者调用与结果分派 |
| `search_transport.py` | MCP/REST 执行、回退、同步与异步调用适配 |
| `search_readiness.py` | 后台探测、真实健康状态、缓存 TTL 与上限 |
| `search_identity.py` | 当前用户或既有 QQ 搜索配置的身份选择 |
| `search_payloads.py` | JSON、结构化结果和 Markdown 解析 |
| `search_evidence.py` | 来源、日期字段、条目文本与覆盖提醒 |
| `search_results.py` | 完整条目分页及超长条目分派 |
| `search_document_paging.py` | 原始搜索文档和超长条目的无损分页 |
| `search_documents.py` | 网页正文与域名结果分页 |
| `search_cursors.py` | 用户/会话游标绑定、格式校验、游标签发及结果信封 |
| `search_redaction.py` | 环境和 HTTP 头中的服务密钥脱敏 |
| `search_feedback.py` | 可恢复失败、真实原因与后续行动说明 |

### 保留的执行与分页约定

- 普通搜索结果仍尽量按完整条目分页；超长单条改为 `structured_text` 文档分页，完整保留脱敏后的证据，不把超大摘要一次塞进上下文。
- `p1.we` 游标仍包含原调用参数、条目/文字位置及内容指纹，绑定原来的用户/会话。续页仍重新检索或提取，并在内容变化时终止旧游标；这和托管浏览器的不可变快照续读不同。
- MCP 搜索失败仍在同一次执行中尝试 REST；MCP 的提取/域名失败保留原因，不制造成功结果。
- 能力“已配置/允许提供”和真实健康状态仍分开返回；后台检查有 `checking` 状态。

### 修复的搜索边界

- 畸形来源 URL 不再丢掉整页证据；无效域名 URL 正常忽略。
- 游标的参数、指纹和偏移经过验证，负数、布尔值、嵌套游标及无效提取地址在调用提供者之前拒绝。
- 搜索内容变化先报告 `content_changed`，不会因为条目变少先误报偏移无效；变化到空结果也会终止旧游标。
- MCP 探测返回工具错误时同样验证真实 REST 回退，不误报已经可用的回退路径。
- 慢探测不能覆盖开始后已写入的新执行结果；就绪缓存即使都未过期也最多 32 项。
- HTTP 头中的密钥及单独回显的 Bearer/Basic 值进入脱敏范围；无法解码的环境文件不会使搜索崩溃。
